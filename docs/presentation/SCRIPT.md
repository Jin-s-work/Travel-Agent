## 1. 고잉 · 약 30초

[표지에서 잠깐 멈춘 뒤 시작합니다.]

안녕하세요. 이번에 만든 여행 준비 서비스, 고잉을 소개하겠습니다. 여행을 준비하다 보면 항공권이나 숙소는 이미 예약했는데, 막상 필요한 정보를 찾으려고 하면 메일함과 지도, 메모를 다시 오가게 됩니다. 고잉은 이렇게 흩어진 정보를 한 여행 안에 모으고, 가고 싶은 장소를 실제 일정으로 연결해 보자는 생각에서 시작했습니다. 오늘은 어떤 문제를 해결하려고 했는지, 실제 화면은 어떻게 동작하는지, 그리고 만들면서 어떤 부분을 고쳤는지 순서대로 말씀드리겠습니다.


## 2. 여행 준비에서 반복되는 일 · 약 45초

[메일함·지도·메모를 차례로 가리킵니다.]

예를 들어 체크아웃 시간이 궁금하면 숙소 확인 메일을 다시 찾아야 합니다. 식당을 고를 때는 지도에서 위치를 보고, 예약이 필요한지 다른 사이트를 확인하고, 정해 둔 일정과 겹치지는 않는지 또 비교해야 합니다. 하나씩 보면 어려운 일은 아닌데, 여행을 준비하는 동안 계속 반복됩니다. 그래서 처음에는 예약 메일을 읽고 질문에 답해 주는 기능부터 만들었습니다. 이후에 실제로 써 보면서, 예약을 정리하는 것만으로는 여행 준비가 끝나지 않는다는 생각이 들었습니다. 그래서 장소 탐색과 일정 편집까지 같은 여행 안에서 이어지도록 기능을 확장했습니다.


## 3. 여행 하나를 중심으로 · 약 45초

[상단 여행과 세 가지 시작 행동을 가리킵니다.]

이 화면이 지금의 홈입니다. 여행을 만들 때는 우선 도시와 날짜를 입력합니다. 그다음에는 예약 메일을 올리거나, 가고 싶은 곳을 찾거나, 하루 일정을 만들 수 있습니다. 상단에는 선택한 여행과 기간을 계속 보여 줍니다. 기능이 늘면서 입력해야 할 항목도 많아졌는데, 같은 도시와 날짜를 화면마다 반복해서 입력하는 게 가장 번거로웠습니다. 그래서 여행에 이미 있는 정보는 다음 화면에서 그대로 이어받게 바꿨습니다. 숙소가 아직 정해지지 않았어도 여행과 장소 탐색을 시작할 수 있고, 필요한 조건만 나중에 추가할 수 있습니다.


## 4. 메일을 예약으로 정리하기 · 약 60초

[가상 호텔의 날짜·시각을 가리킵니다. 이 화면은 기본 분석 결과입니다.]

메일은 텍스트나 eml 파일로 올릴 수 있습니다. 운영에서는 OpenAI의 gpt-5-mini로 예약 정보를 구조화하고, text-embedding-3-small로 검색에 필요한 벡터를 만듭니다. 중요한 건 AI가 뽑은 값을 바로 정답으로 취급하지 않는다는 점입니다. 한 메일에 예약이 여러 개 있으면 각각 저장하고, 왕복 항공편은 출발과 귀국 구간을 나눕니다. 사용자가 시간을 고치면 원문에서 추출한 값과 교정한 값을 따로 보관합니다. 그래서 나중에 다시 분석하더라도 사용자가 수정한 내용이 조용히 사라지지 않습니다. 화면의 메일과 예약은 발표를 위해 만든 예시 데이터입니다. 이 촬영에서는 비용 없는 기본 분석을 사용했고, 운영 AI 분석의 실행 여부는 별도 검증 기록으로 구분했습니다.


## 5. 답변에 출처를 붙이기 · 약 60초

[왼쪽의 총 5개와 오른쪽 원문 보기를 가리킵니다.]

예약을 모았으면 자연어로 질문할 수 있습니다. 예를 들어 둘째 날에 어떤 예약이 있는지 물으면, 해당 날짜를 계산하고 저장된 예약을 조회해서 답합니다. 여기서 실제로 문제가 한 번 있었습니다. 처음에는 날짜 질문도 의미가 비슷한 문서를 몇 개 찾는 방식으로 처리했는데, 그러면 하루 예약이 여덟 개 있어도 일부가 검색 결과 밖으로 빠질 수 있습니다. 그래서 하루 전체를 묻는 질문은 SQL 날짜 범위 조회로 바꿨습니다. 사용자가 직접 넣은 예약도 같이 포함합니다. 환불 규정처럼 원문의 설명이 필요한 질문은 검색한 근거를 사용하고, 답변 아래에서 어느 메일을 참고했는지 확인할 수 있게 했습니다. 근거가 없는 내용은 추측해서 채우지 않는 것이 기본 원칙입니다.


## 6. 장소를 찾고 비교하기 · 약 55초

[실내·음식 사진과 방문 전 확인 필요를 가리킵니다.]

장소 탐색은 현지 분위기의 식당을 찾는 경우와, 그 도시의 대표 명소를 가고 싶은 경우를 나눴습니다. 음식점이나 카페 같은 장소 종류는 별도로 고를 수 있습니다. 카드에서는 사진과 추천 이유, 확인해야 할 정보를 보고, 상세 화면에서 주소와 출처를 확인합니다. 사진은 권한과 지점을 확인한 자료가 있는 곳에만 표시합니다. 숙소가 등록되고 위치까지 확인되면 숙소를 기준으로 거리 조건을 적용할 수 있습니다. 다만 직선거리와 실제 도보시간은 다른 값으로 다룹니다. 현재 운영에서는 무료 공개지도 검색과 저장된 자료를 함께 사용하고, 정확한 도보 경로처럼 별도 공급자가 필요한 기능은 아직 제한이 있습니다.


## 7. 모르는 정보는 남겨 두기 · 약 50초

[OFF 상태를 설명합니다. 아직 실제 리뷰 품질을 통과했다는 뜻이 아닙니다.]

처음 구상한 차별점은 현지 언어 리뷰가 많고 한국어 리뷰는 적은 장소를 찾는 것이었습니다. 그런데 여기에는 조심해야 할 부분이 있습니다. 일본어 리뷰가 많다고 해서 작성자가 모두 일본에 사는 주민이라고 말할 수는 없습니다. 수집한 일부 리뷰를 전체 리뷰의 비율처럼 보여 줘도 안 됩니다. 그래서 원문을 확보했는지, 언어를 판별할 수 있었는지, 언제까지 몇 건을 관측했는지를 따로 관리하도록 만들었습니다. 언어를 모르겠는 리뷰도 분모에서 숨기지 않습니다. 이 분석 도구와 계산 로직은 구현했지만, 실제 수집과 이용 범위, 언어 품질 검증을 통과하기 전까지 엄격한 리뷰 기반 추천은 꺼 두었습니다. 지금 화면에 없는 근거를 만들어 보여 주지는 않습니다.


## 8. 예약을 지키면서 일정 편집하기 · 약 60초

[시간 미확인·고정 예약·충돌 표시를 가리킵니다.]

일정을 만들 때는 이미 확정한 예약부터 배치합니다. 그 사이의 빈 시간에 선택한 장소를 넣을 수 있는지 확인합니다. 머무르는 시간만 맞으면 되는 게 아니라, 이전 장소에서 오는 시간과 다음 예약으로 가는 시간까지 함께 봐야 합니다. 이동시간이나 영업 여부를 모르면 기본적으로는 배치를 보류하고, 사용자가 잠정 초안을 허용했을 때만 미확인 표시와 함께 넣습니다. 편집도 먼저 미리보기를 보여 줍니다. 뒤 일정이나 예약에 어떤 영향을 주는지 확인한 뒤 적용하고, 마음에 들지 않으면 되돌릴 수 있습니다. 되돌리기도 과거 상태를 무조건 복구하는 게 아니라 현재 조건을 다시 검사합니다. 그리고 일정에서 항목을 지워도 실제 외부 예약이 취소되는 것은 아닙니다.


## 9. 계속 쓸 수 있게 고친 부분 · 약 55초

[저장 위치와 실제 검색 장애 해결을 설명합니다.]

기능을 늘리는 것만큼, 중간에 실패해도 다시 사용할 수 있게 만드는 데 시간이 들었습니다. 오래 걸리는 분석은 작업 번호와 상태를 DB에 저장해서 새로고침해도 이어서 확인할 수 있게 했습니다. 무료 서버의 로컬 디스크에만 저장하면 재시작 때 자료가 사라질 수 있어서, 운영 데이터는 Supabase에 보관하도록 바꿨습니다. 장소 검색이 계속 실패했던 문제도 있었는데, 단순히 한도가 소진됐다는 안내를 반복하는 대신 실제 오류를 조사했습니다. 운영 서버에서 기존 지도 서버로 연결이 거절되는 것을 확인했고, 무료 Photon 검색으로 바꾼 뒤 런던 지점 50곳을 받아 음식점 12곳을 화면에 표시했습니다. 다시 찾을 때는 유효한 자료를 재사용해서 불필요한 외부 호출을 줄였습니다.


## 10. 현재 상태와 다음 과제 · 약 50초

[시험 수치는 회귀 시험의 결과임을 말하고 마무리합니다.]

현재는 초대한 소수 사용자가 접속하는 비공개 베타로 배포했습니다. 여행과 예약 관리, 장소 탐색, 일정 생성과 편집까지 한 흐름으로 연결했습니다. 최근 전체 회귀 시험은 Python 1,039개와 JavaScript 124개가 통과했고, 외부 환경이 필요한 시험 15개는 건너뛴 상태로 따로 기록했습니다. 그렇다고 추천 품질까지 검증됐다는 뜻은 아닙니다. 100개 도시를 선택할 수 있지만 도시마다 확보한 장소 자료는 다르고, 실제 사용자의 만족도는 아직 측정하지 않았습니다. 무료 환경에서는 검색과 화면을 불러오는 데 시간이 걸리는 점도 남아 있습니다. 앞으로는 기능을 더 늘리기보다 반복 입력과 대기 시간을 줄이고, 친구들이 실제로 어디서 막히는지 확인하려고 합니다. 이상으로 발표를 마치겠습니다. 감사합니다.


## 5분으로 줄여야 할 때

슬라이드는 그대로 넘기되 3·7·9번 설명을 짧게 합니다. 아래 축약 대본을 쓰면 약 5분을 목표로 연습할 수 있습니다.

1. 안녕하세요. 여행 준비 서비스 고잉을 소개하겠습니다. 항공권이나 숙소를 예약해도 필요한 정보를 찾으려면 메일함과 지도, 메모를 계속 오가게 됩니다. 고잉은 흩어진 예약을 한 여행에 모으고, 장소를 일정으로 연결하려고 만들었습니다.
2. 처음에는 체크아웃 시간이나 환불 규정을 메일에서 찾아 주는 기능부터 시작했습니다. 그런데 실제로 쓰려면 식당도 고르고, 그곳에 들렀다가 다음 예약에 갈 수 있는지도 봐야 했습니다. 그래서 예약 정리에서 장소 탐색과 일정 편집으로 범위를 넓혔습니다.
3. 여행의 도시와 날짜를 한 번 입력하면 예약·탐색·일정 화면이 같은 정보를 이어받습니다. 숙소가 없어도 시작할 수 있고 세부 조건은 필요할 때만 추가합니다.
4. 메일은 OpenAI gpt-5-mini로 구조화하고 text-embedding-3-small로 검색합니다. 추출 결과를 정답으로 확정하지 않고 사용자 교정값을 따로 둡니다. 재분석이 실패해도 기존 예약을 지우지 않습니다. 화면은 가상 메일을 무료 기본 분석한 예시입니다.
5. 하루 전체 예약을 묻는 질문에서는 검색 방식도 바꿨습니다. 비슷한 문서 몇 개만 찾으면 하루에 예약이 여덟 개 있어도 일부가 빠질 수 있기 때문입니다. 날짜 질문은 SQL로 해당 날짜의 예약을 전부 가져오고, 수동 예약도 포함합니다. 설명형 질문은 근거를 검색하고 원문을 확인할 수 있게 했습니다.
6. 장소는 현지 탐색과 대표 명소를 나눠 봅니다. 카드에서 사진과 확인할 정보를 보고, 상세와 비교로 이어집니다. 숙소 위치가 확인되면 거리 조건을 적용하지만, 직선거리만으로 도보시간을 추정해 확정하지는 않습니다. 모든 도시와 식당의 자료가 확보된 상태도 아닙니다.
7. 리뷰 언어로 장소를 찾는 기능도 설계했습니다. 다만 현지 언어가 많다는 것이 현지 주민이 많다는 뜻은 아닙니다. 원문과 미판별 수, 관측 기간을 따로 관리하며 실제 수집·이용·품질 검증 전까지 엄격 기능은 꺼 두었습니다.
8. 일정은 확정 예약부터 보존합니다. 그 사이에 장소를 넣을 때는 머무는 시간뿐 아니라 양쪽 이동과 준비 시간을 함께 검사합니다. 모르는 조건은 확인 필요로 남기고, 편집은 미리보기 후 적용합니다. 되돌릴 때도 현재 조건을 다시 검사하며 외부 예약을 자동 취소하지 않습니다.
9. 분석 작업을 DB에 저장해 새로고침 후에도 확인하게 했고, 무료 서버가 재시작해도 자료가 남도록 Supabase를 연결했습니다. 지도 연결 실패는 실제 오류를 확인한 뒤 Photon으로 바꿨습니다. 런던 후보 12곳 표시와 캐시 재사용을 운영에서 확인했습니다.
10. 최근 회귀 시험은 Python 1,039개와 JavaScript 124개가 통과했습니다. 외부 환경 시험 15개는 별도로 남겼습니다. 이 결과가 추천 품질이나 사용자 만족도를 증명하는 것은 아닙니다. 앞으로는 검색 대기와 반복 입력을 줄이고 실제 사용에서 막히는 부분을 확인하겠습니다. 감사합니다.

## 10분으로 구성할 때: 약 60–90초 시연 추가

## 예상 질문과 답변

**Q. ChatGPT에 메일을 붙여 넣는 것과 무엇이 다른가요?**

여행별로 예약을 계속 저장하고, 원문·교정값·현재 값을 분리한다는 점이 다릅니다. 날짜 전체 조회와 일정 충돌·소유권·비용 제한은 대화 프롬프트가 아니라 서버 코드로 검사합니다.

**Q. 모든 것을 AI가 결정하나요?**

아닙니다. AI는 메일 구조화와 근거 설명을 맡습니다. 추천 후보·조건·점수와 일정 제약은 서버가 계산하고 설명에 없는 장소나 예약 사실이 추가되면 검증합니다.

**Q. 왜 날짜 질문에는 벡터 검색을 쓰지 않나요?**

그날의 예약을 빠짐없이 가져오는 것이 목표이기 때문입니다. 상위 몇 건 검색과 전수 범위 조회는 목적이 다릅니다. 환불 규정처럼 원문의 의미를 찾아야 하는 질문에 검색을 사용합니다.

**Q. 일본어 리뷰가 많으면 현지인 맛집 아닌가요?**

그렇게 단정할 수 없습니다. 관측한 리뷰의 원문 언어 분포만 말할 수 있습니다. 작성자의 거주지나 전체 리뷰 비율은 별도 근거가 필요합니다.

**Q. 100개 도시에서 모두 추천이 되나요?**

100개 도시의 입력·시간대 처리를 지원합니다. 실제 장소 자료와 검수 수준은 도시마다 다릅니다. 새 도시 공개지도 검증은 런던에서 했고, 자료가 없는 곳을 합성 카드로 채우지 않습니다.

**Q. 무료인가요?**

호스팅과 DB는 현재 Free 플랜을 사용합니다. OpenAI는 사용량 비용이 있어 전역 일 0.50달러·월 3달러 한도를 설정했습니다. 모든 서비스 비용을 합한 월 요금이 3달러라는 뜻은 아닙니다. 리뷰·유료 경로 공급자는 별도 승인과 설정이 필요합니다.

**Q. 실제로 예약까지 해주나요?**

예약 링크, 준비 할 일, ICS와 문의 초안을 제공합니다. 외부 예약·메시지 발송·결제는 자동으로 실행하지 않습니다. 일정에서 빼는 것도 예약 취소와 다릅니다.

**Q. 시험이 많으면 실제 서비스도 완벽한가요?**

아닙니다. 현재 숫자는 정해진 회귀 시험의 통과 건수입니다. 다양한 실제 메일·모든 도시·실물 모바일·사용자 만족도는 별도 검증해야 합니다.

**Q. 가장 어려웠던 부분은 무엇인가요?**

기능을 추가하면서 기존 데이터를 안전하게 유지하는 부분이었습니다. 분석 실패·재시작·동시 수정·삭제와 완료의 경쟁에서도 이전 예약이 유지되고 삭제한 자료가 되살아나지 않게 만드는 데 신경을 썼습니다.

**Q. 다음에 무엇부터 개선할 계획인가요?**

검색 대기 구간을 계측해 줄이고, 친구들이 어떤 입력이나 안내에서 멈추는지 확인하려고 합니다. 그다음 자주 쓰는 도시부터 근거를 보강할 계획입니다.
