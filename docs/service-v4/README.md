# 고잉 v4 — 서비스 점검과 다음 고도화 계획

작성: 2026-10-07. 이번 문서 세트는 실제 코드 감사와 합성 재현을 바탕으로 한 **구현 전 기획**이다.

이후 1·2단계 코드와 자동 시험을 적용했다. [2단계 검증 보고서](reports/stage2-validation.md)가 최신 기록이다. 최신 코드·자동 시험·브라우저 미검증 범위는 [1단계 검증 보고서](reports/stage1-validation.md)와 [진행 기록](IMPLEMENTATION_STATUS.md)을 본다. 아래 기획과 최초 감사 결과는 구현 후 검증 결과를 대신하지 않는다.

추천 경험의 중심은 두 가지다.

- **현지어 리뷰로 찾기:** 관측한 원문 리뷰의 언어 근거로 식당을 찾는다.
- **유명한 곳:** 유명 식당·카페·대표 명소를 별도의 근거로 찾는다.

숙소 거리·방문 조건·개인 취향은 두 경험에 공통으로 연결한다. 최소한의 입력만으로 기본 추천을 받고, 필요한 경우에만 취향을 추가한다. 현지어 비중을 현지 주민 비율로 표현하지 않는다.

## 그대로 사용할 구현 프롬프트

1. [1단계 — 정확한 후보, 빠른 조회, 이어지는 여행 흐름](prompts/01-reliable-journey.md)
   - 잘못된 0건·공개 후보 일정404·반복 SQL·결과 유실을 해결한다.
   - 메일 시각 교정·짧은 조건 수정·선택 복원·복구 경로를 연결한다.
2. [2단계 — 현지어 리뷰와 유명한 곳, 두 추천 경험 완성](prompts/02-evidence-led-recommendations.md)
   - 지점 ID 연결·실제 공급자 계약·언어 품질·도시별 기능 상태를 연결한다.
   - 입력 없는 기본 추천과 명시 선호 모델, 두 구획의 독립적 추천을 구현한다.

각 파일 전체를 새 구현 요청으로 사용한다. 1단계 검증 기록을 확인한 후 2단계를 실행한다. 두 파일 모두 저장소 경로·참조 문서·작업 계약·실패 처리·시험·완료 산출물을 포함한다.

## 이번 점검에서 중요한 것

- 후보가 있어도 0건이 되는 경로와 추천 장소를 일정에 넣을 때404가 나는 경로를 재현했다.
- 공식 카탈로그 지점과 리뷰 수집 지점의 연결 부족을 재현했다. 엄격 리뷰 기능은 플래그만 켜면 완성되는 상태가 아니다.
- 선택 입력을 비우면 순위가 나오지 않는 문제를 확인해 일반 추천 모델을 별도 설계했다.
- SQL 반복과 유지보수 진행성 문제를 확인해 새로운 기능보다 먼저 고치도록 구성했다.
- 현재 디자인과 이미 구현된 많은 기능은 재사용한다. 실제 데이터가 없는 도시에 지원 완료를 표시하지 않는다.

전체 Python 실행은 1032통과·7실패·15건너뜀이다. 실패는 메일 job 대기10초 초과이며 해당 파일 단독39통과, 선행순서 재현220통과였다. 최초 timeout 원인은 미확정이다. JavaScript124개는 통과했다. 자세한 조건과 원본 로그는 감사 보고서에 있다.

브라우저는 로컬 로그인 첫 화면까지 확인했다. 합성 로그인 서버 접근이 자동 승인 검토에서 거절되어 로그인 후 흐름은 이번에 검증하지 못했다. 이 문서들은 앱 수정·배포·실제 리뷰 수집 완료를 의미하지 않는다.
