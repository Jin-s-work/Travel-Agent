# 고잉 UX·제품 감사 — 코드 기반

2026-10-07. 대상: `/Users/jinsangwoo/Desktop/ChatGPT/travel-inbox-rag`.

현재 색·Pretendard·여백·사진 카드·여행가방 브랜드를 유지한다. 이번 변화는 새 메뉴나 토글을 더 만드는 일이 아니라, **현지어 리뷰로 찾는 장소와 유명한 장소의 차이를 첫 화면에서 이해하고, 찾기→저장→일정→수정 중 작업을 다시 하지 않게 만드는 일**이다.

이 문서는 로컬 소스와 진행기록을 읽은 정적 감사다. 브라우저 조작·운영 API·외부 제공자 호출·앱 코드 변경·`.env` 열람은 하지 않았다. 보고서의 동작 근거는 함수 경로이며, 실화면 재현 결과는 메인 감사의 관측을 별도로 합쳐야 한다. 대상 및 상위 디렉터리에서 AGENTS.md를 확인했으나 발견되지 않았다. emil-design-eng의 실제 Before/After/Why 표, 좋은 기본값, 반복 동작의 즉각성, 키보드·터치 접근성 기준을 적용했다.

## 이미 해결되어 유지해야 하는 것

- 주요 메뉴는 이미 홈·탐색·일정·예약·더보기이며, 모바일은 5개 하단 메뉴다. `index.html:47–62`, `design-system.css:304–313,406–419`. 더보기나 새 하단 탭으로 문제를 해결하지 않는다.
- 도시/날짜/인원 상속, 추천 단일 요청, 현재 조건과 이전 결과의 분리, 작업 진행·새로고침 복구·취소·예산·실패별 행동은 이미 있다. `foundation.js:793–818,1092–1164`. 이를 새로운 기능으로 다시 제안하지 않는다.
- 종류(음식점/카페/볼거리)와 관점(현지 탐색/대표 명소)은 별도 선택이며 결과도 두 관점으로 렌더링한다. `foundation.js:801–809,982,1161`.
- 추천 카드의 **일정에 넣기**는 이미 있다. `foundation.js:1299,1358–1364`. 단순히 이 버튼을 추가하는 제안은 잘못이다.
- 예약 수정값 보존, 재분석, 대표/구간 시각 충돌 경고, 409 세 값 비교가 있다. `foundation.js:432–515`. 남은 문제는 수정을 두 군데 해야 하는 입력 모델이다.
- 모달 Escape·포커스 복귀, 큰 글자 설정, reduced motion, 터치 44px·모바일 하단 safe-area도 이미 구현/기존 검증되어 있다. `foundation.js:39–44`, `design-system.css:125–126,206–212,342,409–419`. 실기기 Safari/VoiceOver 결과와 동일시하지 않는다.
- 진행기록상 현재 100개 도시는 입력 지원이며, 검수된 기초 후보·공개지도 보조 탐색·현지어 리뷰 검증은 서로 다른 범위다. 현재 공개지도 결과가 나온다는 이유로 현지어 맛집 추천 완료라고 말하지 않는다.

## 실제 흐름과 남은 단절

**탐색:** 여행 선택 → 도시·방문일·종류·관점 → 조건 변경(4개 탭) → 장소 찾아보기 → 현지 탐색/대표 명소별 결과 → 상세/저장/일정에 넣기/비교. 현재 현지어 검증은 `조건 변경 → 리뷰 기준` 속 선택 항목이며 기본 체크 상태는 OFF다. 현지 탐색에 공개지도 장소와 현지어 검증 자료가 함께 들어갈 수 있지만, 카드의 후반부 설명에서야 그 차이를 명시한다.

**일정 담기:** 카드 → `addPlaceToItinerary` → 일정 조회 → 기존 일정이 있으면 편집 미리보기, 없으면 전체 생성 조건 폼. 현재 신규 후보는 먼저 메모리 Map에 추가된다. 기존 일정 삽입 기본일은 탐색 방문일보다 일정 화면에서 마지막으로 본 날짜를 우선한다.

**예약 교정:** 목록 → 상세 → 수정 → 대표 날짜/시각 및 구간 날짜/시각/시간대를 각각 입력 → 저장. 충돌을 알려 주는 기능은 있지만 같은 시각을 한 번 수정해 관련 대표값까지 안전하게 제안하는 기능은 없다.

**복구:** 홈의 ‘다음 예약’·‘예약 확인하기’, 일정의 ‘예약 화면에서 확인’은 해당 항목을 여는 대신 예약 탭만 연다. 오류의 원인을 알게 되어도 긴 목록에서 다시 찾아야 한다.

## 현지어 리뷰 핵심 구획의 상태 계약

두 결과 구획을 유지하고 각 구획 안에 근거 상태를 표시한다. 공통 최상단에서 ‘일부 완료’라는 말 하나로 모든 상태를 뭉개지 않는다. 유명/인기 구획이 준비되어 있으면 현지어 구획 자료 부족과 무관하게 볼 수 있어야 한다.

| 상태 | 사용자 문구 예시 | 다음 행동 | 금지되는 의미 전환 |
|---|---|---|---|
| 아직 확보한 리뷰 없음 | 이 도시의 현지어 리뷰 자료를 아직 준비하지 못했어요. | 유명한 곳 보기 / 링크 저장 | 한국어 0%, 현지어 많음, 현지인 맛집으로 표시 |
| 저장된 검증 작업 진행 | 확보한 리뷰의 언어와 출처를 확인하고 있어요. | 실제 진행 단계 / 기존 결과 보기 | 가짜 퍼센트, 새 요청을 반복 생성 |
| 표본·판별 자료 부족 | 관측한 리뷰가 추천 기준을 판단하기에 부족해요. | 관측 범위와 부족 이유 보기 | 임의로 적합, 기준 자동 완화 |
| 현재 기준 불충족 | 이번 현지어 리뷰 기준을 통과한 곳이 없어요. | 적용 기준 보기 / 유명한 곳 보기 | 같은 카드를 순위만 바꿔 현지어 추천으로 표시 |
| 자료 만료·이용 범위 변경 | 이 장소의 리뷰 근거를 다시 확인해야 해요. | 사용 가능한 최신 근거 확인 | 과거 비율을 현재 추천 근거로 고정 |
| 연결 실패·조회 제한 | 자료 연결이 지연되고 있어요. 저장된 결과는 볼 수 있어요. | 기존 작업 재확인 / 알려진 재시도 시각 | 실패를 ‘이 도시 맛집 없음’으로 표현 |
| 기준 충족 | 관측한 리뷰에서 현지어 비중이 높은 장소예요. | 표본·기간·미판별·출처 확인 | 현지 거주자 비율, 관광객이 적다는 단정 |

한 카드의 간략 근거 예시는 **‘판별한 리뷰 120개 중 현지어 82% · 최근 관측’**처럼 분모를 숨기지 않는 방식이다. 120·82는 UI 예시 숫자이며 실제 데이터가 아니다. 한국어/미판별/기간·한계는 한 단계 상세에서 확인한다. 카테고리·도시별 실제 데이터 상태는 백엔드 응답과 일치해야 한다.

## 기존 기능을 연결하는 확장 우선순위 3개

| 순위 | 제안 | 재사용할 기능 | 새 메뉴 없이 놓을 위치 | 완료 판단·한계 |
|---|---|---|---|---|
| 1 | **이번 여행에서 먼저 확인할 것**: 출발·방문에 영향을 주는 예약 시각/자료 기한/지점 미확인을 우선순위 1~3개로 제시하고 해결 후 원 흐름으로 복귀 | booking needs_review·time_conflicts, itinerary conflicts/unresolved/unplaced, bookmark resolution, 기존 예약 준비 할 일 | 홈의 기존 ‘확인하기’ 영역과 일정 오류 영역 | 중복 항목을 합치고 실제 대상에 연결한다. 완료는 근거/상태 변화로 판단하며 버튼만 눌렀다고 확인 완료로 바꾸지 않는다. 알림 발송·새 외부 수집은 없음. |
| 2 | **비는 시간에 저장한 장소 넣기**: 이미 선택한 장소 중 고정 예약 사이에 검토할 수 있는 후보를 제안 | bookmark, 현재 추천 snapshot, itinerary preview/validator, 기존 체류시간/버퍼 | 일정의 날짜별 빈 구간에 하나의 행동 | 장소는 먼저 저장한 범위에서 시작한다. 양쪽 이동·영업이 미확인이면 ‘검증됨’ 대신 잠정/미배치 이유를 보인다. 무료 데이터만으로 실제 도보시간을 만들어 내지 않는다. |
| 3 | **관심 장소에서 예약 준비 이어가기**: 날짜·인원·장소·예약 링크를 기존 예약 준비 항목에 미리 채우고 사용자가 확인해 저장 | saved place, 검증된 reservation_url/open_rule facts, TravelTools 예약 준비 폼 | 장소 상세의 예약 관련 근거 옆 | 장소 저장→예약 준비가 연결되고 값 재입력이 줄어든다. 예약 준비와 실제 예약 확정은 계속 별도다. 링크/오픈 시각이 미확인이면 비워 두고 외부 예약·전송을 자동 수행하지 않는다. |

세 기능 모두 핵심 현지어 자료 파이프라인과 UI 의미 정합성을 먼저 완성한 뒤 확장한다. 사진 확대·새 테마·추가 여행 도구 메뉴·새 토글 묶음은 이번 우선순위가 아니다.

## 두 단계 구현으로 나눌 때의 UX 경계

**1단계: 핵심 탐색을 명확히 하고 당장 반복하는 일을 줄인다.** UX-01의 두 구획/독립 종류 필터/정직한 상태 표시, UX-05의 대상 직접 연결, UX-06의 문구·필드·포커스·목록 복귀를 적용한다. 기존 작업 복구·단일 요청·비교·사진·디자인 토큰은 유지한다. 현지어 파이프라인이 아직 검증되지 않았으면 핵심 구획은 명확한 준비/부족 상태로 배포할 수 있으나 ‘완성된 추천’이라고 표시하지 않는다.

**2단계: 교정과 일정 담기를 끝까지 연결한다.** UX-02의 중복 시간 교정, UX-03의 여행별 미완성 작업 보존, UX-04의 공통 장소 삽입 흐름을 완성한다. server draft가 필요하면 최소 스키마/소유권/삭제/만료 규칙을 별도 결정한다. 예약 보존·preview/apply/undo·409·epoch·세션 정리는 회귀 기준이다. 확장 1은 기존 경고를 연결하는 수준에서 함께 적용하고, 확장 2~3은 핵심 흐름의 완료 후 선택한다.

성과 수치는 아직 없다. 첫 검증은 신규 사용자 3~5명에게 (1) 현지어 리뷰와 유명한 곳 구분, (2) 한 장소 일정에 넣기, (3) 예약 시각 교정, (4) 오류 대상 복구를 수행하게 하고 완료율·도움 요청·중복 입력 횟수·잘못 이해한 상태를 관찰한다. 기존 Python/JS 통과 수는 사용자 이해도 성과가 아니다.
