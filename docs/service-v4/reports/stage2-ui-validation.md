# 2단계 소비자·관리자 경험 검증

2026-10-07 · 현재 체크아웃의 구현 결과. 실제 브라우저 시험과 공급자 출시 검증을 대체하지 않는다.

## 적용한 경험

- `현지어 리뷰로 찾기` / `유명한 곳`을 두 탭으로 제공하고 음식점·카페·볼거리는 독립된 칩으로 선택한다. `주변 장소 참고하기`는 별도 보조 진입점이다. 주변 참고 수가 두 핵심 추천의 통과 수에 합산되지 않는다.
- 도시별 언어 기능 상태를 필터 앞에 표시한다. 100개 도시 입력 지원과 도시별 실제 언어 gate를 구분한다. 유명한 곳은 언어 기능이 꺼져 있어도 사용할 수 있는 근거를 표시한다.
- 현지어 비율 하한·한국어 상한·같은 플랫폼 평점·전체 평가 수를 직접 수정할 수 있다. C 최소값, U/T 한도, 원문·지점·권한·언어 품질은 UI에서 완화하지 않는다. 기본보다 완화한 결과는 서버의 `criteria_group`을 따라 `직접 설정한 기준`에 따로 표시한다.
- 카드와 상세에 T/C/U/L/K, 판별 본문 기준 L/C·K/C, 전체 본문 기준 L/T·(K+U)/T, 관측 기간·확인일·수집 종료 이유를 표시한다. 미측정을 0%로 바꾸지 않는다. 주민 비율이나 맛의 확률로 표현하지 않는다.
- 유명함은 공식 대표성·동일 플랫폼 평가 규모·편집 선정으로 나눈다. 기존 사진 최대 3장, 상세·저장·비교·일정 preview/apply/undo를 재사용한다. canonical ID는 변경하지 않는다.
- 기능 꺼짐, 만료, 예산 소진, 공급자 실패, 품질 부족, 기준 미달을 서로 다른 설명과 다음 행동으로 제공한다. 한 구획의 근거 철회가 다른 구획의 가용 카드를 숨기지 않는다.
- 모드 선택은 서버 workspace `context.discovery_mode`에 저장한다. 모드만 바꿨다고 여행 조건을 수정 중으로 표시하지 않는다. 개인·여행·세션 격리는 기존 draft API를 재사용한다.
- 선호 반영의 범위를 이번 여행으로 설명하고 수정·철회 경로를 유지한다. 제품 분석 참여와 별개이며 향후 학습에 사용하지 않는 상태를 명시한다.

## 관리자 흐름

1. 공식 카탈로그에서 지점 선택 → 공급자 외부 ID·주소·좌표·공식 출처 입력 → 미리보기.
2. 공식/외부 지점을 나란히 표시하고 이름·주소·좌표·지점/이전/폐업을 각각 확인 → 승인 또는 거절. 불일치 사유가 남으면 UI에서 승인하지 않으며 서버도 재검증한다. 승인 연결은 철회할 수 있다.
3. provider/build/adapter별 계약 증거를 개별 필드로 기록한다. 원문·번역, originalLanguage 의미, 정렬, 원천 페이지와 공급자 내부 상한, 이용 범위, 실제 표본, 보고서 hash, 가격·최소 결제·추가 비용을 분리한다.
4. 수집 범위 제출은 `/admin/review-collection-preview`만 호출한다. 공급자 호출·비용 예약이 없는 상한 미리보기 후 별도 `이 범위로 수집 접수`를 눌러야 durable job을 접수한다. 입력 수정과 중복 클릭은 이전 미리보기를 무효화한다.
5. 기존 job 상태·실제 처리 수·비용·공급자 원문 삭제 상태를 유지한다. 독립 언어 평가 JSON은 미리보기 후 제출하고 저장된 평가와 TP/FP/FN·분모를 다시 확인한다.
6. 도시 프로필·품질 gate·유효 집계를 보고 제품을 미리보기한다. 기능 설정은 별도 동작이며 체크박스 하나로 실제 품질 검증을 대체하지 않는다.
7. 사용자 검토 요청은 canonical 지점별 공용 대기열에 접수하고 유료 실행이나 메시지 발송을 자동 시작하지 않는다.

관리자 기능에는 기존 session/CSRF/admin 서버 검증을 사용한다. 새 모듈의 요청은 계정/여행 epoch가 바뀌면 늦은 응답으로 화면을 갱신하지 않는다.

## 코드 검토

- XSS: 외부 장소명·근거·이유·보고서 텍스트는 공통 `make(..., text)`의 `textContent`로 구성한다. 새 모듈에는 `innerHTML`, `eval`, 개인 localStorage/sessionStorage가 없다. 외부 링크는 공통 URL 검사 후 `noopener noreferrer`로 열린다.
- 비동기 상태: capability/admin 읽기의 epoch와 request serial, 관리자 쓰기의 session epoch, 수집 미리보기의 입력 version과 form 연결 상태를 확인한다. 이전 응답이 새 계정·여행 화면을 채우지 않는다.
- 성공 오표시: 계약 승인·언어 평가 통과·기능 ON·관측 집계 수를 분리한다. endpoint 오류를 “0개 도시 지원”으로 표시하지 않으며, 평가/대기열 조회 실패를 드러낸다. JSON 제출 성공만으로 제품 gate 통과를 주장하지 않는다.
- 접근성: 실제 button/tab/fieldset/label, 키보드 좌우/Home/End, selected/pressed 상태, 새로고침 중 탭 포커스 유지, 기존 공통 모달 포커스/취소, 44px 행동 영역, 320px·200%용 CSS, reduced-motion을 적용했다.

## 미검증 범위

저장된 브라우저 접근 차단 때문에 합성 OIDC `127.0.0.1:8767`을 통과하는 실제 브라우저 흐름은 실행하지 않았다. 우회하지 않았고 새 화면 스크린샷도 시험 증거로 만들지 않았다. 320/390/768/1440px·글자 200%·실기기 터치와 스크린리더는 코드/단위 시험의 보장 범위를 넘어 **not_verified**다.

실제 Apify 호출·계정 잔액·사용권·도시별 실제 리뷰 언어 평가·제품 ON은 이 UI 시험의 결과가 아니다. 자동 시험 합성 수치를 운영 성과나 실제 주민 구성으로 해석하면 안 된다.
