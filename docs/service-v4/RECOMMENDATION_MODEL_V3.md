# 추천 모델 계약 — 적은 입력으로 시작하는 근거 기반 추천

2026-10-07 · 구현 제안. 학습되었거나 성능 향상이 입증된 모델이 아니다.

## 1. 설계 결정

현재는 규칙 기반·내용 기반 추천을 우선한다. 실제 사용자가 적은 상태에서 협업 필터링이나 학습 기반 순위 모델을 먼저 도입하면 클릭 편향과 데이터 부족의 영향이 크다. 여기서 데이터 기반이란 **출처가 있는 사실·관측 리뷰·명시적 선호·거리 데이터를 같은 입력에서 재현 가능하게 사용하는 것**이다.

추천기는 `CandidateBuilder → Eligibility → FeatureBuilder → Ranker → Diversifier → Explainer`의 단계를 명시적으로 분리한다. LLM은 마지막 설명 단계에만 선택적으로 사용한다. 실제 API와 파일 구조는 기존 `recommendations` 모듈을 확장한다.

## 2. 입력 스냅샷

- 서버가 검증한 사용자·여행 범위(`user/trip scope`), 조건과 버전(`conditions/version`).
- 방문 도시·날짜·인원, 출발점 유형과 좌표(`origin kind/coordinates`) 또는 비공개 참조와 버전(`private ref/version`).
- 반드시 지켜야 하는 조건과 선호. 미지정과 미확인(`unknown`)을 구분한다.
- `discovery_mode`: `observed_local / iconic / reference`의 명시적 버전 매핑.
- 선택한 장소 종류(`restaurant/cafe/attraction`)와 해당 도시의 실제 지원 기능(`city capability`).
- 사용 가능한 기준 지점(`canonical`) 후보와 지점 연결 버전.
- 사실·출처·집계·정책·모델·가격·평가 시각의 스냅샷(`facts/source/aggregate/policy/model/price/clock`).
- 조회 범위·후보 상한(`cap`)·후보 탈락 이유·선택적 선호 반영 동의.

`clock`은 추천 실행(`run`)의 접수 시각 또는 평가 기준 시각으로 고정한다. 새로 검색한 자료와 알고리즘 버전 변경을 한 비교에 섞지 않는다.

## 3. 후보 자격 판단(Eligibility)은 점수와 분리

| 평가 | 예 | 처리 |
| --- | --- | --- |
| 사용 불가 | 지점 불명 / 삭제 / 표시 권한 철회 | 노출·순위에서 제외 |
| 확인된 위반 | 휴무 / 인원 초과 / 필수 거리 제한 초과 | 추천에서 제외하고 사용자에게 사유 표시 |
| 필요한 자료 불명 | 도보 시간이 필수 조건인데 경로가 미확인(`route unknown`) | 방문 적합성을 `needs_confirmation`으로 표시 |
| 개인 입력 미지정 | 선호 태그 없음 / 예산 제한 없음 | 일반 모델로 정상 시작 |
| 언어 검증 기준(gate) 미통과 | 표본 부족 / 원문 불명 / 품질 기준 미통과 | `observed` 핵심 구획에서 제외하고 이유 표시 |
| 유명함의 근거 없음 | `public_map`의 이름·좌표만 있음 | `iconic` 핵심 구획에서 제외하되 `reference`로 제공 가능 |

`language_qualified`, `visit_fit`, `rankable`, `score_complete`를 하나의 불리언(boolean)으로 합치지 않는다. 예를 들어 언어 조건은 통과했지만 4인 예약 가능 여부가 미확인인 카드는 “언어 조건 통과 · 방문 조건 확인 필요” 그룹에 둔다.

## 4. 특징(feature) 사전

모든 특징(feature)은 `value, status, source_ids, as_of, version, missing_reason`을 반환한다.

| 특징 | 계산/자료 | 주의 |
| --- | --- | --- |
| local_lower | L/T | 주민 비율이 아니며, 검증 기준을 통과한 경우에만 사용 |
| korean_upper | (K+U)/T | 단순 K/C보다 보수적. 분모가 0이면 null |
| language_unknown | U/T | 추출 불명과 분리 |
| rating | 동일 플랫폼의 rating/scale | 서로 다른 플랫폼의 척도를 혼합하지 않음 |
| rating_count | 전체 평가 수 | 본문 언어의 분모와 분리 |
| regional_evidence | 검수된 지역·공식·편집 근거 | 없는 값을 인기(popular) 근거로 대체하지 않음 |
| iconic_evidence | official/platform/editorial 유형 | 원문에 없는 인기 순위를 추정하지 않음 |
| preference_match | 명시한 태그와 후보 태그의 교집합 크기 / 요청 태그 수 | 요청 태그가 0개이면 미지정이며 null |
| straight_distance | 사용자 출발점과 지점 사이의 지리적 거리 | 실제 도보 시간이 아님 |
| walking_duration | 공급자 경로 + 이동 수단 + 확인 시각 | 실패·미제공을 0분으로 표시하지 않음 |
| visit_fit | 영업·인원·고정 일정의 제약 평가 결과 | unknown을 satisfied로 채우지 않음 |
| price_fit | 통화·인당/그룹·세금·보증금 기준 | 비교 가능한 조건만 사용 |
| personal_feedback | 반영 범위를 정한 명시적 선호 | 방문하지 않았다는 사실을 맛 평가로 해석하지 않음 |

## 5. 첫 사용자를 위한 기본 모델(cold start)

새 모델명은 제안이며 기존 v1/v2 모델의 결과 재현(`replay`)을 보존한다. 한 구획(`section`)에서 사용할 모델을 먼저 정하고, 후보마다 기준이 낮은 모델로 바꾸지 않는다.

### local_observed_general_v3

선호·숙소·예산을 입력하지 않은 사용자도 자격을 충족하는 자료가 있으면 기본 순서로 결과를 받는다.

1. 동일한 유효 언어 검증 기준과 사용자가 명시한 필수 조건을 적용한다.
2. 방문 적합성 그룹(`confirmed / needs_confirmation`)은 섞지 않는다.
3. 그룹 내부에서는 `local_lower 내림차순 → korean_upper 오름차순 → language_unknown 오름차순 → canonical_place_id` 순서로 정렬한다.
4. 사용자가 “가까운 곳 우선”을 명시하면 선택한 `ordering_profile`에 따라 거리순으로 정렬한다. 기본 순서를 몰래 변경하지 않는다.
5. 다양성을 위해 동일 체인·동네·유형이 과도하게 반복되는 것을 제한하되, 필수 조건과 언어 검증 기준을 완화하지 않는다.

출력은 `ordering_kind=rule, rankable=true, score=null, ordering_profile=...`일 수 있다. `score=null`을 미완성 추천으로 간주하지 않는다. “맛있을 확률”, “주민 인기 점수”를 만들지 않는다.

### iconic_general_v3

- `공식 대표 명소`, `플랫폼에서 평가가 많은 곳`, `편집 자료 선정`의 근거 소그룹을 유지한다.
- 플랫폼 인기 그룹에서는 동일한 플랫폼·도시·종류·척도 안에서 `전체 평가 수 내림차순 → 평점 내림차순 → canonical_id`로 정렬한다. 이는 평가 규모에 따른 순서이며 방문객 수에 따른 순서가 아니다.
- 공식·편집 자료가 순위를 제공하지 않으면 해당 근거에 순위가 있다고 표현하지 않는다. 출처 목록의 자의적 순서를 “1위 명소”로 표시하지 않는다.
- 특정 근거 소그룹에만 자료가 충분하면 그 범위의 결과를 제공하고, 비어 있는 그룹은 자료 부족으로 남긴다.
- 현지어 검증 기능이 OFF여도 이 모델은 독립적으로 동작한다.

### reference_general_v3

지점이 확인된 공개지도·편집 자료의 참고 후보를 제공한다. 기본 순서는 명시한 출발점과의 직선거리 또는 안정적인 지점명·ID 순이며, 정렬 기준을 표시한다. 현지어·유명함·인기가 검증되었다고 주장하지 않는다. 핵심 두 구획의 수치를 채우는 데 사용하지 않는다.

## 6. 취향 반영 모델

기존 `local_observed/editorial/iconic`의 버전별 가중치 모델은 기준선으로 유지한다. 새로운 `personalized_v3`는 다음 조건을 충족할 때만 추가한다.

- 사용자가 선호 반영을 선택했고, 정의된 특징(feature)이 있어야 한다.
- 특징 함수·가중치·정규화·결측 규칙·다양성 규칙을 모델 등록부(`registry`)에 고정한다.
- 데이터가 빠지면 정해진 모델 전환을 `run`에 명시하고 사용자에게 “기본 추천”으로 표시한다. 후보별 재가중은 금지한다.
- 성분 총점이 다른 모델의 결과를 하나의 순위로 합치지 않는다.
- 피드백의 목적은 이번 여행에서 제외 / 다음 추천의 선호 반영 / 서비스 분석 / 향후 학습으로 분리한다.
- ‘관심 없음’ 철회·여행 삭제·분석 동의 OFF 상태에서도 개인 기능이 어떻게 동작하는지 검증한다.

새로운 가중치를 학습으로 얻은 최적값으로 소개하지 않는다. 첫 버전은 기존 정적 모델과 명시적인 일반 정렬만으로도 완성할 수 있다.

## 7. 같은 근거로 재현하는 설명

서버의 설명 근거 생성기(`reason builder`)가 출처 참조(`source ref`)와 수치·문구 슬롯을 만든다.

예(합성):

- `판별한 리뷰 190건 중 일본어 150건`.
- `관측 본문 200건 · 한국어 4건 · 미판별 10건`.
- `선택한 숙소에서 직선거리 650m`.
- `공식 관광 자료의 대표 장소 · 10월 7일 확인`.
- `4인 예약 가능 여부는 확인이 필요해요`.

LLM에는 확정된 place ID·순위·이유·허용 문구만 입력한다. 출력 검증기(`validator`)는 장소 추가·순위 변경·수치 변조·미확인을 확정으로 바꾸는 출력을 거절한다. 템플릿 대체 응답(`fallback`)은 외부 호출 없이 동일한 근거를 설명한다.

## 8. 평가

### 계약 평가

동일한 입력에서 같은 출력이 반복되는지 확인한다. 지점 오류·필수 조건 위반·언어/권한 검증 누락·null 또는 분모 왜곡·다른 사용자 참조는 모두 0건이어야 한다. 13번째·101번째 후보도 평가에 포함한다.

### 추천 순위 평가

동일한 조건·후보·사실·평가 시각(`clock`)·정책(`policy`)으로 모델 A/B를 비교한다.

- 상위 k개 후보의 canonical ID, 순위 변화, 점수 성분, 결측 사유.
- 체인·동네·종류의 중복 분포와 검증 기준을 통과한 후보 수.
- 언어 프로필·도시·종류별 자료 범위(`coverage`)와 잘못된 0건 판정.
- 특징 하나만 바꾸는 반사실적 테스트(`counterfactual test`)로 바뀌어야 하는 부분과 유지되어야 하는 부분 확인.
- 실제 관련성(`relevance`) 라벨이 없으면 NDCG·정확도는 미측정으로 표시한다. 합성 자료의 정렬 테스트 통과를 실제 만족도 향상으로 보고하지 않는다.

### 언어 평가

개발용 자료와 독립 평가용 자료(`heldout`)를 분리한다. 현지어 precision·한국어 recall·TP/FP/FN·unknown·모델/원문 버전을 기록한다. 한국어 정답 사례가 0개이면 `recall=null`이다. 평가용으로 보충한 한국어 리뷰는 장소 집계에 합치지 않는다.

### 실제 관찰

추천 화면의 실제 노출 → 저장 성공 → 일정 적용(`apply`) 성공 → 방문 피드백을 구분한다. 링크를 열었다고 원문을 읽거나 예약을 완료한 것으로 간주하지 않는다. 각 지표의 기간·분모·사용자 수·run 수·제외 범위를 표시한다. 소수 지인의 결과에서는 건수와 이유를 우선한다.

## 9. 학습 모델 도입 조건

현재 기본 결정은 `learning_status=insufficient_evidence`다. 클릭 몇 개만으로 자동 학습·가중치 변경·A/B 승자 선언을 하지 않는다.

후속 검토에는 독립적인 사용자·여행·도시·지점의 분포, 실제 노출과 긍정/부정/방문 결과, 동의·삭제 가능성, 시점을 분리한 평가 자료(`holdout`), 노출 위치 편향과 관련성 평가가 필요하다. 근거가 충분하지 않으면 기존 모델을 유지한다. 데이터를 기다리는 작업을 이번 구현 범위에 넣지 않고, 계측·평가 명령·양식을 완성한다.

## 10. 모델 전환과 기준 완화의 경계

- 일반 모델 선택은 사용자 입력 프로필의 미지정 또는 지원하지 않는 선호 조합에 의해서만 run/section 시작 시 결정한다. 후보 하나의 사실 누락으로 전체 구획이 더 쉬운 모델로 전환되지 않는다. 개별 후보의 근거 결측은 해당 후보의 unknown/insufficient 상태로 남긴다.
- 사용자가 바꿀 수 있는 기준은 L/T 하한, (K+U)/T 상한, 플랫폼 평점과 전체 평가 수다. 완화한 경우 새 run과 `직접 설정한 기준` 묶음을 사용하고 기본 strict 배지를 주지 않는다. C 최소값·U/T 품질 한도·지점/권한/정렬/원문/모델 gate는 사용자 변경 대상이 아니다.
- 초기 언어 평가 정책은 도시 전체100건 이상과 함께 한국어 정답50건·현지어 정답50건·현지어 판정50건 이상을 제안한다. 미설정/미충족이면 운영 gate가 닫힌다. 이는 작은 파일럿의 가설 기준이며 95% 실서비스 정확도 보장이 아니다.
