# 고잉 v4 수용 시험

2026-10-07 · 구현 전 계약. 아래 표는 목표 시험이며 아직 통과한 제품 검증 결과가 아니다. 현재 감사 결과는 AUDIT.md와 reports를 본다.

## 공통 원칙

- 모든 정상/실패 시험은 임시 SQLite 또는 disposable PostgreSQL, 합성 A/B 계정, 두 여행씩으로 실행한다.
- 운영 DB·실제 메일·실제 사용자 예약으로 삭제/충돌 시험을 하지 않는다.
- provider는 기본 fake다. 실제 공급자 시험은 따로 승인된 상한과 지점 목록으로 실행한다.
- 오류 재현 스크립트의 pass는 결함이 존재한다는 뜻이다. 수정 후 회귀 시험은 정상 계약을 assert한다.
- UI의 배지·카드 수·버튼 상태와 API 상태를 함께 검사한다. API pass를 브라우저 pass라고 하지 않는다.
- 동작에 영향 없는 문자열 동일성 테스트만으로 계약을 검증했다고 하지 않는다.
- 같은 입력에서 deterministic output은 ID·순서·자격·이유·버전을 비교한다. 실행 시각/서버 생성 ID는 정규화한다.

## 성능 실행 양식

하나의 숫자만 보고하지 않는다. 다음 열을 CSV/JSON으로 남긴다.

```text
run_id, environment, storage_backend, deployment_commit,
scenario, candidate_count, concurrency, repetitions,
cold_start, queue_ms, provider_ms, db_ms, pool_wait_ms,
render_ms, total_ms, sql_count, checkout_count, writes,
provider_calls, retries, error_code, cost_state
```

warm 저장 결과 p95 ≤ 2초, warm 캐시 추천 p95 ≤ 5초는 제안 목표다. 최소 20회·사용자 5명 조건과 데이터 크기를 명시한다. Render cold start·로컬/운영·실제 provider/fake를 분리한다. 공유 프로젝트에 부하를 주는 live 시험은 승인 범위를 먼저 확인한다.

## 경계 조건 보강

- B13: 한국어 정답이1개이고 모두 맞았어도 최소 분모 정책 미달이면 gate를 통과하지 않는다. 초기50건 기준·정책 미설정 차단을 함께 검사한다.
- B18: 사용자가 언어 비중/평점 기준을 완화하면 새 run과 `직접 설정한 기준` 묶음이 생기며 기본 엄격 배지는 없다. C/unknown 품질 기준은 소비자가 변경할 수 없다.
- B21~B23: 사용자 프로필 미지정에 따른 일반 모델 선택과 개별 후보 feature 결측을 분리한다. 후보 하나의 결측이 구획 전체의 모델 전환을 일으키면 실패다.
- A17: 탐색일이 초기 제안일인 것과 사용자가 나중에 직접 지정한 날짜의 우선권을 각각 검증한다.
