# 04 장소 탐색 검증 기록

검증 환경: 2026-10-05, 로컬 Python 3.13/FastAPI/SQLite, 현재 작업 디렉터리. 기존 01~03 코드와 사용자의 미커밋 변경을 보존했다. HEAD는 `aefee57`이며 이번 작업은 미커밋이다. 합성 검증과 실제 후보 검수를 구분한다.

## 구현

- migration 4: 여행별 방문 조건·버전, 장소 보관함·개인 메모·제외, 공용 후보팩·지점·필드별 사실·출처·사용 범위·감사·철회 기록.
- migration 5: 작업과 연결된 추천 입력/후보 snapshot, 순위 버전, 결과, 동일 방문일/인원의 비교 세트, 제한된 행동 이벤트.
- 기존 인증·소유권·CSRF·Origin·SQLite 작업/멱등 키·lease/fencing·삭제 절차를 재사용했다. 추천은 저장된 검수 후보와 리뷰 근거를 재사용하며 유료 외부 호출은 하지 않는다.
- URL 저장과 지점 확인을 구분한다. 검수된 ID/주소/공식 URL로 대조하며 모호한 이름은 후보 선택을 요구한다. 안전 URL reader는 DNS/IP/redirect/MIME/크기/시간을 검사하며 현재 resolver가 임의 URL을 자동 수집하지 않는다.
- 세 가지 점수 모델은 명시된 가중치를 사용한다. 필수 조건 위반/확인 필요/자료 부족/적합을 분리한다. 결측 성분이 있으면 종합 점수는 null이며 가중치를 재배분하지 않는다. 엄격 언어 조건은 공급자·품질·운영 gate를 통과한 관측 근거만 사용한다.
- 후보·출처 변경은 결과 활성화 직전 다시 검사한다. 저장 이후 철회/만료된 결과는 읽을 때 사용할 수 없게 처리한다. 비교는 같은 요청에 속한 서로 다른 2~3곳만 가능하다.
- LLM 유료 호출 없이 서버 템플릿으로 설명한다. 별도 설명 검증기는 새 장소·순서 변경·숫자/예약 주장·출처 변경을 거절한다.

## 브라우저 실행 기록

```bash
BROWSER_FIXTURE_DIR=<명시한 임시 경로> .venv/bin/python tests/browser_discovery_fixture.py
# 127.0.0.1:8765 앱, 127.0.0.1:8766 합성 OIDC
```

합성 A 로그인 → 도쿄 4인/11월 6~9일 여행 → 기존 여행을 재사용한 방문 조건 저장 → URL·개인 메모 저장 → 지점 확인 job → 상세 → 새로고침 후 조건·보관함 유지까지 실행했다. 세션 만료 시 개인 화면이 지워지고 합성 OIDC 재로그인 후 복원됐다.

추천 실행에서는 6곳 중 4인 조건에 맞는 2곳만 각 구획에 표시됐다. 확인된 최대 인원 2명/휴무 후보는 제외됐다. 실제 잔여석은 미확인, 이동은 직선거리 추정으로 표시됐다. 엄격 리뷰 조건을 켜자 현지 탐색 적합 결과는 0곳, 대표 명소 2곳을 유지했다. 다시 조건을 편집하면 이전 결과임을 명시했다.

검증 중 새 HTML에 오래된 JavaScript가 남아 추천 버튼이 작동하지 않는 정적 자산 문제를 발견했다. 자산 버전을 명시해 수정한 후 추천 작업/결과를 실제로 확인했다. 최종 비교·접근성 검증 기록은 아래에 이어 기록한다.

## 실제 자료와 미검증

`examples/real-discovery-candidates.json`에 도쿄/바르셀로나 각 6곳과 출처·지점 검수 기록을 작성했다. 출처는 2026-10-01 확인 시점을 유지하며 새로 읽었다고 날짜를 덮어쓰지 않는다. 12곳은 초기 조사 분량이며 도시별 30곳 목표를 완료한 것이 아니다. 실제 후보를 운영에 자동 등록/승인하지 않았고 표시 사용 권한은 검토 대기다. Sagrada Família 인원 규정 등 상충 근거는 conflict로 유지한다.

실제 OIDC 계정 로그인, 외부 장소 검색/경로/예약/잔여석, 실제 리뷰 수집과 타깃 리뷰 언어 품질 검증은 not_run이다. 실제 후보 부족 도시를 합성 데이터로 채워 운영 준비 완료라고 보지 않는다. 06 배포/상시 호스팅과 07 Plan B는 별도다.
