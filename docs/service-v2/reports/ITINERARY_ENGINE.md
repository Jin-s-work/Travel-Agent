# 05 일정 엔진과 편집 검증

2026-10-05 구현·합성 시험 기록이다. 실제 경로 공급자 또는 실제 식당의 미래 방문 가능 여부를 검증한 보고서가 아니다.

## 순수 함수 계약

- `intervals.resolve_local(local_iso, zone, fold=None, offset_minutes=None)`는 UTC instant와 `satisfied/violated/unknown`을 반환한다. 날짜만 있는 값은 instant가 없으며 임의 자정을 만들지 않는다. DST 중복 시각은 fold/offset 선택이 필요하고 존재하지 않는 시각은 거절한다.
- `scheduler.generate(snapshot, bookings, candidates, route_lookup, now)`는 고정 예약을 보존하고 결정적으로 후보를 삽입한다. 결과는 items, legs, conflicts, unplaced, unresolved_conditions, validation_status, assumptions, engine/config 버전과 탐색 횟수다.
- `constraints.validate(items, candidates, snapshot, legs, now, bookings=None)`를 생성·미리보기·적용·undo에서 공유한다. 방문 구간은 `[start,end)`이며 비교는 UTC 기준이다.
- `edits.preview(current, commands, snapshot, bookings, candidates, route_lookup, now)`는 원본을 변경하지 않고 명령·차이·영향 날짜·검증 결과를 만든다. `edits.revalidate`는 현재 예약과 장소 자료로 이동·제약을 다시 계산한다. DB revision·소유권·version·preview 만료·활성 pointer는 service/repository 책임이다.

순수 함수는 DB와 외부 공급자를 직접 호출하지 않는다. 서버가 만든 item ID를 재사용하며 예약 항목은 안정적인 booking/event 참조로 식별한다. 권한·가격·사용량을 검사하는 이동 어댑터는 명시적으로 주입한다. API는 도시 체류 구간 한 곳, 1~14일, 최대 30개 선택 장소를 지원한다. 도시 간 통합 최적화는 구현하지 않았으며 항공의 양 끝 현지 시각과 timezone은 그대로 보존한다.

## 배치와 시간 제약

고정 예약과 사용자 잠금 항목을 먼저 놓고 빈 구간마다 이전 항목→후보→다음 항목의 이동과 버퍼를 검사한다. 방문 전체가 영업 구간 안에 들어가야 하며 날짜 휴무·브레이크·마지막 입장·마지막 주문을 별도로 검사한다. 별도 브레이크 사실도 후보 영업 구간에서 빼므로 처음 가능한 시각이 브레이크에 걸려도 이후 유효한 구간을 탐색한다. 구간을 나눈 뒤에도 원래 마지막 입장·주문 제한은 유지한다. 원래 영업 범위와 마감의 확인 상태는 브레이크의 확인 상태와 분리한다. 따라서 잠정 브레이크 정보가 있어도 확인된 영업 시작·종료 또는 입장·주문 마감 위반을 unknown으로 낮추지 않는다. 자정을 넘는 영업은 다음 날 종료 구간이고, 일반 미래 주간 시간표는 날짜가 확인된 영업 사실이 아니다.

4박 숙소는 4일 전체 busy interval이 아니다. 숙박 anchor와 체크인·체크아웃 정보로 남기고 짐 보관은 별도 미확인이다. 날짜만 있는 숙박은 시각 미확인 표시를 유지한다. 날짜만 있고 시간이 없는 일반 고정 예약은 그 날짜의 자동 배치를 보류하며 예약을 자정으로 변환하지 않는다. 항공의 일정 포함 여부는 출발 현지 날짜 한 개가 아니라 UTC 구간으로 판단한다.

필수 인원·아동·식단·접근성·가격·반경 정보가 없으면 unknown이다. 시설 총좌석은 예약 인원 제한을 대체하지 않는다. 출처를 읽지 않았거나 사용 정책·기간이 맞지 않는 사실은 적합 근거가 아니다. provisional 영업·이동은 기본 엄격 모드에서 배치하지 않는다. 명시적으로 잠정 초안을 허용한 경우에만 provisional 항목으로 놓고 확인된 휴무·인원 불일치·시간 충돌은 계속 금지한다.

배치 후 같은 validator를 전체 일정에 다시 적용한다. 앞뒤 항목 변경으로 새 이동 충돌이 생기면 선택 방문을 미배치 목록으로 옮긴다. 고정 예약이나 사용자 잠금은 임의 이동·삭제하지 않고 충돌을 남긴다. 남는 빈 시간은 오류가 아니다.

## 이동과 가정

이동은 `provider/estimate/unknown`으로 나누고 추정 시간을 확인된 공급자 시간으로 승격하지 않는다. 경로 미확인은 0분이 아니다. 잠정 초안에서 필요하면 `planning_allowance_minutes`로 별도 공간을 예약하고 실제 `duration_minutes`는 null로 유지한다. 알려진 경로 불가(`ROUTE_IMPOSSIBLE`)와 미설정/실패(`NO_ROUTE`, unknown)를 구분한다.

공급자 확인 시각은 서버가 관측한 응답 시각과 비교한다. 작업 시작 직후 도착한 정상 응답을 미래 자료로 오인하지 않되 공급자 확인 시각이 응답 관측보다 미래이면 확인값으로 쓰지 않는다. 현재 시각의 만료 검사도 유지한다.

일반 버퍼, 예약 전후 버퍼, 공항 전후 버퍼는 별개다. 공항 버퍼를 모르는데 일반 도보 버퍼로 채우지 않는다. 선택한 버퍼와 체류시간 기본값은 snapshot에 남는다. 휴식은 실제 rest 항목이며 같은 장소에서 시작하는 휴식에 장소 간 이동 버퍼를 추가하지 않는다. 휴식까지 선택 장소의 이용 가능 구간을 벗어나지 않도록 검사한다.

여유롭게/보통/촘촘하게의 초기 주요 방문 목표는 하루 2/3/5개다. 방문 수는 제품 가설이며 편집자가 직접 추가한 일정의 물리적 제한과 혼동하지 않는다. 휴식 시간·빈도·필수 여부를 반영한다. 식사창을 직접 입력하면 이를 사용하고, 식사 종류만 선택했을 때 적용하는 도시별 제안 시간은 `DEFAULT_MEAL_WINDOW`로 명시한다. 모든 장소에 동일한 전 세계 식사 시간을 강제하지 않는다.

삽입 위치 비용은 추가 이동, 식사창 이탈, 동네 왕복, 해당 날짜의 기존 방문 수, 시작 시각, 안정적인 장소 ID 순이다. 성공 확률·최적 경로 보장이 아니다. 내부 평가 횟수는 기본 500, 최대 1,000으로 제한한다. 이동 어댑터의 별도 행렬 요소·시간·금액 제한이 먼저 소진되면 미확인/미배치 이유가 남는다.

## 편집과 현재 자료

명령은 add/remove/move/lock/unlock만 허용한다. 사용자 잠금은 먼저 명시적으로 unlock한 뒤 이동·삭제해야 한다. 예약에서 온 항목은 일정 편집으로 이동·삭제·잠금 해제할 수 없다. 예약 교정 화면에서 바뀐 현재 이벤트만 새 검증에 반영하며 일정 저장을 외부 예약 완료로 표현하지 않는다.

미리보기는 before/after 전체 항목과 added/removed/changed ID, 영향 날짜를 반환한다. 실제 적용은 서버에 저장된 preview와 기준 version으로만 수행한다. undo는 과거 내용을 현재 자료로 재검증한 새 revision이고, 삭제·취소된 예약을 부활시키지 않는다. 장소가 바뀌면 새 이름·좌표·좌표 사용 허용과 출처를 먼저 갱신한 다음 경로를 조회한다. 삭제되거나 사용을 철회한 장소의 과거 좌표로 공급자를 호출하지 않는다.

사용자가 체류시간을 직접 바꾸면 `duration_origin=user`로 기록하고 그 항목의 기본 체류시간 가정만 제거한다. 다른 가정은 보존하며 시작 시각만 옮겼을 때 기본 체류시간을 사용자가 확인한 값으로 바꾸지 않는다. 이 부분은 브라우저 최종 점검에서 발견한 표시 문제를 회귀 시험과 함께 수정했다.

## 실행한 검증


두 경고는 기존 FastAPI/Authlib의 httpx 호환 전환 안내다. 최종 전체 회귀 결과와 브라우저 흐름은 IMPLEMENTATION_STATUS의 상위 작업 기록을 따른다. 이 보고서 작성 직전 다음을 포함한 합성 사례를 실행했다.

위 74개는 순수 엔진 39개, API 21개, 이동 어댑터 14개다.

- 도쿄 4인과 바르셀로나 2인: 120분 창에는 90분 체류+양쪽 30분 이동이 들어가지 않는다. 150분 창은 정확히 맞고 예약 전 10분이 추가되면 실패한다.
- 13:30부터 90분 체류가 14~17시 브레이크와 겹치면 배치하지 않는다. 도착 시점만 검사하지 않는다.
- 숙박 4박, 일반 날짜만 있는 예약, 날짜만 있는 숙박, 명시적인 예약끼리 충돌을 구분한다.
- DST 존재하지 않는 시각·중복 시각과 fold, 자정 이후 영업, Tokyo 출발과 Madrid 도착, 출발·도착 현지 날짜가 다른 항공을 검사했다.
- unknown·estimate 경로, 미래 일반 영업시간, 잠정 휴업 제보는 엄격 모드에서 배치하지 않는다. 명시적 잠정 모드에서도 확인된 폐업·인원 불일치는 거절한다.
- 명시적 잠금 해제, 예약 편집 거절, 원본 불변 미리보기, 현재 예약 교정·삭제와 출처 철회 뒤 undo 재검증을 확인했다.
- 좌표와 이용 허용 변경 뒤 새로운 경로 입력, 삭제된 장소의 공급자 호출 0회, 작업 시작 이후 정상 경로 응답 시각을 확인했다.
- 밀도·휴식·식사창, 반경 제한, 공항 버퍼 미확인, 탐색 상한, 최종 검증에서 늦게 불가능해진 선택 방문 제거를 확인했다.
- 체류시간 60→40분 수정 시 기본 제안 표시 제거와 다른 가정 보존, 시작 시각만 수정할 때 기본값 출처 유지, 브레이크 뒤 17시 배치와 기존 마지막 입장 제한 유지도 확인했다.
- 잠정 브레이크와 확인된 영업 사실이 함께 있을 때 입장·주문 마감 각각의 위반, 영업 시작 전·종료 후 방문의 위반을 잠정 모드에서도 거절한다. 확인된 영업 범위 안에서 잠정 브레이크만 겹치는 방문은 확인된 위반으로 과장하지 않고 provisional로 유지한다. 마지막 점검에서 발견한 확인 상태 혼합 회귀를 수정하고 이 5개 사례를 추가했다.

이 하위 작업은 실제 경로 공급자·실제 OIDC 로그인·실제 방문·상시 배포를 검증하지 않았다. 상황별 Plan B는 07단계 범위이며 구현 완료로 표시하지 않는다.
