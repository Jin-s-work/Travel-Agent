# UI/UX 두 번째 개선 — 2026-10-06

적용 skill: `/Users/jinsangwoo/.codex/skills/emil-design-eng/SKILL.md`.
범위는 기존 제품의 여행 홈·추천 카드·일정 편집 동선이다. 기존 미커밋 변경을 보존했고 서버 계약·DB·추천 점수·일정 validator·비용 계산은 변경하지 않았다.

## 디자인 판단

| Before | After | Why |
| --- | --- | --- |
| 여행 제목·기간·요약이 흩어짐 | 옅은 녹색 여행 요약 카드로 묶음 | 선택한 여행과 인원을 먼저 확인 |
| 작업 요약이 본문 한 줄을 차지 | 상단 작업 버튼과 펼치는 패널 | 여행 콘텐츠 공간 확보, 진행/확인 필요 상태 유지 |
| 날짜 입력으로 예약을 필터 | 날짜·요일·예약 수를 보여주는 선택 막대 | 예약이 있는 날을 한 번에 찾기 |
| 필터가 항상 공간을 차지 | 상세 필터는 펼치기, 적용 조건은 요약에 표시 | 빠른 날짜 선택과 세부 검색의 역할 분리 |
| 추천 카드의 많은 행동이 나열 | 상세·저장, 일정·비교, 근거·관심 없음 순서 | 주요 선택과 부가 행동의 위계 명확화 |
| 일정 후보와 편집 버튼이 길게 펼쳐짐 | 후보 패널과 빠른 조정 도구는 펼치기 | 일정의 시각·장소·이동·확인 상태에 집중 |
| 같은 날짜를 시작·종료 시각에 반복 | 같은 날짜·시간대는 시각만 표시 | 한눈에 시간 확인; 자정·항공 시간대가 다르면 날짜 유지 |
| 탭을 떠난 사이 알림 종료 | 숨겨진 탭에서는 남은 표시 시간 보존 | 결과를 놓치는 상황 감소 |

첫 예약 카드의 상단은 같은 합성 데이터, 1280×900 화면에서 약 780px → 704px로 바뀌었다. 이는 배치 비교이며 실사용 성과 측정이 아니다.

## 구현 내용

- `web/index.html`: 상단 작업 패널, 여행 요약 컨테이너, 예약/일정 날짜 선택, 접힌 상세 필터와 일정 후보.
- `web/js/foundation.js`: 날짜 전용 UTC 계산, 날짜 버튼과 기존 예약 필터 연결, DOM 재사용으로 선택 시 포커스 유지, 작업 패널 Escape/바깥 클릭/포커스 이탈/닫기 동작, 추천 보조 행동, 기존 일정 미리보기 연결, 알림 일시 정지.
- `web/css/foundation.css`: 여행 요약·날짜 버튼·작업 패널·추천 행동·타임라인의 반응형 스타일. 키보드와 화면 전환은 무애니메이션. 이전의 포인터 누름/reduced-motion 규칙 유지. 타임라인 이동 시 sticky header에 제목이 가리지 않도록 여백 지정.
- `web/sw.js`: public shell v12. JS/CSS 내용 해시 갱신, 개인 API 캐시 제외 유지.
- `tests/test_journey_navigation.cjs`: 새로운 행동의 6개 회귀 시험.

여행 날짜 버튼은 최대 31일 범위에만 만든다. 더 긴 여행은 ‘전체’와 기존 날짜 입력을 사용하며 임의로 첫 31일만 보여주지 않는다. 날짜 버튼의 건수는 해당 날짜의 전체 예약 수이며 종류/확인 필요 필터가 적용된 목록의 건수는 별도로 표시한다. 수동 예약과 여러 날 숙박은 기존 `bookingOnDate` 규칙을 재사용한다.

미확인 잔여석·오래된 근거·합성 데이터·작업 실패 등의 안내는 부가 행동 속으로 숨기지 않았다. 변경을 실제 여행지 검증 또는 배포 완료로 간주하지 않는다.

```sh
  .venv/bin/python tests/browser_travel_tools_fixture.py
node --check web/js/foundation.js
npm test
python3 scripts/version_web_assets.py --check
git diff --check
```

- JS syntax, public asset hash, diff whitespace 통과. Python HTMLParser로 태그 닫힘과 ID 중복 검사 통과(166 IDs).
- 백엔드를 수정하지 않아 전체 Python suite를 재실행하지 않았다.

Codex 내장 브라우저에서 합성 OIDC A로 로그인하고 다음을 직접 확인했다.

1. 기존 여행·수동 예약을 새로고침 후 표시.
2. 11월 7일 선택 → 예약 1건, 11월 8일 → 0건과 빈 결과, ‘모든 예약 보기’ → 1건 복구. 선택한 날짜 버튼의 포커스 유지.
3. 작업 내역 열기, Escape 후 summary로 포커스 복귀, 닫기 버튼, 화면 이동. 데스크톱·390px·320px/200% 글자에서 패널 확인.
4. 합성 추천 요청 완료 → 현지 탐색/대표 명소 각 2곳. 보조 행동에서 관심 없음 폼 진입, 두 곳 비교 선택·비교 모달 확인. 피드백은 추가 저장하지 않고 닫았다.
5. 일정의 빠른 조정에서 ‘30분 앞당기기’ → 09:30 변경 폼. 원 일정은 10:00 유지. 실제 apply/undo 계약은 변경하지 않았으며 이번 라운드에서 재실행했다고 주장하지 않는다.
6. 모바일 상세 모달 시작 위치 `scrollTop=0`, 포커스 `dialogTitle`, 긴 다국어명 유지. Escape 닫기.
7. 390×844, 320×812에서 문서 가로 넘침 없음. 320px 다크/200%에서도 날짜 버튼 Enter 선택과 포커스 유지, 작업 패널 닫기 확인. 일정 날짜 제목이 상단 바 아래에 표시됨.
8. 로그아웃 → 개인 앱 숨김, 작업 패널 닫힘/숨김, 로그인 화면 복귀. 브라우저 console error 없음.

초기 재시작에서 `browser_product_fixture.py`는 이전 fixture의 변경된 여행 version과 이미 저장된 실행 키가 충돌해 시작하지 못했다. 제품 오류로 덮어쓰거나 DB를 삭제하지 않고, 같은 임시 데이터를 기존 `browser_travel_tools_fixture.py`로 열어 검증했다. 새 환경은 `BROWSER_FIXTURE_DIR`를 생략하면 새 합성 fixture를 생성한다. 화면의 예약·보관함·이전 일정은 첫 디자인 검증에서 만든 합성 자료이다.

실기기 iOS/Android, 전체 스크린리더 사용성, OS reduced-motion 직접 전환, 운영 로그인, Render 신규 배포는 미검증이다. 추가 유료 호출·의존성 설치·commit/push·배포 없음. 실제 검수 후보 도쿄 0 / 바르셀로나 0, 엄격 리뷰 OFF 상태는 유지한다.
