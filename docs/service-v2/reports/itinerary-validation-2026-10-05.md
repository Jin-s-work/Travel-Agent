# 05 일정 생성·편집 통합 검증

검증일: 2026-10-05. 기준 Git revision은 `aefee57`이며 사용자 변경과 01~04 구현을 보존한 미커밋 작업 트리에서 실행했다. 기존 개인 메일·운영 DB·Chroma를 검증용 자료로 변경하지 않았다. 커밋·push·배포·실제 외부 예약 변경은 실행하지 않았다.

## 연결한 제품 흐름

탐색의 저장 조건과 장소 선택을 일정 요청으로 넘긴다. 현재 여행·도시·기간·성인/아동·필수 조건을 재사용하며 선택 장소의 체류시간, 활동창, 별도 버퍼, 식사창, 휴식 선호, 잠정 허용을 입력한다. 서버가 입력 snapshot과 장소/예약/정책 manifest를 저장하고 기존 SQLite job을 생성한다. 생성 작업 성공과 일정의 검증/잠정/충돌 상태는 별개다.

migration 6은 itinerary, immutable revision, 만료되는 preview를 추가한다. 순수 시간/제약/삽입 엔진, 비용 wrapper를 쓰는 이동 adapter, 소유권/삭제/version을 검사하는 서비스와 타임라인을 연결했다. 삭제 cleanup과 백업 복원 tombstone 처리에도 일정 payload를 포함했다. API·저장 계약은 [API 검증 기록](ITINERARY_API_VERIFICATION.md), 시간과 알고리즘은 [엔진 검증 기록](ITINERARY_ENGINE.md), 실행 방법은 [일정 안내](../ITINERARY_RUNBOOK.md)를 따른다.

## 실제 브라우저 실행

```bash
BROWSER_FIXTURE_DIR=<검증용 임시 경로> .venv/bin/python tests/browser_itinerary_fixture.py
# 앱 127.0.0.1:8765 / 합성 OIDC 127.0.0.1:8766
```

04에서 사용한 임시 여행과 보관함을 재사용했다. 도쿄 2026-11-06~09, 성인4명, 합성 장소2곳이다. 운영 앱은 harness의 가짜 장소/경로를 import하지 않는다. 경로는 네트워크 없이 10분·500m를 반환하는 시험 전용 공급자이며 화면에도 합성 자료임을 표시한다.

1. 탐색의 장소 선택과 기존 조건을 확인하고 11월6일 일정 생성을 요청했다. 저장된 job이 완료되고 새 version1이 표시됐다. 첫 방문10:00~11:00, 둘째11:20~12:20, 휴식12:20~12:40이다. 두 이동마다 별도 일반 준비 버퍼10분을 표시했다.
2. 둘째 방문을11:30~12:10/40분으로 바꾸는 미리보기를 열었다. 변경 전후·영향 날짜·양쪽 이동을 확인했으며 이때 원 일정은 version1이었다.
3. 적용 후 version2가 됐고 새로고침해도11:30~12:10이 유지됐다.
4. 한 편집 되돌리기를 미리보고 적용해 **새 version3**으로11:20~12:20을 복원했다. 과거 version1로 포인터를 되감지 않았다.
5. 별도 충돌 시험에서는 첫 방문을30분 늦췄다. 다음 항목과 겹침·이동시간 부족이 표시되고 적용 버튼이 비활성화됐다. 원 일정을 유지했다.
6. 서버를 재시작한 뒤 기존 저장 일정과 작업을 조회했다. 합성팩 재승인으로 source version이 바뀐 과거 일정은 오래된 근거 상태로 표시됐고 자동으로 검증 완료로 복구하지 않았다. 새 요청의 일정은 현재 source로 생성했다.
7. 320px 화면에서 앱의 실제 글자크기200%를 사용했다. 페이지 scrollWidth320, 편집 모달 내부 client/scroll 폭252로 가로 넘침이 없었다. 긴 다국어명, 시간 입력, 키보드 Enter 열기와 Escape 닫기/포커스 복귀를 확인했다. 탐색 화면도 폭320을 유지했다. 검증 후100%와 원래 viewport로 복원했다.

이 여행의 브라우저 시나리오는 선택 장소와 휴식 편집을 검증했다. 고정 항공·호텔·예약 충돌과 동시 탭 race는 위 자동 시험으로 검증한 범위이며 모든 사례를 브라우저에서 반복한 것은 아니다. 실제 브라우저 error console은0건이었다. 재개 후 같은 브라우저 흐름을 새 일정으로 다시 수행했다. 체류시간을40분으로 편집했을 때 사용자 입력으로 표시되고 기본 제안 문구가 제거된 것을 확인했다. 휴식에는 예약 확정을 표시하지 않으며 유효한 동일 지점 이동과 미확인 이동도 구분했다. 최종 화면의 콘솔 error0건과 타임라인 사진을 확인했다. 잠정 브레이크가 확인된 영업 종료/마감을 약화하던 마지막 회귀는 자동 시험5개를 추가하고 전체682개로 검증했다. 이 마지막 조건 조합을 실제 브라우저에서 다시 생성한 것은 아니다.

## 운영 경계

- 구현 범위는 한 도시 체류 구간의1~14일, 최대30개 선택 장소다. 도시 간 자동 연결 최적화는 제공하지 않으며 도시 경계 입력을 검사한다.
- 실제 경로 제공자는 기본 미설정이다. 허용 좌표의 짧은 도보 추정은 계획 가정이고 엄격 모드의 확인 경로가 아니다. 실제 영업일·잔여석·교통·이동 안전을 검증한 서비스로 표시하지 않는다.
- 자연어 편집은 선택 항목의 삭제/잠금/잠금 해제/명시적 날짜·시각 이동만 지원하는 제한된 parser다. 모호한 지시는 명확화를 요구하고 유료 LLM을 호출하지 않는다.
- 실제 OIDC 계정, 실제 지도 과금·경로, 실제 리뷰 수집·언어 품질, 실식당 미래 방문 가능성은 미검증이다. 실제 후보는 각 도시6곳 검수 자료를 보존했으며 운영 표시 승인 대기다.
- 06 상시 호스팅/출시·운영 재해 복구와07 상황별 Plan B는 이 단계의 완료 범위가 아니다.
