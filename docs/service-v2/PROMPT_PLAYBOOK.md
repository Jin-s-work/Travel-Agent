# Travel Agent 상세 개발 프롬프트 사용 안내

이 안내는 서비스를 구현하는 순서와 각 단계의 완료 기준을 설명합니다. **실제로 복사할 긴 프롬프트 본문은 [전체 프롬프트 모음](COPY_READY_PROMPTS.md)에 있습니다.** 문서를 읽으라는 짧은 실행문 대신, 단계마다 제품 목표·화면·데이터·API·처리 순서·예외·검증·인계를 포함한 본문을 전달합니다.

핵심 베타까지 6단계, 출시 후 고도화 2단계입니다. 프롬프트가 작성됐다는 사실은 서비스 기능이 구현됐다는 뜻이 아닙니다.

## 바로 사용하는 방법

1. Codex에서 이 저장소를 열고 [전체 프롬프트 모음](COPY_READY_PROMPTS.md)의 01단계 블록 전체를 복사해 보냅니다.
2. 개발 결과의 동작 화면·실제 테스트·남은 제약·다음 단계 준비 여부를 확인합니다.
3. 02단계 블록 전체를 보내고 같은 방식으로 진행합니다. 별도 마스터 프롬프트는 필요 없습니다.
4. 같은 채팅에서 이어가는 것이 간단합니다. 새 채팅이라도 같은 최신 저장소와 진행 기록을 읽으면 계속할 수 있습니다.
5. 작업이 끊기면 아래 재개 요청을 사용합니다. 이미 완료된 기능을 다시 만들지 않습니다.

파일 하나만 따로 전달하려면 아래 표의 해당 상세 프롬프트를 사용합니다. 모음 문서의 블록과 개별 파일의 본문은 같습니다. 단계 번호만 다른 짧은 지시문이 아닙니다.

현재 로컬 경로는 /Users/jinsangwoo/Desktop/ChatGPT/travel-inbox-rag 입니다. 다른 컴퓨터에서는 실제 checkout 경로로 바꿉니다. 저장소 파일을 읽지 못하는 도구를 쓸 때는 관련 기획·코드도 함께 제공해야 합니다.

03단계의 읽기 전용 공급자 조사는 기반 개발과 병행할 수 있습니다. 수집 실행은 02단계의 작업·예산 경계를 사용합니다. 04단계는 보관함과 사실, 추천 엔진, 화면 연결을 순서대로 완성합니다. 07단계도 예약 준비, 대체 일정, 오프라인을 각각 검증합니다.

07~08은 첫 배포의 선행조건이 아닙니다. 03의 실데이터 검증이 남아 있어도 04~05의 개발은 진행할 수 있으나 리뷰 엄격 기능은 비활성입니다. 기본 베타 배포와 핵심 리뷰 기능의 실사용 검증 완료는 구분합니다.

## 이번 프롬프트에 구체화한 내용

- 현재 api.py·src/agent.py·src/store.py·web/index.html에서 옮길 책임과 유지할 기능.
- 테이블 필드·소유권·고유성·version·삭제 이력과 구조화 데이터/검색의 역할.
- API method·경로·입력·응답·상태 코드·job·부분 실패·재시도 계약.
- 원문과 번역문, 별점-only와 추출 실패, 관측 비율과 전체 추정의 구분.
- 추천 순서·가중치·결측값·엄격 조건·다양성·근거 설명·사용자 조건 완화.
- 시간대·자정·브레이크·입장 마감·이동·고정 예약·미배치·undo의 검증.
- 필터·카드·비교·타임라인·오류·모바일·키보드·오프라인의 사용자 행동.
- 실제 후보팩 준비·운영 이미지·영구 경로·예산·메모리·백업·삭제 후 복원.
- 실제 사용 지표의 분모와 한계, 가격 미확인·통화·예약 보증금 처리.

새 모듈·일부 API는 구현 제안입니다. 이미 존재한다고 주장하지 않으며 실제 코드와 대조하고 필요한 결정은 기록하도록 했습니다. 가중치·한도·운영 목표의 제안값도 이미 검증된 성능이나 사용자 승인으로 취급하지 않습니다.

## 완료 결과를 판단하는 기준

‘화면을 만들었다’, ‘단위 테스트가 통과했다’만으로 해당 단계 전체가 완료되지는 않습니다.

- 사용자가 화면에서 수행할 수 있는 행동이 API와 저장소까지 연결되어야 합니다.
- 잘못된 입력·빈 결과·부분 실패·권한·재시작 같은 관련 실패 사례를 검증해야 합니다.
- fake provider와 합성 데이터 결과, 실제 공급자 결과를 구분해야 합니다.
- 운영 준비·실제 배포·리뷰 품질·실제 도시 후보 준비 상태를 각각 보고해야 합니다.
- 키나 계정이 없으면 가능한 구현과 검증을 끝내고 해당 live 실행만 미완료로 남깁니다.
- 날짜·코드 revision·미커밋 변경·명령·실제 결과와 미검증 이유가 있어야 합니다.

진행 기록은 docs/service-v2/IMPLEMENTATION_STATUS.md입니다. 구현 상태는 not_started/partial/complete/blocked, 실환경 검증은 not_run/partial/verified/not_required로 별도 관리합니다. 인수시험의 통과는 실제 실행 증거가 있을 때 기록합니다.

## 중단 후 재개 요청

이 블록은 개발 단계의 긴 본문을 대체하지 않고, 이미 시작한 작업을 이어갈 때만 사용합니다.

```text
/Users/jinsangwoo/Desktop/ChatGPT/travel-inbox-rag 저장소에서 이어서 작업해줘.
docs/service-v2/PROMPT_PLAYBOOK.md와 docs/service-v2/IMPLEMENTATION_STATUS.md,
현재 diff와 실행 결과를 확인해줘.
진행 중이거나 가장 먼저 미완료인 단계의 상세 프롬프트를 다시 적용해.
이미 완료된 부분은 유지하고 남은 구현·수정·검증을 끝내줘.
기록과 코드가 다르면 실제 코드와 실행 증거로 상태를 바로잡아줘.
외부 설정이 없어도 독립적인 구현은 계속하고 막힌 live 검증만 따로 기록해줘.
```

공급자 키·이용 조건·언어 평가 데이터가 마련되면 03단계를 다시 적용합니다. 배포 환경이 마련되면 06단계를 다시 적용합니다. 실제 이용 기록이 생기면 08단계의 평가·회고를 다시 실행하며, 작업 안에서 수 주를 기다리지는 않습니다.
