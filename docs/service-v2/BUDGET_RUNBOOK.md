# 외부 호출 비용 설정·정산

2단계 서비스의 추출, 문서/질의 임베딩, 생성 답변은 `ProviderGateway`를 통과한다. 설정이 없으면 `BUDGET_NOT_CONFIGURED`로 호출 전에 닫힌다. 여행·예약 SQL 조회와 날짜 전체 질문은 외부 비용 설정이 없어도 작동한다. 기존 독립형 개발 CLI의 `src.parser`/`src.rag`/`src.embedder` 직접 실행은 서비스의 인증·과금 scope 밖이다. 서비스 운영 실행 경로로 사용하지 않는다. 이관 CLI의 `--process`는 실제 공급자 호출 전에 거절하며, 자료만 이관한 후 로그인한 화면에서 내구성 재분석 작업을 만든다.

## 설정

1. `examples/pricing-policy.template.json`을 공개 웹 디렉터리 밖의 운영 설정 경로로 복사한다.
2. `openai/모델명` 키를 현재 `EXTRACTION_MODEL`, `ANSWER_MODEL`, `EMBEDDING_MODEL`과 정확히 맞춘다. 추출과 답변 모델이 다르면 두 chat SKU를 각각 추가한다.
3. 실제 공급자 계약/가격표를 확인한 뒤 `rates_per_million`에 **백만 단위당 통화 금액**을 소수 문자열로 넣는다. `null`은 미설정이며 템플릿 자체로는 유료 호출을 허용하지 않는다. 코드에 과거 단가나 무료 잔액을 넣지 않았다.
4. `confirmed_at`을 확인한 UTC ISO timestamp, `version`을 운영자가 구별할 수 있는 가격 개정 식별자로 바꾼다. 각 호출은 당시 단가·버전·확인일을 복사하므로 나중에 설정을 바꾸어도 과거 호출 정산 단가는 바뀌지 않는다.
5. `limits` 네 값은 해당 통화의 **백만분의 일 단위 정수**로 설정한다. 예를 들어 1 USD는 1,000,000 micro-USD이다. 이는 단위 설명이며 예산 권장값이 아니다. 사용자 일/월, 전역 일/월 상한을 모두 지정한다.
6. `PRICING_CONFIG=/운영설정/파일.json`으로 경로를 지정하고 서버를 재시작한다. `GET /api/v2/usage`의 `configured`와 설정 화면에서 확인한다.

`max_units`는 호출 한 번의 크기 제한이다. chat 출력은 `max_completion_tokens`로 강제하며 입력 추정에는 메시지·구조화 출력 스키마의 UTF-8 길이와 framing 여유를 포함한다. 임베딩은 실제 batch마다 따로 예약한다. 이 상한을 넘는 입력은 `COST_BOUND_EXCEEDED`로 공급자에 전송하지 않는다. 가격/한도 숫자에 NaN·음수·부동소수 한도·미지정 단위가 들어가면 설정은 유효하지 않다.

기간 경계는 UTC 날짜와 월로 고정한다. 서버 로컬 시간대로 바뀌지 않는다. 통화는 각각 집계하고 승인되지 않은 환율로 더하지 않는다. 무료 크레딧은 자동으로 있다고 가정하지 않으며 다른 앱의 동일 공급자 계정 사용량은 이 ledger가 관측하지 못한다.

## 예약과 정산 읽기

`usage_reservations`는 호출 당시 예상 최대 비용을 보유한다. `usage_ledger`는 예약·미확정·정산 차액·명시적 미전송 해제를 append-only로 기록한다. 파일 저장에는 개인 여행 ID/서버 호출 ID만 쓰며 공급자 오류 본문·API key를 ledger에 넣지 않는다.

| 상태 | 뜻과 비용 계산 |
| --- | --- |
| `reserved` | 아직 전송하지 않은 호출. 예상 비용을 점유한다. |
| `sent` | 전송 단계 진입. 프로세스 종료 뒤 영수증이 없으면 `unknown`으로 전환하며 재호출하지 않는다. |
| `settled` | 응답 사용량으로 정확히 한 번 정산. 실제 비용을 집계한다. |
| `unknown` | timeout/응답 유실/원격 성공 직후 crash. 예상 비용을 유지한다. |
| `pending_reconciliation` | 응답 또는 거절은 확인했지만 사용량은 미확정. 예상 비용을 유지한다. |
| `released` | 전송하지 않은 것이 확인된 시도만 해제한다. 일반 오류로 해제하지 않는다. |

성공 응답은 0600 파일에 기록하고 fsync한 뒤 SQL에 참조/정산을 기록한다. 영수증 저장 후 SQL 정산 전에 종료되면 같은 호출의 영수증을 읽어 정산한다. 원격 성공 후 영수증 저장 전 종료는 로컬 시스템이 원격 결과를 알 수 없는 구간이므로 `unknown`으로 남는다. 외부 exactly-once를 보장하지 않는다.

작업 ID+단계 키+시도 번호가 호출 식별 범위다. 같은 작업의 복구는 완료 응답을 재사용한다. 사용자의 새 재분석 작업은 새 호출 예산을 사용한다. 취소·여행 삭제·세션 회수 뒤 도착한 응답도 사용량은 정산하지만 제품 결과나 개인 파일은 활성화하지 않는다.

SDK 재시도는 `max_retries=0`으로 끈다. 명확한 연결 전 실패는 미전송 해제 후 새 시도로, 명확한 429 거절 응답은 이전 예상 비용을 유지한 채 새 비용을 예약한 후 최대 3회까지 실행할 수 있다. Retry-After/backoff는 한 번에 최대 5초이며 전체 deadline이 있으면 넘지 않는다. 400·401·403은 자동 반복하지 않는다. 응답 유실·read timeout과 성공 여부를 알 수 없는 5xx는 원격 조회/idempotency 보장이 없으므로 자동 반복하지 않는다.

실제 사용 비용이 추정 상한을 초과하면 차액을 원장에 남기고 해당 통화의 후속 외부 호출을 중단한다. 앱 내부 한도는 이미 발생한 공급자 청구의 절대 상한이 아니다. `BUDGET_EXHAUSTED`는 개인 한도, `GLOBAL_BUDGET_STOPPED`는 전역 중단/전역 한도다. 저장 자료는 계속 읽을 수 있다.

서비스의 실제 외부 호출은 공통 semaphore 1개를 공유하므로 대화 요청과 dispatcher 작업을 합해 기본 동시성 1이다. 대기 중에는 비용을 예약하되 아직 `sent`로 기록하지 않는다. 실행 슬롯을 얻은 뒤 권한·취소·deadline을 다시 확인하고 거절되면 미전송 예약을 해제한다. 저장 영수증 재사용과 SQL 조회는 이 실행 슬롯을 기다리지 않는다. 이 보장은 문서화된 단일 서버 프로세스 배포 범위다.

## 미확정 사용량 검토

공급자 응답/청구 내역으로 확인한 사용량만 `Budget.reconcile(call_id, actual_units, actor_id=관리자ID, reason_code='PROVIDER_INVOICE')`에 전달한다. 관리자 role과 active 상태가 필요하며 실제 사용자 데이터를 응답이나 로그에 출력하지 않는다. 원래 예약 기록을 삭제하거나 0 비용으로 추정하지 않는다. `reason_code`는 개인 정보 없는 대문자 코드다. 확인 근거가 없으면 미확정 상태와 예약 비용을 유지한다.

API 토큰·메일 원문·공급자 오류 전문을 정산 사유에 붙이지 않는다. 운영자가 확정한 자료와 별도의 민감하지 않은 정산 근거 식별자를 관리한다. 현재 비용 정산은 로컬 관리 API 클래스 수준이며 외부 관리자 HTTP 수정 화면은 제공하지 않는다.

추정 초과에 따른 통화 중단을 해제할 때는 실제 초과 정산 호출을 확인하고 가격/상한을 고친 뒤 `Budget.resume_after_review(call_id, actor_id=관리자ID, reason_code='PRICE_REVIEWED')`를 사용한다. 관리자와 사유가 원장에 남고 이미 발생한 비용이나 미확정 비용은 지워지지 않는다. 다음 호출에도 네 예산 한도가 다시 적용된다.

백업 시 API와 dispatcher를 중지한 뒤 SQLite·원문·Chroma와 `private-job-artifacts`를 함께 보존한다. 이관/복원 도구가 공급자 영수증과 checkpoint 파일도 복사하고 체크섬 검증한다. 복원은 기존 계약대로 세션을 무효화한다.

## 실행한 검증

```bash
OPENAI_API_KEY=test SEED_ON_EMPTY=0 .venv/bin/python -m pytest \
  tests/test_reliability_budget.py tests/test_reliability_runtime.py -q
```

실제 공급자/과금 API는 호출하지 않았다. 합성 단가·합성 공급자와 임시 SQLite/실제 임시 Chroma를 사용했다. 비용 마지막 잔액의 독립 프로세스 경쟁, 영수증 앞뒤 crash, SIGKILL 후 추출/임베딩/활성화 checkpoint 복구, 취소/회수 후 늦은 비용 정산, 불명 비용 유지, SDK 내부 재시도 차단, 예산 소진 때 SQL 날짜 질문을 검증한다. 최종 전체 테스트 수와 명령 결과는 `IMPLEMENTATION_STATUS.md`에 기록한다.
