# Google 리뷰 크롤링을 통한 언어 분포 기능 검증

작성·자료 확인: 2026년 10월 1일. 대상은 본인과 소수 지인이 쓰는 도쿄·바르셀로나 여행 서비스입니다.
이 문서는 공식 문서 조사와 공개 가격 메타데이터 조회 결과입니다. 실제 장소 리뷰 수집, 유료 실행, 계정 설정, 운영 크롤러 구현은 수행하지 않았습니다.

## 1. 정정할 전제와 이번 권고

**“Places API가 최대 5개 리뷰를 반환한다”와 “Google 리뷰를 5개보다 많이 수집할 수 없다”는 다른 주장입니다.**
Google Places API New의 `reviews`는 관련도순 최대 5개입니다. 이는 해당 API의 응답 범위입니다. [Google Place 자료형](https://developers.google.com/maps/documentation/places/web-service/reference/rest/v1/places)
Apify·Outscraper·SerpApi는 공개 Google Maps 화면의 리뷰를 여러 건 가져오는 별도 서비스를 문서화합니다. 공식 Places API의 리뷰 한도를 그대로 받는 경로가 아닙니다. [Apify](https://apify.com/compass/google-maps-reviews-scraper), [Outscraper](https://docs.outscraper.com/endpoints/google-maps-reviews/), [SerpApi](https://serpapi.com/google-maps-reviews-api)
따라서 언어 분포 기능은 기술적으로 검증할 가치가 있으며, “5개 제한”만으로 출시 후보에서 제외하지 않습니다.
다만 수집 성공, 원문 정확성, 표본의 의미, 이용 조건, 운영 비용을 각각 통과해야 합니다.

**권고: Apify의 소규모 실험을 우선 설계하고, 적용 약관·이용 권한과 계정별 비용 조건을 확인한 뒤 실행합니다.**
원문과 번역, 원문 언어를 구분하는 출력이 문서화되어 있고 소규모 이벤트 사용액이 낮아 이 기능의 첫 검증에 적합하다는 판단입니다.
공급자가 “모든 리뷰”를 수집한다고 소개하더라도 특정 장소의 전수 수집·현재 정상 작동·분석 및 재배포 권한을 검증한 것으로 처리하지 않습니다.

## 2. 가능한 수집 경로

| 경로 | 검증할 수 있는 것 | 첫 버전 판단 |
| --- | --- | --- |
| 사람이 공개 화면을 확인 | 원문·번역·언어·장소 매칭의 소량 기준 자료 | 품질 대조에 사용 |
| 공개 화면의 DOM을 읽는 자체 브라우저 수집 | 화면에 표시되는 리뷰를 정렬·스크롤하며 수집하는 방식 | 허용 범위를 확인한 제한 실험 후보 |
| Apify Compass 리뷰 Actor | 장소 목록을 받아 리뷰 데이터셋을 생성 | 우선 후보 |
| Outscraper Reviews API | 리뷰 수와 날짜 범위·페이지네이션을 지정 | 대체 후보 |
| SerpApi Reviews API | 페이지 토큰으로 리뷰를 순차 조회 | 명확한 페이지 제어가 필요한 대체 후보 |

자체 DOM 수집은 장소 열기, 리뷰 영역 확인, 정렬, 보이는 리뷰 읽기, 중복 제거, 한도에서 중단하는 수준으로 설계합니다.
이 경로의 실제 작동 여부와 허용 범위는 이번에 검증하지 않았습니다. 선택자·스크롤 동작·번역 상태가 바뀌면 유지보수가 필요하다는 구현상 판단입니다.
로그인 제한, CAPTCHA, 접근 거부를 만나면 중단합니다. 우회·계정 교대·제한 회피를 실험 범위에 넣지 않습니다.
자체 브라우저 실행은 서버 CPU·메모리와 개발 시간을 소비하므로 “리뷰 API 요금이 없음”을 “비용이 없음”으로 계산하지 않습니다.
현재 512MB 앱 서버에 브라우저 수집기를 함께 넣는 것은 메모리를 측정하기 전에는 채택하지 않습니다.

### 자체 브라우저 수집을 시험한다면

자체 구현도 기술 후보입니다. 아래는 **공개 화면과 허용된 접근 범위를 전제로 한 설계 의사코드**이며 실제 Google 화면에서 검증한 실행 코드가 아닙니다. 확인하지 않은 CSS 선택자나 비공개 엔드포인트를 작동하는 코드로 제공하지 않습니다.

```text
입력: 지점 URL, 최대 레코드, 기간, 시간·페이지 상한, 허용 정책 버전
1. 지점의 이름·주소를 확인하고 리뷰 영역을 연다.
2. 최신순 설정과 원문 표시 상태를 확인한다.
3. 현재 화면에 실제 나타난 리뷰마다 다음을 수행한다.
   - 원문과 번역, 본문 없음과 추출 실패를 구분한다.
   - 허용된 리뷰 ID, 날짜, 원문, 별점만 표준화한다.
   - 작성자 프로필·사진·다른 방문 내역은 수집하지 않는다.
   - 이미 본 ID의 편집본인지 새로운 리뷰인지 검사한다.
4. 리뷰 영역을 작은 구간으로 이동하고 새 레코드를 즉시 처리한다.
   - 가상 스크롤로 이전 DOM이 사라질 수 있어 마지막에 한 번만 읽지 않는다.
5. 반복 화면·새 레코드 없음·한도·기간·차단 상태를 구분해 종료한다.
6. 종료 사유, 실제 원문 수, 미판별과 추출 불명 수를 반환한다.
```

현재 보이는 리뷰 수가 전체 수집 수가 아니고, 스크롤 끝이 플랫폼 전수의 증거도 아닙니다. 정렬 상태나 원문 분리가 바뀌면 기존 파서를 계속 적용하지 않고 품질 실패로 멈춥니다. UI의 번역 토글·더보기·날짜 표시를 검수한 fixtures와 대조합니다.

초기 운영 서버에는 이 브라우저를 함께 상주시키기보다 독립적인 제한 실험으로 실행하고 결과 계약만 같은 adapter에 연결하는 편이 낫다는 판단입니다. 자체 코드의 장점은 동작을 직접 통제하는 것이고, 부담은 페이지 변경 대응·실패 재현·원문 정확성 검수입니다. 이 부담을 감당할 수 있는지 상용 공급자의 낮은 실험 비용과 비교합니다.

## 3. 공급자별 기술 확인

### Apify Compass Google Maps Reviews Scraper

공식 소개는 수천 건을 반환할 수 있다고 설명하면서 입력·장소·웹사이트 내부 한도·도구 상태에 따라 결과량이 달라진다고 명시합니다. 장소별 실제 시험이 필요합니다. [수집 범위와 한계](https://apify.com/compass/google-maps-reviews-scraper)
입력은 Maps URL 또는 지원되는 Place ID이며 `maxReviews`로 장소당 상한을 둡니다.
`reviewsSort`는 `newest`, `mostRelevant`, `highestRanking`, `lowestRanking`을 지원합니다.
`reviewsStartDate`를 쓰면 `newest`가 필요하고 절대 날짜·시각은 UTC로 해석합니다.
`reviewsOrigin=google`로 제3자 원천 리뷰가 섞이지 않게 하고, `reviewsFilterString`은 비웁니다.
`personalData=false`로 작성자 이름·사진·프로필 등 불필요한 항목을 제외해도 `reviewId`는 반환됩니다. 기본 설정을 그대로 쓰지 않습니다. [입력 스키마](https://apify.com/compass/google-maps-reviews-scraper/input-schema)

공식 출력 예제에는 `text`, `textTranslated`, `originalLanguage`, `translatedLanguage`, `reviewId`, `publishedAtDate`, `scrapedAt`, `reviewOrigin`이 있습니다.
`language`는 실행의 표시 언어이므로 리뷰 원문 언어로 집계하지 않습니다. 언어 집계에는 원문과 `originalLanguage`를 사용하되 샘플로 검증합니다. [출력 예제](https://apify.com/compass/google-maps-reviews-scraper)
공급자 언어 라벨을 정답으로 고정하지 않고 독립적인 원문 언어 판별과 불일치 여부를 기록합니다.
반환 ID도 연결 가능한 식별자이므로 작성자 필드 제거만으로 완전한 익명 데이터라고 부르지 않습니다.

### Outscraper Google Maps Reviews API

`reviewsLimit`는 장소당 리뷰 상한이며 0은 무제한 요청을 뜻합니다. 이 프로젝트에서는 항상 양의 상한을 지정합니다.
`lastPaginationId`로 다음 범위를 요청하고 `sort`로 최신순·관련도순·평점순을 선택합니다.
`start`와 `cutoff`는 리뷰 시각 범위를 지정하며 사용 시 정렬이 최신순으로 바뀝니다.
`source=google`, `ignoreEmpty`, 조회 표시 언어인 `language`를 지원합니다. [API 입력 문서](https://docs.outscraper.com/endpoints/google-maps-reviews/)
문서에서 확인한 예제에는 `review_text`, 리뷰 링크·별점·타임스탬프가 있으나 원문·번역·원문 언어를 명확히 분리한 필드는 확인하지 못했습니다.
이는 그 기능이 없다는 확정이 아니라 공개 문서로 확인하지 못했다는 뜻입니다. 원문 보존과 안정적인 리뷰 ID를 실제 응답에서 검증해야 합니다.
비동기 요청 결과는 완료 후 4시간 동안 조회할 수 있다고 문서화되어 있어 결과 회수 실패 처리도 필요합니다. [응답·비동기 문서](https://docs.outscraper.com/endpoints/google-maps-reviews/)

### SerpApi Google Maps Reviews API

`next_page_token`으로 다음 페이지를 가져옵니다. 필터 없는 첫 페이지는 8개, 이후 `num`은 최대 20개입니다.
정렬은 `qualityScore`, `newestFirst`, `ratingHigh`, `ratingLow`이며 정렬에 따라 반환 가능한 총량이 달라질 수 있습니다.
`extracted_snippet.original`과 `.translated`를 구분하고 `snippet`은 원문·번역이 섞일 수 있다고 명시합니다.
`review_id`, `iso_date`, `iso_date_of_last_edit`가 문서화되어 있습니다. 확인한 스키마에는 원문 언어 코드가 명시되지 않아 원문에서 판별해야 합니다. [API와 출력 스키마](https://serpapi.com/google-maps-reviews-api)
페이지가 항상 최대 수만큼 차거나 마지막까지 이어진다고 가정하지 않고 토큰 소멸·빈 응답·반복 토큰을 각각 기록합니다.

## 4. 현재 단가와 6,000개 수집 예시

다음은 공개 USD 단가로 계산한 사용량 예시입니다. 세금·환율·기존 사용량·추가 서비스·재시도는 별도이며 실제 견적은 아닙니다.

| 공급자·조건 | 과금 단위와 시작 조건 | 6,000개 계산 |
| --- | --- | --- |
| Apify Free | 리뷰당 $0.0006, 월 $5 무료 크레딧 | 리뷰 이벤트 사용액 $3.60 |
| Apify Starter/Bronze | $19/월 구독에 $19 크레딧 포함, 리뷰당 $0.00045 | 리뷰 사용액 $2.70이지만 최소 월 결제는 $19 |
| Outscraper | 월 첫 500리뷰 무료, 501~100,000 구간 $3/1,000리뷰 | 무료량이 남아 있으면 $16.50, 없으면 $18 |
| SerpApi Starter | $25/월, 1,000검색 포함 | 약 330검색이므로 해당 월 요금 $25 |

Apify 리뷰 단가는 공식 공개 Actor API의 최신 `pricingInfos`에서 확인했습니다. 적용 시작일은 2026-03-13, 모델은 `PAY_PER_EVENT`입니다. [공개 가격 메타데이터](https://api.apify.com/v2/acts/compass~google-maps-reviews-scraper)
같은 메타데이터의 시작 이벤트는 실행 메모리 GB당 $0.00005이며 최소 한 이벤트입니다. 1GB 실행 한 번을 가정하면 $3.60005부터라는 이벤트 계산이지만 전체 청구액 보장은 아닙니다.
Apify Free는 월 $5 크레딧, Starter는 월 $19와 같은 금액의 포함 크레딧을 제공합니다. Free 크레딧 소진 시 다음 주기까지 이용이 차단된다고 설명합니다. [요금제](https://apify.com/pricing)
이벤트 과금에 플랫폼 사용료가 포함되는지는 Actor 설정을 확인해야 하며, 실행 후 데이터셋 접근·보관에도 비용이 생길 수 있습니다. 최대 실행 과금 설정도 확인합니다. [과금 방식](https://docs.apify.com/actors/running/actors-in-store)
따라서 “6,000개를 무조건 무료” 또는 “Starter에서 $2.70만 결제”라고 안내하지 않습니다.

Outscraper는 월 구독료 없는 종량제이며 위 구간별 단가와 무료량을 가격표에서 확인했습니다. [가격표](https://outscraper.com/pricing/)
선불 충전 최소액은 $10이며 후불 카드 방식도 안내합니다. 최소 충전액과 실제 사용 비용은 다른 개념입니다. [결제 안내](https://outscraper.com/how-to-scrape-google-maps-reviews/)
선불 잔액보다 작업 사용액이 크면 작업을 완료하고 차액을 청구한다고 명시하므로 잔액을 강제 지출 상한으로 사용하지 않습니다. [FAQ](https://outscraper.com/faq/)

SerpApi의 정상적인 가득 찬 페이지를 가정하면 장소당 `1 + ceil((200 - 8) / 20) = 11검색`, 30곳은 330검색입니다.
마지막 페이지에서 200개를 넘게 반환해도 분석에는 장소당 200개만 사용하고 실제 수신량은 별도 기록합니다.
Free는 월 250검색이므로 이 예시는 무료량을 초과하며 Starter는 $25/월·1,000검색입니다. 장소 검색·재시도·다른 정렬 검증은 추가 요청입니다. [페이지 단위](https://serpapi.com/google-maps-reviews-api), [요금제](https://serpapi.com/pricing)

## 5. 약관과 권한은 수집 경로별로 확인

Maps 소비자 서비스 이용과 Maps Platform API 계약은 구분해서 검토합니다. 어느 하나의 설명을 모든 경로의 허가나 금지로 단순 확대하지 않습니다.
소비자용 Maps 추가 약관에는 콘텐츠 복제, 대량 다운로드·피드, 재배포와 Maps 기반 새 서비스 등에 대한 제한이 있습니다. 공개 화면이라는 사실만으로 대량 수집·이용 권한을 추정하지 않습니다. [Maps 소비자 약관 2](https://www.google.com/help/terms_maps/)
Platform 약관 3.2.3에는 스크래핑·저장·캐싱·파생 콘텐츠 등에 관한 제한이 있으며 실제 계약과 서비스별 예외도 함께 검토해야 합니다. [Maps Platform 약관](https://cloud.google.com/maps-platform/terms)
수집업체에 돈을 낸 사실만으로 Google이나 리뷰 작성자로부터 저장·분석·공개 권한까지 받았다고 처리하지 않습니다.
공급자의 계약에서 수집 원천, 허용 목적, 원문 보관, 언어 통계 생성, 공개 표시, 제3자 권리, 삭제 대응을 확인합니다.
이 문서는 모든 크롤링을 전 세계에서 불법이라고 판정하지 않으며, 특정 사용이 허용된다고 법률적으로 보증하지도 않습니다.

`robots.txt`는 크롤러에 대한 접근 규칙이며 접근 권한 부여 자체가 아니라는 점을 RFC가 명시합니다. 허용 경로가 곧 데이터 이용 라이선스는 아닙니다. [RFC 9309](https://www.rfc-editor.org/rfc/rfc9309.html)
실행 전 적용 경로와 규칙을 확인하고 존중합니다. 로그인·CAPTCHA·차단 화면을 회피하는 수단은 채택하지 않습니다.
검토 결과 이용 근거가 확인되지 않으면 해당 원천의 자동 수집을 활성화하지 않고, 허용된 공급자·자료나 자체 확인 근거로 기능을 검증합니다.
이는 “5개보다 많이 가져올 기술이 없다”는 결론과 다릅니다. 권한 확인 상태를 기술 검증 상태와 별도로 기록합니다.

## 7. 통과 조건과 중단 조건

다음 숫자는 공급자의 성능 보장이 아니라 첫 실험의 제안 판정 기준입니다. 실행 결과를 보고 조정합니다.

| 항목 | 통과 기준 | 실패 시 처리 |
| --- | --- | --- |
| 장소 정확성 | 대상 모든 지점이 입력과 일치 | 해당 실행 격리, 연결 규칙 수정 |
| 원문 보존 | 대조한 최소 30건에서 번역문 대체·원문 절단의 체계적 오류 없음 | 원문 분석 비활성 |
| 언어 판별 | 소량 원문 대조로 구조를 검증한 뒤 리뷰 데이터 명세의 현지어 precision·한국어 recall·언어별 평가를 별도 통과 | 판별기·임계값 수정 후 재검증 |
| 리뷰 중복 | 안정적인 ID로 제거 가능하고 최종 중복 0건 | ID 전략 검증 전 집계 금지 |
| 날짜·원천 | 정상 레코드에 수집 시각·Google 원천·해석 가능한 게시일 기록 | 불명 레코드 격리·별도 집계 |
| 수집 완결성 | 반환량·종료 사유·요청 상한 도달 여부가 모두 기록됨 | 전체 수집이라는 표시 금지 |
| 기능 가용성 | B의 10곳 중 9곳 이상에서 해석 가능한 결과 또는 명확한 부족 사유 | 재시도 남발 대신 공급자 재평가 |
| 비용 | A·B 전체 정산·예약액 $3 이내, 미확인 비용 항목 없음 | 새 작업 접수 중단 |
| 이용 조건 | 예정된 수집·보관·집계·표시 범위를 확인 | 해당 원천 활성화 보류 |

언어 엄격 필터는 [리뷰 데이터 명세](REVIEW_DATA_SPEC.md)의 기준을 따릅니다. 초기값은 분류 가능 본문 100개 이상, 본문 중 미판별 10% 이하, 추출 불명 0건이며 미판별을 포함한 보수적 비율로 판정합니다. 단순 관측 정보 표시와 엄격 필터 통과는 구분합니다.
미달 장소는 탈락한 음식점이 아니라 “언어 근거 부족”으로 표시합니다. 평점·음식·거리 추천은 독립적인 근거로 유지할 수 있습니다.
검증용 30건의 정확도는 전체 서비스 정확도 추정치가 아닙니다. 카탈루냐어·스페인어 혼동과 한국어 오분류를 별도 오류로 기록합니다.

## 8. 최신 200개를 정직하게 해석하기

**최신 200개는 관측한 최근 리뷰 집단이며 전체 방문객이나 전체 리뷰의 무작위 표본이 아닙니다.**
별점만 있는 리뷰는 원문 언어를 알 수 없으므로 텍스트 리뷰와 분리합니다. 총 평점 수를 언어 비율의 분모로 쓰지 않습니다.
일본의 지역 언어 집합은 `ja`, 바르셀로나는 최소 `es`와 `ca`를 함께 검토합니다. 지역 언어 사용과 주민 여부는 구분합니다.
한국어 리뷰 작성자가 관광객이고 스페인어 리뷰 작성자가 현지인이라고 단정하지 않습니다. `Local Guide`도 거주지 증거로 쓰지 않습니다.
정렬·조회 언어·계절·수집 기간·플랫폼 이용자 구성이 결과에 영향을 줄 가능성을 표시하고 도시 간 수치를 같은 모집단처럼 비교하지 않습니다.

표시 예시: “최근 수집 200개 중 텍스트 174개, 언어 판별 161개. 한국어 4개, 지역 언어 112개. 관측 기간 2026-05-01~09-30.”
이 수치는 설명용 가상 예시이며 실제 장소 분석 결과가 아닙니다. 판별 161개를 분모로 썼는지 텍스트 174개를 썼는지 화면에 명시합니다.
기본 집계는 `한국어 수 / 판별 가능한 단일 언어 리뷰 수`로 정의하고 혼합 언어·판별 불가·빈 텍스트 수를 나란히 보여줍니다.
“한국인 없는 맛집”, “현지인 90%” 대신 “관측한 리뷰에서 지역 언어 비중이 높음”처럼 근거에 맞는 문구를 사용합니다.
서로 다른 정렬의 리뷰를 섞어 단일 비율로 계산하지 않습니다. 관련도순 비교 실험은 최신순 결과와 별도 집단으로 보존합니다.

## 9. 갱신·유지보수와 숨은 비용

활성 여행의 후보만 주 1회 또는 방문 준비 시 갱신하는 안으로 시작하고 모든 장소를 매일 다시 수집하지 않습니다.
날짜 필터를 쓸 때 최신순과 마지막 수집일보다 7일 겹치는 범위를 사용하고 리뷰 ID로 중복을 제거합니다. 날짜 필터의 요구 조건은 공급자마다 적용합니다. [Apify 날짜 설정](https://apify.com/compass/google-maps-reviews-scraper/input-schema), [Outscraper 날짜 설정](https://docs.outscraper.com/endpoints/google-maps-reviews/)
갱신 상한에 걸리면 “해당 기간 일부만 확인”을 기록합니다. 수집을 중단한 지점 밖의 리뷰가 없다고 가정하지 않습니다.
원문 수정을 놓치거나 삭제된 리뷰가 남을 수 있으므로 허용된 보관 기간 안에서 재확인·만료·삭제 대응을 설계합니다.
중복 제거로 저장량이 줄어도 재수집된 리뷰가 무료라고 가정하지 않고 공급자의 실제 과금 이벤트를 정산합니다.
비용표에는 리뷰 이벤트 외에 결과 회수·보관·재시도·수동 검수·언어 판별·공급자 장애 대응·어댑터 수정 시간을 남깁니다.
원문 보관 기간은 임의로 영구 설정하지 않습니다. 검증에 필요한 최소 기간과 삭제 정책을 이용 조건에 맞춰 정하고 집계 보관 허용 여부도 별도로 확인합니다.

## 10. 공급자 교체가 가능한 데이터 계약

원시 응답을 화면이나 추천 점수 코드에 직접 연결하지 않고 `ReviewProvider` 어댑터를 둡니다.
공통 요청은 `place_reference`, `max_reviews`, `sort`, `published_after`, `display_language`, `source`, `budget_limit`입니다.
공통 응답은 `provider`, `provider_version`, `place_id`, `review_id`, `text_original`, `text_translated`, `language_original`, `language_confidence`, `published_at`, `updated_at`, `fetched_at`을 사용합니다.
미지원 필드는 빈 문자열이나 거짓 값으로 채우지 않고 null과 `capabilities`로 표현합니다.
수집 결과에는 `requested_count`, `received_count`, `unique_count`, `text_count`, `classified_count`, `stop_reason`, `cost_actual`을 별도로 둡니다.
정책 메타데이터에는 `policy_checked_at`, `allowed_uses`, `retention_until`, `redistribution_allowed`를 두고 원문과 집계의 허용 범위를 구분합니다.
입력·정규화·집계 테스트는 허용된 fixture와 가상 자료로 재현하고 CI에서 유료 공급자를 자동 호출하지 않습니다.
공급자를 바꿀 때 같은 장소·기간·정렬로 소량 비교하되 서로 다른 공급자의 결과를 즉시 같은 집단으로 합치지 않습니다.

이번 단계의 완료물은 **기술·가격·권한의 확인 사항과 실행 가능한 제한 실험 계획**입니다. 운영 크롤러와 실제 언어 통계는 아직 구현·검증되지 않았습니다.
