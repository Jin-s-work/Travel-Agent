# 비공개 베타 인수 테스트

작성일: 2026-10-01. [PRD](PRD.md), [기술 명세](TECHNICAL_SPEC.md), [리뷰 데이터 명세](REVIEW_DATA_SPEC.md)의 구현 완료 여부를 판단할 **예정 테스트 64개**입니다. 아래 결과는 실행·통과했다고 주장하는 기록이 아닙니다. 실제 결과는 별도 실행 보고서에 남깁니다. 기존 코드의 테스트 통과도 아래 신규 기능의 통과를 뜻하지 않습니다.

리뷰 계산에는 [합성 JSON fixtures](examples/review-language-fixtures.json)를 사용합니다. 실제 식당·사용자·리뷰·계약 승인을 나타내지 않습니다. 실제 공급자 호출, 비용 지출, 인증 계정 조작, 배포 검증은 각각 별도 실행 범위로 관리합니다.

## 실행 수준과 공통 준비

- **단위:** 결정적 계산, 파서, 상태 전이, 시간·권한 규칙. 합성 입력으로 실행합니다.
- **통합:** 임시 SQLite·Chroma·파일 저장소와 fake provider를 연결합니다. 외부 호출 횟수·저장 부작용까지 검사합니다.
- **E2E:** 서로 다른 사용자·브라우저 저장 영역, 모바일 화면·키보드·오프라인 흐름을 검사합니다.
- **복구:** 테스트 프로세스 강제 종료, lease 만료, 공급자 응답 유실, 백업 복원을 격리 환경에서 재현합니다.
- **검수:** 사람이 근거와 표현·읽기 순서를 확인합니다. 필요 시 자동 검사와 병행합니다.

공통으로 사용자 A/B, 사용자마다 다른 여행 2개, 도쿄·바르셀로나의 가상 지점, 사용자가 교정한 예약, 고정 예약이 충돌하는 여행, 정상/실패 fake provider를 준비합니다. 시간은 고정된 테스트 clock을 사용합니다. 원문·계정 식별자·예약번호는 합성값만 사용하고, 실제 데이터에 대한 삭제·복원 실험은 하지 않습니다.

`미지원/미확인`, `조건 불충족`, `입력 오류`를 다른 결과로 검증합니다. 예를 들어 언어 자료가 없는 장소는 한국어 비중 0%가 아니며, 예약 인원을 모르는 장소는 수용 불가 또는 무제한이 아닙니다. API 응답뿐 아니라 DB·벡터·파일·로그·브라우저 캐시·작업 이벤트의 부작용도 확인합니다.

## 출시 판정과 증거

첫 비공개 배포에서는 AUTH 전체, DATA 전체, OPS-01~07, 시간 충돌·고정 예약·인원·미확인 사실 검증을 차단 조건으로 삼습니다. 리뷰 기능은 REVIEW 전체와 공급자 접근·계산·저장·표시 권한 기록이 통과하기 전 기본 OFF입니다. 오프라인 기능은 UI-05~08 통과 전 비활성입니다. 해당 기능을 끄고 나머지 베타를 출시할 수 있지만 미지원 상태를 숨겨서는 안 됩니다.

근거 없는 주민 비율, 미확인 예약 자리/인원 확정, 다른 사용자 자료 노출, 고정 예약 자동 변경, 삭제 데이터 부활, 승인되지 않은 외부 호출은 한 건이라도 출시 차단입니다. UI 성능·후보 수 부족은 수치와 영향 범위를 보고 판단하며 자동으로 통과 처리하지 않습니다.

실행 보고서는 각 ID에 `not_run / passed / failed / blocked / not_applicable`과 실행일, 코드 commit, config·정책·adapter·모델 버전, fixture ID, 테스트 수준, request/job ID, 검증한 부작용, 실패 증거를 기록합니다. `not_applicable`에는 기능 OFF와 이유를 붙입니다. 실제 공급자 실험은 표본 수·정렬·수집 범위·비용·중단 사유를 별도로 남깁니다. 합성 fixture 통과를 실제 데이터 접근 권한·수집 성공률·분류 정확도의 증거로 대신하지 않습니다.

## JSON fixture 사용 계약

`schema_version=1.0`, `synthetic=true`입니다. `defaults`와 각 case의 `input_overrides`를 **객체는 재귀 병합, 배열은 교체** 방식으로 합쳐 입력을 만듭니다. fixture의 입력·상태 이름은 테스트 어댑터 계약이며 서비스의 최종 DTO를 강제하지 않습니다.

- `strict_pass`는 관측 언어 엄격 조건만 뜻합니다. 실제 운영 권한·평점·전체 평가 규모·인원·동선 검증을 대체하지 않습니다.
- `decision=unsupported`는 자료/권한/품질 부족, `fail`은 검증 가능한 언어 임계값 불충족, `invalid_input`은 수치·설정 계약 위반입니다.
- `metrics`는 허용된 합성 입력으로 계산한 값입니다. `display_mode=counts_only/reference_only`인 경우 엄격 배지 또는 전체 모집단 비율로 표시하면 안 됩니다. 권한 미확인·만료·입력 오류는 제품에 노출할 metrics가 null입니다.
- 기본 현지어와 한국어는 서로 겹치지 않습니다. `T=C+U`, `L+K≤C`, `R=rating_only_count+T+extraction_unknown_count`를 검사합니다. 미판별 상하한은 95% 신뢰구간이 아닙니다.
- 수치는 반올림하지 않고 판정하며 표시용 반올림은 이후에 수행합니다. JSON 기대값 비교는 절대 오차 `1e-12`를 허용합니다. `reason_codes_include`는 최소 포함 사유이며 배열 순서는 의미가 없습니다.

이 문서를 작성하면서 JSON 구문·불변식과 합성 기대값을 검증할 수는 있지만, 그것은 앱의 구현·테스트 실행과 별개입니다.
