## A. 시작과 재사용

적용되는 AGENTS, git 상태, `docs/service-v3/PRD.md`, `IMPLEMENTATION_STATUS.md`, `CITY_COVERAGE.md`, 1단계 결과를 읽는다. 기존 `docs/service-v2/TECHNICAL_SPEC.md`, `REVIEW_DATA_SPEC.md`, `RUNTIME_PROMPTS.md`, 일정/운영 계약을 적용한다. emil-design-eng 스킬을 읽어 실제 폼·카드·모달을 다듬는다.

기존 `src/destinations`, `src/discovery`, `src/recommendations`, `src/itineraries`, `src/reliability`, `src/travel_tools`, `src/product`를 조사한다. `src/recommendations/engine.py`의 movement는 현재 Haversine 직선거리이며 duration이 null이다. 이를 실제 도보시간으로 이름만 바꾸지 말라.

인증/owner checks/CSRF, jobs/fencing/checkpoints, budget 예약·unknown 정산, 삭제 tombstone, immutable recommendation snapshot, itinerary validator/preview/apply/undo를 재사용한다. 운영은 Render Free + Supabase이며 로컬 SQLite 전용으로만 구현하면 미완료다. 새 과금·계정·공급자 허용을 기본 전제로 삼지 않는다.

## B. 숙소 데이터와 이관

개인 `trip_accommodations` 또는 동등 모델을 만든다. 최소 계약:

- 서버생성ID, owner_id, trip_id, stop_id, version, deleted_at.
- 표시명, 입력종류(name/map_url/booking), 원입력(개인), private_note 별도.
- booking_id는 선택. 연결해도 실제 예약상태를 바꾸지 않는다.
- identity_state(unresolved/candidates/confirmed/needs_reconfirmation/unavailable), 확인지점ID/주소/lat/lon, 좌표 provenance/checked_at/precision.
- facility timezone, checkin_date/checkout_date, 정확한 시각은 있을때만. 숙박범위 `[checkin, checkout)`.
- source/version/권한/보관기간. 개인 숙소 주소·좌표·예약번호를 공용 장소 데이터나 일반 분석 이벤트에 넣지 않음.

기존 stop.base_location은 label-only로 이관한다. 이름만으로 좌표/지점/예약완료를 추측하지 않는다. 기존 origin 좌표는 사용자가 직접 넣은 것으로 provenance를 유지하고 검증된 공급자 좌표로 승격하지 않는다. 원문 메일 추출값·교정값·현재 유효값을 유지한다. 기존 숙박 예약과 연결 후보를 제안하되 여러 후보면 선택하게 한다.

DDL/마이그레이션 버전, 제약, owner索引, 외래키, tombstone/삭제, SQLite·Postgres 어댑터를 구현한다. dry-run으로 대상 수와 unresolved 수를 보고하고 원본을 덮어쓰지 않는다. 동일 반복이관은 중복숙소를 만들지 않는다. 롤백은 새컬럼/테이블의 기능OFF와 백업복구를 구분한다.

## C. 숙소 확인 UX와 API

여행 홈/탐색 출발점 요약에서 ‘숙소 추가’를 연다. 기본필드는 ‘숙소 이름 또는 지도 링크’ 하나. 예약에 숙소가 있으면 기존 후보를 먼저 보여 같은 이름을 다시 입력시키지 않는다. 날짜는 해당 stop을 제안하되 실제 checkin/checkout 확인 전까지 예약사실로 확정하지 않는다.

저장 응답과 지점 식별 job을 분리한다. 저장201이어도 unresolved일 수 있고 사용자는 다른 일을 계속한다. 모호하면 후보들의 원어명·주소·도시·외부ID·공식/지도링크를 대조하고 직접선택한다. 자동첫결과 선택 금지. 식별실패는 숙소저장실패와 다르다.

권장 API, 기존 경로와 일관되게 조정 가능:

- GET/POST `/trips/{id}/accommodations`
- PATCH/DELETE `/trips/{id}/accommodations/{aid}` (expected_version)
- POST `.../{aid}/resolve` (Idempotency-Key, capped input)
- POST `.../{aid}/select` (candidate_id, expected_version, 서버 candidate list 검증)
- GET `/trips/{id}/origin-context?visit_date=YYYY-MM-DD&stop_id=...`

서버가 가진 후보ID만 선택 가능하고 다른 사용자/여행의 숙소/booking/stop참조는404다. owner_id를 client에서 받지 않는다. 임의 URLfetch는 기존 safe_fetch로 내부망/DNS/redirect/timeout/응답크기/MIME를 막는다. 사용자 메일 속 링크 자동fetch를 새로 도입하지 않는다.

## D. 그날의 기준점 결정

순수 함수 `resolve_origin(trip, stays, visit, overrides, clock)`을 만든다. 같은 입력은 같은 결과를 반환하고 결정 이유, 출처, unknown/conflict를 함께 반환한다.

1. 사용자가 명시적으로 선택한 방문용 출발점이 유효하면 우선한다.
2. 해당 도시 구간과 날짜에 확인된 숙소가 한 개면 제안한다. 출발점 선택과 숙박 예약 확정은 다른 상태다.
3. 체크아웃 당일에는 전날 숙소를 ‘체크아웃 전 출발점 후보’로 제안할 수 있다. 그날 종일 투숙 중이라고 단정하지 않는다.
4. 오전 체크아웃/오후 체크인으로 숙소가 두 개라면 방문 시각과 사용자 선택을 함께 본다. 날짜가 겹치면 모호, 공백이면 미확인이다.
5. 숙소 이름만 있고 좌표가 없으면 위치 미확인이다. 도시 중심/0,0/가장 유명한 호텔로 대체하지 않는다.
6. 숙소·날짜·도시·좌표 version이 바뀌면 관련 추천과 경로가 오래된 값임을 표시한다. 과거 snapshot은 보존하되 최신처럼 표시하지 않는다.

짐 보관, 조기 입실, 공항에서 호텔까지 도착한 시각은 확인된 별도 사실이 없는 한 미확인이다. 위치 권한 거절은 전체 탐색을 막지 않는다. 실시간 위치는 사용자의 명시 행동에서만 요청하고 기본 수집하지 않는다.

입력 모델의 null은 실제 미확인을 뜻한다. 화면에 ‘숙소 미입력’과 ‘숙소는 저장됐지만 위치 미확인’을 구분해 다음 행동을 다르게 보여라. 여행 날짜를 바꾸면 숙소 원본을 몰래 이동시키지 말고 현재 여행 밖의 숙박이라는 안내를 제공한다.

## E. 지도·경로 제공자와 비용 경계

`GeocodingProvider.resolve(query, city, limits)`와 `RouteProvider.matrix(origins, destinations, mode, departure, limits)` 인터페이스를 정의한다. fake와 disabled는 필수이며, 실제 어댑터 하나는 현행 공식 문서를 확인해 준비한다. credentials가 없으면 OFF로 표시하고 fake를 운영 fallback으로 쓰지 않는다.

정규화 응답에는 provider/version, 출발·도착 identity와 version, mode, checked_at, expires_at, 구간별 상태, distance_m, duration_seconds, 근거와 표시 허용 범위를 보존한다. 숫자는 음수와 NaN/Infinity를 거절한다. 같은 지점임이 서버에서 확인된 경우만 0을 허용한다. 실패·구간 없음·미지원은 null이다.

Google Routes 등을 쓰면 각 출발×도착 element 오류를 따로 처리한다. 요청 전체200과 모든 구간 성공은 다르다. 후보 전체를 매번 matrix에 보내지 않는다. 도시·지점·필수 조건으로 후보를 먼저 줄이고 설정된 N개만 조회한다. 후보 수, element 수, 시도 횟수, deadline, 비용 예약을 job에 남긴다. 현재 상한/단가를 공식 자료로 확인하고 영구 상수 대신 설정으로 관리한다.

모든 외부 호출을 기존 비용 wrapper로 통과시킨다. ZERO_SPEND 또는 예산0이면 실제 호출 수는0이어야 한다. SDK 내부 재시도와 응답 유실로 인한 과금 unknown도 포함한다. 문서 조회·카드 열기·필터 타이핑이 새 유료 job을 만들지 않는다. 이미 성공한 checkpoint는 재사용하고 서버 재시작 후 무조건 재호출하지 않는다.

캐시 키에는 방향, 이동 수단, 출발 시각 bucket, 출발/도착 ID와 version, provider/version, 접근성 제약을 포함한다. 데이터 계약이 허용한 범위와 TTL에서만 재사용한다. 과거 경로를 실시간 교통으로 표현하지 않는다. provider 장애가 저장된 여행·예약 조회로 번지지 않게 한다. 공개 장소 경로와 개인 숙소 위치를 같은 공개 cache namespace에 넣지 않는다.

공용 Nominatim 자동완성은 만들지 말라. 현재 정책의 식별·출처 표기·앱 전체 최대1요청/초·개인정보 전송·자동완성 제한을 읽는다. 담당자가 용도를 검토해 명시적으로 공급자를 선택한 경우에만 고려한다. 기본 무료 기능을 공용 서비스의 무제한 사용에 의존시키지 않는다. 숙소 주소를 검색 공급자에 전달하는 목적과 범위가 사용자에게 보여야 한다.

## F. 정직한 거리와 필터

직선거리 계산은 순수 함수이며 좌표 범위와 위경도 쌍을 검증한다. 단순 estimate 외에 구체적인 `haversine_straight_line` method를 남겨 실제 경로와 구분한다. 반올림은 표시할 때만 하며 필터 임계값은 원값으로 계산한다. 위도/경도0은 유효한 값일 수 있으므로 falsy 검사로 버리지 않는다.

- ‘직선거리1km 이내’: 유효 좌표의 직선거리로 판단한다.
- ‘도보15분 이내’: 유효한 walking route로만 판단한다.
- ‘가까운 곳 우선’: 선호다. 거리 unknown을 0분이나 최고점으로 채우지 않는다.
- ‘다음 예약 가는 길’: 출발점→후보→다음 확정 예약의 두 구간을 검증한다. 직선거리 합을 실제 도보시간으로 대신하지 않는다.

반경·예산·필수 조건을 자동으로 완화하지 않는다. 거리 필수 조건에서 unknown 후보는 엄격 결과에서 제외하고 제외 이유를 집계한다. 사용자가 잠정 초안을 허용한 경우에만 일정에서 provisional로 둘 수 있다. 확인된 휴무·폐업·인원 위반은 잠정 모드에서도 배치 금지다.

도보 경로 실패 시에는 ‘도보시간 미확인 · 직선거리850m’처럼 두 상태를 동시에 설명한다. 실패한 route를 0으로 치환하지 말고, 유효한 직선거리를 경로 실패 때문에 삭제하지도 말라. 접근성 필요 조건에 맞는 경로인지 알 수 없으면 그것도 미확인이다.

## G. 추천 모델과 재현성

기존 local_editorial_v1, iconic_v1, local_observed_v1 모델과 초기 가중치를 확인한다. 거리 성분의 계산을 변경하면 새 버전을 만든다. 조건·후보·사실·정책·clock·숙소 version·route 참조를 run snapshot에 저장한다. 필요한 성분이 null이면 자료 부족이며 남은 가중치로 몰래 재분배하지 않는다.

모델 비교 명령은 동일 snapshot을 두 버전에 입력해 순위 이동, 성분 점수, 다양성, 필수 조건 위반을 출력해야 한다. 새 검색 시점의 자료 변화와 알고리즘 변화를 섞지 않는다. 새 모델의 실제 사용 성과가 없으면 평가 양식과 재실행 명령만 제공한다.

현지 탐색은 현지 주민의 비율 주장이 아니다. strict 리뷰는 기존 이용 범위·언어 품질·관측 기간 gate를 유지한다. 도시100개가 생겼다는 이유로 현지어 집합을 모두 자동 활성화하지 않는다. 한국 도시에서 한국어 리뷰가 많다는 것을 같은 방식의 관광객 지표로 해석하지 않는다. 평점과 전체 평가 수, 언어 관측 분모를 따로 보여준다.

LLM은 서버가 결정한 후보·순위·근거를 설명한다. 새 장소·잔여석·시간·추천 순위를 만들면 검증기가 거절하고 템플릿으로 복구한다. 설명 생성 실패 때문에 결정적 추천 결과까지 지우지 않는다.

빠른 행동은 ‘숙소 근처 저녁’ 하나부터 완성한다. 현재 숙소·날짜·저녁 선호를 눈에 보이는 draft에 채우고 기존 필수 조건·예산·리뷰 필터를 몰래 바꾸지 않는다. 더 많은 조건을 선택해야만 사용 가능하게 만들지 말라. 숙소가 없으면 위치 확인 요청과 일반 탐색을 함께 제공한다.

## H. 카드·상세·비교

카드는 ‘숙소에서 직선거리850m · 도보시간 미확인’처럼 표시한다. 실제 경로가 있으면 ‘숙소에서 도보 약12분 · 확인일’로 표시한다. 기준점이 숙소가 아니라면 그 지점 이름을 보여준다. 숙소 이름만 있을 때 ‘가까움’ 배지를 만들지 않는다.

추천 이유2~3개, 중요한 미확인, 가격 통화/인당·그룹/식사·하루 기준, 출처 확인일을 표시한다. 총좌석, 예약 링크, 통상 영업표를 방문일의 실제 잔여석으로 읽지 않는다. 지도 링크는 확인된 지점으로 연결하고 링크 열기를 예약 완료 이벤트로 기록하지 않는다.

비교는 서로 다른 최대3곳이며 같은 방문일·인원·기준점·이동 수단에서 비교한다. 오래된 경로와 새 경로를 동등하게 표시하지 않는다. 예상 비용은 통화별로 분리한다. null은 미확인이고0은 무료다. 패키지 포함 항목·선결제·환급 예치금의 기존 계산 계약을 재사용한다.

320/390px, 긴 다국어 이름, 큰 글자에서도 핵심 행동과 미확인이 잘리지 않아야 한다. 저장·상세·일정 추가가 주 행동이고 비교·피드백은 보조 행동이다. 명확한 사용자 동작에 짧은 피드백을 주되 키보드 반복 입력과 스크롤에 장식 모션을 넣지 않는다. 버튼 로딩/실패가 레이아웃을 크게 흔들지 않게 한다.

접근성은 화면이 예쁜지와 별도로 확인한다. modal focus trap·Escape·닫힌 뒤 원래 버튼으로 포커스 복귀, aria live 알림, 색에 의존하지 않는 상태 표시, reduced motion을 점검한다. 필터를 수정하는 동안 이전 결과가 유지되고 이전 조건임이 보이게 한다.

## I. 일정 삽입과 편집

추천/보관함에서 고른 장소를 기존 command 계약에 연결한다. 새 삽입 기능을 별도 일정 엔진으로 만들지 않는다. item의 안정적 ID, 현지 시각/IANA/UTC, 체류시간과 출처, route leg의 근거·확인 시각, lock_origin을 유지한다.

preview는 변경 전후, 영향 구간, 이전/다음 이동, 충돌·미확인, 통화별 가격 차이를 반환한다. 원 일정·예약·외부 예약은 바뀌지 않는다. apply 직전에는 소유권·tombstone·version·고정 예약·잠금·영업/경로 신선도를 다시 검사한다. 실패409는 원본 보존, 성공은 새 revision/version의 원자 저장이다. undo는 최소10개 편집에 대해 현재 제약으로 재검증한 새 revision이다.

필수 산술 시험: 식사가13시에 끝나고 다음 확정 예약이15시이면 이동30+체류90+이동30=150분 후보는120분 창에 배치 불가다. 식사를12:30에 마치면150분으로 정확히 가능하고, 추가 버퍼10분이 생기면 다시 불가다. 양끝 이동을 모두 검사해야 하며 경로 없음=0 처리는 시험 실패다.

고정 예약을 자동 이동/삭제하지 않는다. 숙박 전체 기간을 종일 busy로 막지 않는다. 공항 이동·체크인·출국 준비 버퍼는 일반 도보시간과 별개다. 자정 넘는 영업·휴무 예외·브레이크·마지막 주문/입장과 방문 전체 체류를 검사한다. 일정에서 제거하는 것은 외부 예약 취소가 아니라는 안내를 유지한다.

시간 입력·위아래 이동·키보드 경로를 제공하고 드래그만 강요하지 않는다. 자연어 편집도 같은 command 검증을 통과한다. 입력을 편하게 했다는 이유로 고정 예약의 보호를 해제하지 말라.

## J. 시험팩·관측·운영 검증

순수 geometry/model 시험과 실제 공급자 품질 시험을 분리한다. 합성 fixture 표시를 보존하고 다음 상황을 포함한다.

1. 사용자A/B 각각2여행, 두 숙소, 동명 호텔의 다른 지점, 미확인 주소, 0도 경도 같은 유효 좌표와 범위 밖 좌표.
2. 체크아웃 당일, 숙소 겹침/공백, 숙박 수정/삭제, 동시 지점 선택과 버전 충돌.
3. 도쿄·마드리드·뉴욕·시드니, 100개 도시 계약, DST 없는/중복 시각, 국제 항공 출발·도착 시간대.
4. 강 건너 직선500m/실제 도보25분, 반대 방향에서 다른 시간, 경로 실패·오래된 캐시·이동 수단 불일치.
5. 이동시간 unknown, 직선거리만 있는 후보, 도보 필수 조건, 사용자 명시 완화 선택.
6. 후보 자료0, 엄격 조건 통과2개, 언어 미지원, 이전 결과 유지와 늦은 응답 무시.
7. matrix 상한, 마지막 예산 동시 요청, unknown 과금, 취소, 프로세스 재시작/checkpoint, 삭제 후 완료 경쟁.
8. preview/apply409/undo/새로고침과 위의120/150/160분 산술 시험.
9. 메일 체험팩 숙소는 가짜이므로 실제 호텔 검색 결과에 자동 연결되지 않음. AI 미설정이면 실제 추출 정확도는 미검증.

실제 브라우저에서 여행 선택→숙소 저장→지점 후보 선택→숙소 근처 저녁→상세→비교→일정 preview→apply→새로고침→undo를 확인한다. 키가 없으면 합성 로컬 환경으로 전체 흐름을 검증하고 운영에서는 직선거리/unknown 처리를 확인한다. 실제 지도 조회 없이 도보시간 라이브 검증 완료라고 보고하지 않는다.

실행한 명령, 테스트 결과, 스크린샷, 실제 측정한 호출 수와 비용 예약, 브라우저 종류, 실기기 미검증, 도시별 실제 후보 수와 OFF 기능을 기록한다. 기본 회귀 그룹은 다음과 같다. 새 tests 파일은 실제 구현 이름으로 보고서에 남긴다.

```
PYTHON_DOTENV_DISABLED=1 .venv/bin/python -m pytest tests/test_destinations.py tests/test_discovery_foundation.py tests/test_recommendation_engine.py tests/test_recommendation_api.py -q
node --test tests/*.cjs
python3 scripts/version_web_assets.py --check
```

일정·비용·삭제·복원에 영향이 있으면 해당 기존 시험도 실행한다. 수정과 상관없는 테스트를 반복해 실제 브라우저 검증을 대체하지 말라. 수동 시험은 확인한 행동과 결과를 적고 ‘문제없음’ 한 줄로 끝내지 않는다.

`docs/service-v3/IMPLEMENTATION_STATUS.md`를 갱신한다. DB 복원/migration에 영향이 있으면 운영 문서와 복구 절차도 바꾼다. 일반 설정은 기본값으로 관리하고 비밀만 호스팅 secret에 넣는다. 새 환경변수를 무더기로 사용자에게 묻지 말라.

최종 보고는 구현, 합성 검증, 실제 공급자 검증, 배포를 구분한다. 다음 개선은 관측 근거·사용자 가치·비용·데이터 의존성을 비교해 하나만 제안한다. 실사용 수치를 만들거나 수 주를 기다리는 작업을 이번 완료 조건으로 삼지 말라.
