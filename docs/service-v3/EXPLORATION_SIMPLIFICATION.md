## 추천·입력의 보존 규칙

- ‘둘러보기’는 저장된 실행의 장소를 중복 없이 모은 보기다. ‘현지어 리뷰로 찾기’와 ‘유명한 곳’의 자격·순위·근거는 바꾸지 않는다. 이전 버전 결과도 볼 수 있다.
- 저장된 결과가 있으면 화면 진입/새로고침만으로 추천을 다시 실행하지 않는다. 오류·연결 끊김·예산 소진은 자동 재시도하지 않는다.
- 날짜·분류를 바꾸면 이전 결과라는 표시를 유지한다. 여행 변경 후 늦게 도착한 응답은 사용하지 않는다.
- 휴무·인원 불일치·필수 조건 위반을 숨기거나 자동 완화하지 않는다. 공통 미확인 안내를 줄여도 사실 상세와 언어 분모·출처는 유지한다.
- 간편 예산 입력은 기존 통화·인당/일행·식사/하루 기준과 최소 금액을 유지한다. 상한 0은 무료 조건이며 빈칸은 상한 없음이다.

## 사진 경로와 제한

`trip_places 소유권 → 정확한 OSM feature → 명시적 Commons File 링크 또는 근접 지점 Wikidata P18 → Commons imageinfo → 라이선스·주소 검증 → SQL cache → 기존 gallery`

- 사진 없는 곳에 다른 식당·생성 사진을 넣지 않는다. 음식/내부/외관 유형을 파일명으로 추측하지 않는다.
- Wikidata는 체인 공통 ID를 제외하고 지점 좌표 100m 이내일 때만 사용한다. `brand:wikidata`, 임의 URL, Wikimedia category는 따라가지 않는다.
- Commons의 현재 `utm_source / utm_campaign / utm_content`만 제거하고 기존 HTTPS·호스트·파일 확장자 검사를 통과시킨다. 서명 토큰이나 임의 query는 허용하지 않는다.
- 최대 3장, 첫 장만 lazy load. 저자·원출처·라이선스 표시. 확인일을 촬영일로 바꾸지 않는다.
- `place_photos`는 기존 개인 여행 job/lease/fencing/cancel을 사용한다. 삭제·권한·지점 변경을 결과 저장 직전에 다시 확인한다.
- 요청당 최대 6곳, 요청당 HTTP 4초/384KB/redirect 0, 전역 일 120회·사용자 일 60회. SQL에서 호출 전에 원자적으로 확인하고 0원 호출 원장에 기록한다. 403/429 후 15분 쉰다.
- 성공 또는 명시적 사진 없음은 7일, 일시 실패는 15분 보관한다. 활성 장소·출처 사용권은 읽을 때 다시 검사한다. 이미지 파일·리뷰·숙소 주소·메일은 저장하지 않는다.
- `POST /api/v2/trips/{trip_id}/place-photos`. 같은 명시적 Idempotency-Key/다른 입력은 409. 자동 호출은 15분 단위로 합친다. 캐시 GET은 네트워크 호출을 하지 않는다.
- 운영 제어에서 공급자 `public_place_photos`를 중단할 수 있다. 무료 공개지도 기능이 꺼져 있으면 사진 수집도 꺼진다. 새로운 유료 API·계정·호스팅 요금제를 추가하지 않았다.

공식 계약: [OSM API 0.6](https://wiki.openstreetmap.org/wiki/API_v0.6), [MediaWiki imageinfo](https://www.mediawiki.org/wiki/API:Imageinfo). Commons 원출처의 표시 가능한 라이선스를 개별 확인하며 OSM 자료 사용권이 사진 권리를 대신하지 않는다.

## 실제 자료 확인

파리 도심의 공개 식당 6곳을 확인했다. 5곳은 연결된 사진 파일이 없었고, Au Vieux Paris d’Arcole 1곳은 지점 Wikidata에 연결된 CC BY-SA 2.0 사진 1장을 확인했다. 새 imageinfo URL의 추적 매개변수 때문에 첫 시도에서 거절되던 사진을 수정 후 검증했다. 이 6곳 표본을 전체 도시의 사진 확보율로 해석하지 않는다. 무료 자료만으로 모든 식당에 사진 1~3장을 보장할 수 없다. 없는 곳은 작은 안내와 ‘지도에서 사진 보기’를 제공한다.

## 배포·복구

새 schema15는 공개 사진 metadata 테이블 하나를 추가한다. 개인 예약·일정·여행 행을 수정하는 이관은 없다. SQLite/PostgreSQL 두 경로와 schema11/12/13/14 → 15를 격리 시험한다. 이전 이미지로 바로 rollback하면 구형 앱이 schema15를 거절하므로, UI 문제는 schema15를 이해하는 이 버전 기반의 수정 배포로 복구한다. 사진 공급자만 문제면 운영 제어로 새 사진 호출을 중단한다. 임의로 운영 DB 버전을 낮추거나 개인 자료를 복원하지 않는다.

후속 검증: 이전 schema13 전 추천에는 `trip_places` 연결이 없어 사진 요청이 거절되는 호환성 문제를 수정했다. 해당 사용자의 해당 여행에 저장한 후보 snapshot의 **정확한 장소 ID**로만 기존 연결을 인정한다. 다른 여행의 ID는 계속 404다. 사진 표적 시험은 SQLite/PostgreSQL 각각 **16 passed**. 운영 Chrome에서 새 필터·이전 추천 12곳·상세 읽기를 확인했다.
