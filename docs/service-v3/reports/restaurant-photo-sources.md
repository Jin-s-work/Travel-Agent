## 검수와 동작

- Commons 공식 imageinfo의 라이선스·저작자·파일 설명과 장소 카테고리, 기존 공식 지점 주소를 대조했다. Chrome/macOS에서 13개 실제 이미지를 화면으로 확인했다. 파일명이 비슷하다는 이유만으로 다른 지점 사진을 연결하지 않았다.
- 니혼바시 타마이 본점과 바 라 플라타는 이번 조사에서 지점과 재사용권을 함께 확인한 사진을 확보하지 못했다. 사진 없음 상태와 기존 공식 사이트 링크를 제공한다.
- 원본을 서버에 다운로드하거나 유료 Places Photos를 호출하지 않는다. 브라우저가 Commons 썸네일을 필요한 때 직접 표시한다. 첫 장은 lazy loading, 두 번째는 조작 시 요청한다. 한 장 실패 시 다른 장을 유지하고 모두 실패하면 출처 링크로 안내한다.
- API 메타데이터의 URL은 추적 쿼리를 제거하고 정확한 Commons 이미지 호스트/경로만 허용했다. HTTPX 헤더 확인은 403이었으며 성공으로 기록하지 않는다. 실제 Chrome의 독립 로컬 갤러리와 앱에서 같은 썸네일 표시를 확인했다.
- 화면에서 저작자·사진 출처·라이선스·알려진 촬영일·화면 맞춤 잘림을 표시한다. 촬영일을 확인일로 대체하지 않는다. 대부분 오래된 사진이므로 최신 모습으로 소개하지 않는다.
- 만료·비활성 사진, 지점 불일치, 장소/출처/팩 삭제·철회를 현재 읽기에서 검사한다. 영업 사실의 유효기간과 사진 라이선스 검토의 유효기간은 다르다. 메타데이터 검수 갱신 예정은 1년이며 그 전에 확인된 철회는 즉시 manifest enabled=false로 반영한다.
- 사진은 현재 응답에만 추가된다. 저장된 추천 점수·후보 snapshot·원문 Chroma·오프라인 bundle에는 넣지 않는다. service worker도 외부 사진을 캐시하지 않는다. 기기의 일반 HTTP 캐시는 외부 CDN 정책에 따른다.
- 단일 정본: [restaurant_photos.json](../../../src/discovery/restaurant_photos.json). src/ 배포 경로 안에 포함되어 .dockerignore의 개인 자료 제외 규칙을 바꾸지 않는다.

## 운영

새 사진은 지점 일치·원출처·허용 라이선스·저작자·촬영일·시각 확인 후 명시적으로 추가한다. 다른 식당/일반 음식 사진이나 AI 생성 이미지를 해당 지점의 실제 사진으로 대체하지 않는다. 현재 방식은 검수한 카탈로그 사진이며 실시간 전 세계 식당 사진 검색의 구현을 뜻하지 않는다.
