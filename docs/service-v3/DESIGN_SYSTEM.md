# 여정 · 여행을 모으는 화면

개정일: 2026-10-07 · 디자인 버전: `yeojeong-petrol-v2`

‘여정’은 여행의 흐름을 뜻하는 한 단어다. 이름·브라우저 제목·앱 설치 이름·화면의 표식을 같은 이름으로 맞춘다. 사용자가 제공한 `DESIGN.md`는 사진과 글자의 위계, 분명한 선택 상태, 단순한 탐색을 참고했다. Airbnb의 빨강·전용 서체·로고를 복제하지 않는다. 이전 코랄 시스템의 대비·오류 처리·접근성 계약은 보존하면서 여행 사진과 실제 정보가 더 먼저 읽히도록 바꿨다.

## 1. 인상보다 사용 순서

- 여행 선택 → 방문 날짜·출발점 확인 → 장소 찾기 → 사진·이유 확인 → 저장·일정에 넣기의 순서를 따른다.
- 큰 홍보 문구, 비어 있는 패널, 제목 위에 반복되는 설명, 모든 항목을 둘러싼 배지를 줄인다.
- 사진은 해당 지점의 실제 자료만 쓴다. 사진이 없는 장소를 일반 음식 이미지·AI 이미지로 대신하지 않는다.
- 장소의 외관·음식·실내 등 구분을 사진에 표시한다. 최대 3장까지 사용할 수 있으며 실제 확보·허용된 수만 표시한다.
- 가격·이동·중요한 미확인은 카드에서 읽게 하고, 촬영자·라이선스·상세 근거는 명확한 펼침으로 제공한다. 확인할 사실을 단순히 숨겨서 짧게 만들지 않는다.
- 실제 작업 단계·처리 수·자료 부족·실패·이전 조건의 결과를 구분한다. 새 색이나 사진이 추천 검증 기준을 바꾸지 않는다.

## 2. 실제 서체: Pretendard Variable

[공식 Pretendard 저장소](https://github.com/orioncactus/pretendard)의 [v1.3.9 배포](https://github.com/orioncactus/pretendard/releases/tag/v1.3.9)와 [공식 라이선스](https://github.com/orioncactus/pretendard/blob/v1.3.9/LICENSE)를 확인했다. 익숙한 한국어 UI의 글자 형태와 숫자 가독성을 위해 SUIT에서 교체했다. 원본 폰트와 라이선스를 수정 없이 자체 호스팅한다.

- 파일: `web/fonts/PretendardVariable-v1.3.9.woff2`
- 크기: **2,057,688 bytes** (약 1.96 MiB)
- SHA-256: `9599f12fd42fc0bce1cd50b47a0c022e108d7aa64dd0d1bb0ed44f3282d900b4`
- 라이선스 전문: `web/fonts/Pretendard-OFL.txt`; 출처·버전·해시: `web/fonts/README.md`
- 지원 weight: 100–900; 화면은 **400 / 500 / 600**을 사용한다.
- 본문·입력 16px / 일반 표제 28px / 장소명 18px / 필드 이름·행동 14px / 부가 설명 13px를 기본으로 한다. 제목은 600, 버튼과 필드 이름은 500, 본문은 400이다.
- 과도한 음수 자간을 줄이고 본문 `-.012em`, 제목 `-.025em`, 장소명 `-.015em`로 통일한다. 가는 큰 제목과 두꺼운 작은 문장을 반복하지 않는다.
- `font-display: swap`으로 내용을 먼저 표시한다. 같은 출처의 파일 하나를 `preload`하고 공개 자산 캐시를 사용한다. 외부 CDN 요청을 추가하지 않는다.
- 전체 가변 폰트를 보존하므로 첫 다운로드가 SUIT보다 약 1.37 MiB 커진다. 읽을 수 있는 상태는 시스템 폴백으로 먼저 제공하며, 모든 세션에서 반복 다운로드한다고 가정하지 않는다.
- 내부 서체 이름·글리프·메타데이터는 바꾸지 않았다. 기존 SUIT 파일은 구버전 캐시 호환용으로 보존한다.
- 포함되지 않은 원어 글자는 OS 서체로 폴백한다.

폰트 파일 존재와 실제 브라우저 적용은 별개의 검증이다. 통합 검증에서 `document.fonts` 로드 상태와 계산된 `font-family`, 네트워크 응답을 확인한다.

## 4. 글자·레이아웃

- 기본 본문 16px/400, 라벨 15px/500, 설명 13px/400, 장소 이름 19px/600, 구획 제목 20px/600, 페이지 제목 28px/500을 기준으로 한다.
- 한국어와 긴 원어명은 줄바꿈을 허용한다. 핵심 내용에 줄 수 제한·잘라내기·작은 글자로 강제 축소를 사용하지 않는다.
- 기본 간격은 4/8/12/16/20/24/32/40/64px다. 입력과 결과 사이에는 충분한 간격을 두되 카드 안에서 문단마다 큰 여백과 가로선을 반복하지 않는다.
- 데스크톱 사이드바는 196px다. **960px 화면에서도 추천 2열**을 유지한다. 720px 이하에서 1열, 매우 넓은 1600px 이상에서 3열이다. 큰 글자 설정에서는 폭과 관계없이 1열이다.
- 장소 사진은 3:2, 상세는 16:10 비율로 먼저 공간을 잡는다. 모바일에서 사진 한 장 때문에 다음 행동이 지나치게 멀어지지 않게 한다.
- 카드 외곽은 없애고 사진 12px 반경과 간격으로 묶는다. 입력 8px·정보 패널 14px·모달 24px 반경을 사용한다.
- 주요 행동 48px, 사진 화살표·카드 버튼·펼침 조작은 최소 44px다. 캡션 문장 안의 출처 링크는 inline 링크다.
- 날짜와 분류는 채운 선택 형태 및 `aria-pressed`, 상단 탐색 탭은 밑줄을 함께 사용한다. 색만으로 선택 여부를 구분하지 않는다.

## 5. 사진 컴포넌트

`figure.place-photo-gallery`는 최대 3장의 승인된 지점 사진을 사용한다. `.place-photo-type`은 실제 메타데이터의 사진 유형을 보여 준다. 유형을 모르면 임의로 음식·실내라고 분류하지 않는다. `.place-photo-caption`은 현재 사진을 짧게 설명한다.

사진 정보는 `details.place-photo-credit-details` → `summary` → `.place-photo-credit-body`로 묶는다. ‘사진 정보’를 열면 현재 사진의 촬영자·촬영일·출처·라이선스·과거 사진 안내를 읽을 수 있다. 현재 사진이 바뀌면 연결된 정보도 바뀌어야 한다.

- 이전·다음 버튼과 방향키를 제공한다. 모바일 가로 스와이프를 지원하더라도 화살표를 없애지 않는다.
- `.place-photo-frame`은 `touch-action: pan-y`로 세로 스크롤을 유지한다. 넘김에 자동 재생이나 장식 모션을 넣지 않는다.
- 사진 영역을 먼저 확보하고 `loading=lazy`, `decoding=async`, 크기 속성·alt를 사용한다. 사용하지 않은 다음 사진을 무조건 먼저 받지 않는다.
- 사진 실패는 다른 유효 사진 또는 출처 확인 안내로 복구한다. 승인 사진 없음은 작은 텍스트 안내다.
- 원문 지점·작가·라이선스·검토 기한을 확인한 사진만 사용한다. 사진이 실제 영업·특정일 잔여석·추천 자격을 보장하지 않는다.
- 원문 응답·사진을 개인 Chroma나 오프라인 bundle에 자동으로 넣지 않는다. 오프라인 표시 권한은 별도다.

## 6. 모션과 접근성

`emil-design-eng` 원칙을 적용한다. 반복 사용하는 탭·필터·사진 전환·키보드 탐색은 즉시 반응한다. 포인터 누름의 `scale(.97)`과 140ms, 실제 작업 중 점의 opacity 활동 표시만 유지한다. `transition: all`, 여백·크기 애니메이션, 가짜 진행률을 추가하지 않는다.

hover는 hover 가능한 포인터로 제한한다. `prefers-reduced-motion`에서는 움직임을 제거한다. 시스템/명시적 다크 모드·200% 글자·forced-colors와 기존 dialog의 Escape·초점 가두기·복귀를 유지한다. 사진 위 화살표는 테마와 무관한 흰 배경·짙은 글자로 두고 초점 윤곽을 보이게 한다.

## 8. 조건을 바꾸는 방식

조건 편집은 펼침 목록 여러 개 대신 **현재 조건 요약 + 필터 버튼** 한 곳으로 모은다. 반복되는 ‘필터’, ‘필터 더 보기’, ‘여행 조건’ 진입로를 줄이고 편집 창에서 목적이 적힌 탭으로 구분한다.

- 방문·인원 / 취향·예산 / 이동·필수 / 리뷰 기준의 탭 이름을 항상 표시한다. 600px 이하에서는 2열, 큰 글자에서는 1열이다.
- 선택 항목은 네이티브 라디오·체크박스와 제목·설명이 있는 행으로 제공한다. 눌러야만 의미가 드러나는 토글이나 pill 모양을 기본으로 하지 않는다.
- 바깥 화면의 날짜·장소 유형은 즉시 선택하는 기능이므로 유지한다. 선택된 상태는 색·윤곽·접근성 속성으로 함께 표현한다.
- 편집 중인 값은 적용 전의 결과를 덮어쓰지 않는다. 취소는 원래 조건을 유지하고 적용은 한 번의 명확한 행동으로 실행한다.
- 오류가 있는 탭은 자동으로 열고 해당 필드로 이동한다. 키보드 방향키·Escape·초점 복귀는 기존 dialog 계약을 따른다.
- 결과 건수는 반복 배지 대신 구분된 텍스트로 표시하고, 필터는 작은 모서리의 윤곽선 버튼으로 표현한다.

| Before | After | Why |
| --- | --- | --- |
| ‘필터 더 보기’ 펼침 안에 또 다른 조건 진입로 | 현재 조건 한 줄과 이름 있는 탭을 갖춘 ‘필터’ 편집 창 | 어디서 값을 바꿔야 하는지 한눈에 파악 |
| 엄격 리뷰 ON/OFF | ‘검증된 리뷰 언어만’ / ‘언어 제한 없이’ 라디오 행 | 선택 결과와 자료의 한계를 누르기 전에 이해 |
| 여러 둥근 chip·건수 badge가 연속됨 | 날짜와 유형만 선택 버튼, 건수는 텍스트 | 선택할 수 있는 것과 단순 정보를 구분 |
| 작은 12–13px 필드 이름과 큰 본문 | 필드 이름 14px·입력 16px | 입력 화면에서 읽는 피로를 낮춤 |
| 제목마다 다른 음수 자간과 500/600/650 굵기 | Pretendard 400/500/600, 절제한 자간 | 임의로 조합한 듯한 느낌을 줄이고 일관성 확보 |

메일 화면은 `메일로 예약 추가 → 분석 결과 → 예약 모아보기 → 저장된 메일` 순서다. 현재 분석 방식은 파일 선택 전에 짧게 알려 주고, 업로드 상자에 겹친 패널 테두리와 장식 아이콘을 제거한다. 테스트 메일 링크를 제목 옆에 두고 모바일 분석 버튼을 전체 폭으로 제공한다. 예약 날짜·종류·확인 필요 필터는 펼치지 않아도 보이며 390px에서 날짜·종류 2열, 큰 글자에서는 1열로 배치한다.

| Before | After | Why |
| --- | --- | --- |
| 업로드 패널 안에 다시 큰 상자와 장식 아이콘 | 제목·분석 방식·파일 선택 영역 한 묶음 | 메일 추가라는 한 가지 행동을 바로 인식 |
| 예약 필터를 먼저 펼쳐야 날짜·종류 선택 가능 | 날짜·종류·확인 필요를 바로 보여 줌 | 자주 하는 조회에 불필요한 단계 제거 |

## 9. 검증 경계

정적 파일·대비·폰트 원본 크기·해시·라이선스를 확인했다. 실제 Chrome의 폰트 로드, 960px 2열, 모바일·다크·큰 글자·사진 넘김·실패 복구 결과는 통합 검증 보고서에 기록한다. 코드 변경을 실제 브라우저 검증이나 모든 기기 지원 완료로 대신 보고하지 않는다.

이 개편은 사용자 여행·예약·소유권·리뷰 품질 조건·지출 상한을 바꾸지 않는다. 새 이름과 디자인은 유료 공급자를 자동으로 켜지 않는다. 장소별 실제 사진 수와 미지원 유형은 데이터 보고서를 따른다.
