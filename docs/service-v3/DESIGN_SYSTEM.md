# Travel Inbox · 사진으로 탐색하는 여행 디자인 시스템

개정일: 2026-10-06 · 디자인 버전: `travel-photo-coral-v1`
적용 파일: `web/css/design-system.css`, `web/css/foundation.css`, `web/manifest.webmanifest`

사용자가 새로 제공한 `DESIGN.md`의 Airbnb 분석을 시각 참고로 적용했다. 흰 배경, 잉크색 글자, 간결한 필터, 실제 장소 사진이 중심이다. 이전 `toss.md`·`yeogi.md`에서 적용했던 상태 구분·입력 보존·접근성 원칙은 유지하면서 초록 팔레트와 무거운 카드 외곽은 교체했다. 제품은 Travel Inbox이며 Airbnb 로고·전용 Cereal 서체·마케팅 이미지·상표 자산을 복제하지 않는다. 이 문서는 해당 회사의 공식 디자인 시스템·인증을 뜻하지 않는다.

## 1. 화면 원칙

1. **장소부터 읽는다.** 사용할 수 있는 실제 식당 사진 → 한글·원어 이름 → 추천 이유 → 방문 전 확인 → 상세·저장 순으로 읽는다. 사진이 없으면 작은 안내만 제공한다. 다른 식당 사진·AI 생성 사진·일반 음식 사진을 해당 지점의 사진처럼 표시하지 않는다.
2. **코랄은 주요 행동에만 쓴다.** 추천 실행·저장 확정 등 화면의 주요 행동에 코랄을 사용한다. 날짜·유형 선택은 잉크색, 일반 버튼은 흰색과 윤곽으로 구분한다. 코랄을 예약 성공이나 검증 완료 의미로 사용하지 않는다.
3. **여행 문맥을 유지한다.** 선택 여행·기간·도시를 상단에 유지한다. 출발점은 중립 배경의 간결한 구획에 표시한다. 위치 미확인·직선거리·실제 경로 시간을 구분한다.
4. **입력을 늘리지 않는다.** 기존 여행 조건을 재사용한다. 자주 쓰는 날짜·장소 분류를 먼저 보여 주고 세부 조건은 펼쳐서 확인한다. 실패 후 입력·이전 결과를 보존한다.
5. **상태를 정직하게 보여 준다.** 실제 작업 단계, 처리 수, 빈 결과, 자료 부족, 조건 불일치, 부분 성공, 세션 만료를 구분한다. 사진이 있다는 사실은 운영·잔여석·품질 검증의 증거가 아니다.

## 2. 색상과 역할

`palette → semantic → component` 구조다. `design-system.css`가 색상의 단일 원본이며 기능 CSS는 역할 토큰을 사용한다. 기존 `--surface`, `--ink`, `--accent`는 호환 alias다. Light/dark 설정과 시스템 테마를 모두 지원한다.

### 계산한 대비

sRGB 상대 휘도 공식으로 계산한 토큰 대비다. 아래 계산이 전체 화면의 접근성 인증을 의미하지는 않는다.

| 전경 / 배경 | 대비 |
| --- | ---: |
| 흰색 / 주요 코랄 `#E00B41` | 4.89:1 |
| 코랄 글자 `#C41548` / 약한 코랄 `#FFF1F4` | 5.39:1 |
| 잉크 `#222222` / 흰색 | 15.91:1 |
| 보조 글자 `#3F3F3F` / `#F7F7F7` | 9.83:1 |
| 설명 `#6A6A6A` / `#F7F7F7` | 5.05:1 |
| 다크 버튼 글자 `#29131A` / `#FF7594` | 6.84:1 |
| 경고 `#885B0F` / `#FFF7E6` | 5.55:1 |
| 오류 `#B32505` / `#FFF0EB` | 5.94:1 |

사진 위 컨트롤은 테마와 무관하게 흰 버튼·짙은 글자를 사용한다. 개수는 짙은 반투명 바탕과 흰색 글자를 함께 둔다. 사진 밝기에 직접 의존하는 글자·아이콘을 두지 않는다.

## 3. 글자·공간·반응형

- 서체: 기기에 설치된 Pretendard와 OS 기본 한글·라틴 서체. 외부 폰트 요청을 추가하지 않는다. Airbnb Cereal·Circular 파일을 가져오지 않는다.
- 페이지 제목 28px/650, 구획 제목 20px/600, 장소 제목 18px/600, 본문 15px/1.6, 보조 설명 13px/1.65. 원어명을 줄임표로 숨기지 않고 줄바꿈한다.
- 4/8/12/16/20/24/32/40/64px 간격을 사용한다. 카드 사이 가로 24px·세로 32px, 모바일 페이지 좌우 20px(380px 이하 16px).
- 반경: 입력·버튼 10px, 사진 16px, 정보 패널 18px, 모달 24px, 날짜 chip pill. 장소 카드는 사진과 내용의 간격으로 묶으며 별도 두꺼운 외곽을 두지 않는다.
- 화면 주요 행동 48px, 나머지 컨트롤과 사진 이전·다음 버튼 최소 44px. 첨부의 32px 사진 아이콘 규격은 제품 접근성을 위해 확장했다.
- 추천은 넓은 데스크톱 3열, 일반 데스크톱 2열, 좁은 화면 1열이다. 앱 사이드바·실제 내용 폭을 고려해 1280/1000px 기준을 사용한다. 첨부 브랜드의 공식 breakpoint라는 의미는 아니다.
- `--text-scale`과 큰 글자 설정을 유지한다. 큰 글자에서는 추천 1열, 사진 컨트롤은 이미지 아래로 이동해 글자와 사진이 겹치지 않게 한다.
- 선택 탭은 밑줄과 글자, 선택 날짜·분류는 채운 형태와 `aria-pressed`로 표시한다. 색만으로 선택 상태를 전달하지 않는다.

## 4. 실제 사진 계약

### 카드와 상세

`figure.place-photo-gallery`에 사진을 최대 2장 표시한다. `place-photo-frame`은 4:3 비율로 공간을 먼저 확보한다. 상세도 같은 갤러리를 재사용하며 일반 글자에서 높이를 제한한다. 자동 재생·자동 넘김·모션 확대를 하지 않는다. 사용자가 이전·다음 버튼이나 방향키로 전환하며 현재 사진의 출처·작가·라이선스가 함께 바뀐다.

- 원문 지점과 연결되고 표시가 허용된 사진만 사용한다.
- 출처 URL·작가·라이선스·확인 기한을 검증한 결과만 표시한다. 작가·촬영일, 출처·라이선스, 현재 모습과의 차이 안내를 짧은 캡션으로 묶는다. 캡션 링크는 본문 안의 inline 링크이며 사진 넘김과 카드 행동 버튼은 44px 영역을 유지한다.
- 가능한 촬영 시점과 “현재 모습과 다를 수 있어요”를 함께 표시한다. 촬영일을 모르면 미확인이다.
- 사진 로딩 실패는 현재 사용 가능한 다른 사진 또는 출처 확인 안내로 전환한다. 이미 확보한 사진 영역은 유지해 아래 버튼의 위치가 갑자기 움직이지 않게 한다.
- 승인된 사진이 없는 장소는 작은 `.place-photo-gallery-empty` 안내를 보여 준다. 빈 큰 이미지판이나 다른 가게 사진을 채워 넣지 않는다.
- 사진 표시가 추천 점수·평점·리뷰 언어·영업시간의 검증을 바꾸지 않는다.
- 개인 API 전체 캐시나 오프라인 bundle에 사진을 추가하지 않는다. 공개 사진이라도 라이선스·표시 권한·오프라인 저장 권한은 별도로 판단한다.

### 터치·초점·미디어

이미지는 `loading=lazy`, `decoding=async`, 실제 크기 속성과 의미 있는 alt를 사용한다. 두 번째 사진은 사용자가 넘길 때 요청한다. 이미지 정보에 `innerHTML`을 사용하지 않는다. 외부 링크는 기존 안전 링크 함수를 거친다. 사진 버튼은 44px이며 초점 윤곽이 사진 위에서도 보이게 한다. 사진 개수는 조용한 live status로 전달한다.

## 5. 추천과 근거의 정보 위계

- 사용자 조건을 확인한 추천, 방문 전 확인할 실제 후보, 명확한 조건 위반을 서로 구분한다.
- 추천 기준을 통과한 장소가 없을 때 확인 후보를 보여 줄 수 있지만 검증된 추천 순위로 바꾸지 않는다.
- 가격 기준·이동 근거·중요한 미확인·확인일을 카드에서 읽을 수 있게 유지한다. 카드 안의 가격·이동·접기 항목마다 가로선을 반복하지 않는다. 중요한 미확인 목록은 14px/1.5, 항목 간 4px로 표시하고 줄 수를 강제로 자르지 않는다.
- 상세·보관함 저장은 주요 카드 행동이다. 일정·비교·추가 근거는 더 가벼운 버튼으로 제공한다.
- 입력 변경 중에도 이전 결과를 유지하되 이전 조건임을 표시한다. 나중에 도착한 과거 요청으로 최신 결과를 덮어쓰지 않는다.

## 6. 진행·모션·접근성

추천 진행 컴포넌트는 기존 durable job의 `validating/queued/running/reconnecting/complete/partial/empty/budget/failed/cancelled` 상태를 읽는다. 실제 단계·처리 수를 표시하고 시간 기반 가짜 퍼센트나 자동 진전하는 단계를 만들지 않는다. 세 점의 900ms opacity 반복은 활동 표시뿐이며 처리 속도·남은 시간을 뜻하지 않는다.

`emil-design-eng` 원칙을 적용한다. 자주 쓰는 탭·필터·사진 전환·키보드 이동에는 모션을 넣지 않는다. 포인터 누름만 `scale(.97)`과 140ms로 반응한다. `transition:all`이나 크기·여백 애니메이션을 추가하지 않는다. `prefers-reduced-motion`에서는 활동 점도 정적으로 보인다. hover는 hover 가능한 포인터에서만 동작한다. 기존 dialog의 Escape·focus trap·초점 복귀를 유지한다.

## 8. 검증 경계

토큰 대비는 위 공식으로 계산했다. 정적 CSS, 프런트엔드 검사, 실제 Chrome의 데스크톱·모바일 폭·다크·큰 글자·사진 넘김·실패 복구는 통합 검증 보고서에 실제 수행 범위로 남긴다. 이 문서는 아직 수행하지 않은 브라우저 시험을 통과했다고 선언하지 않는다.

이번 디자인 개편은 사용자 여행 사실·예약·검증 기준·비용 상한을 바꾸지 않는다. 사진을 보여 주기 위해 유료 지도·리뷰 공급자를 자동으로 켜지 않는다. 실제 도시·지점별 사진 범위와 미지원 장소는 데이터 검증 보고서를 따른다.
