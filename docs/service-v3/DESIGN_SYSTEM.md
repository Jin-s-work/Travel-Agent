# Travel Inbox · 초록 디자인 시스템

작성일: 2026-10-06 · 적용 파일: `web/css/design-system.css`, `web/css/foundation.css`

사용자가 제공한 `toss.md`를 주된 시각·상호작용 참고로 사용하고, `yeogi.md`의 여행 정보 위계와 역할별 표면을 보완적으로 적용했다. 제품은 Travel Inbox의 여행 관리 서비스다. 첨부 자료의 브랜드, 금융·예약 상품 개념, 로고와 전용 서체를 복제하지 않는다. 이 문서는 토스나 여기어때의 공식 배포물·인증을 뜻하지 않는다.

## 1. 의사결정 원칙

1. **중립적인 배경과 초록색 주요 행동.** 흰색 카드와 회색 배경에 내용을 놓고, 현재 화면의 가장 중요한 행동에 초록색을 사용한다. 경고는 황갈색과 설명, 오류는 빨강과 설명으로 구분한다. 초록색만으로 예약 확인·근거 검증 완료를 뜻하게 하지 않는다.
2. **한 번에 읽을 수 있는 문맥.** 여행 이름·기간·도시를 화면 상단에 유지하고, 출발점 → 방문 조건 → 추천 결과 순으로 읽는다. 숙소에 장식용 색상 왼쪽 선을 두지 않는다.
3. **행동 전에 필요한 정보만.** 일반 방문 조건은 먼저 보이고, 세부 평점·리뷰·기술적 근거는 사용자가 펼친다. 핵심 미확인은 카드에서도 보이며 상세로 숨기지 않는다.
4. **현재 상태와 다음 행동을 함께.** “0건” 하나로 끝내지 않는다. 실제 후보가 없거나, 필수 조건을 만족하지 않거나, 방문 전 확인이 필요하거나, 작업 중인 경우를 구분한다.
5. **일관성과 접근성.** 기존 여행·예약·일정·보관함·설정에 같은 역할 토큰을 사용한다. 새 색·크기·모션을 추가할 때는 이 문서와 토큰부터 갱신한다.

## 2. 토큰 구조

`palette → semantic → component` 구조를 사용한다. 기능 CSS에서 직접 팔레트 값을 적지 않고 의미 토큰을 참조한다. 기존 기능을 깨지 않도록 `--surface`, `--ink`, `--accent` 등은 semantic 토큰에 대한 호환 alias로 유지한다. 이전 foundation의 amber·forest 색상 중복 선언은 제거했다.

| 역할 | 라이트 | 다크 | 사용 |
| --- | --- | --- | --- |
| `--fill-page` | `#F9FAFB` | `#11161D` | 페이지 바탕 |
| `--fill-surface` | `#FFFFFF` | `#1D232C` | 카드·모달·상단 바 |
| `--fill-secondary` | `#F2F4F6` | `#282F39` | 보조 버튼·정보 구획 |
| `--fill-brand` | `#087F5B` | `#34D399` | 가장 중요한 행동 |
| `--fill-brand-weak` | `#E8F7F0` | `#183C30` | 선택·약한 강조 |
| `--text-primary` | `#191F28` | `#F1F3F5` | 제목·본문 |
| `--text-secondary` | `#4E5968` | `#C3C9D1` | 보조 정보 |
| `--text-tertiary` | `#626D7C` | `#A3ADBB` | 설명·placeholder |
| `--text-brand` | `#087F5B` | `#6EE7B7` | 링크·선택 설명 |
| `--text-on-brand` | `#FFFFFF` | `#101C17` | 주요 버튼 안 글자 |
| `--text-warning` / `--fill-warning` | `#925C08` / `#FFF5E0` | `#FFC978` / `#3B2D1B` | 확인이 필요한 상태 |
| `--text-danger` / `--fill-danger-weak` | `#B42335` / `#FFEFF1` | `#FFABB5` / `#3E252C` | 실패·입력 오류 |

`data-theme=light/dark`는 명시적 설정을 우선한다. 설정이 없을 때 시스템 `prefers-color-scheme`을 따른다. 같은 글자 색을 다크 표면에 재사용하지 않는다.

### 측정한 대비

sRGB 상대 휘도에 따른 `(밝은 휘도 + 0.05)/(어두운 휘도 + 0.05)` 계산이다. 아래 값은 토큰 조합 검증이며, 전체 페이지의 접근성 인증을 뜻하지 않는다.

| 전경 / 배경 | 대비 |
| --- | ---: |
| 흰색 / 브랜드 `#087F5B` | 5.00:1 |
| 브랜드 글자 `#087F5B` / 약한 브랜드 `#E8F7F0` | 4.53:1 |
| 본문 `#191F28` / 흰색 | 16.56:1 |
| 보조 글자 `#4E5968` / 보조 배경 `#F2F4F6` | 6.45:1 |
| 설명 `#626D7C` / 보조 배경 `#F2F4F6` | 4.76:1 |
| 다크 버튼 글자 `#101C17` / 브랜드 `#34D399` | 9.10:1 |
| 경고 `#925C08` / 경고 배경 `#FFF5E0` | 5.16:1 |
| 오류 `#B42335` / 오류 배경 `#FFEFF1` | 5.84:1 |
| 입력 윤곽 `#8793A1` / 흰색 | 3.13:1 |
| 다크 입력 윤곽 `#6B7787` / 입력 배경 `#222A35` | 3.18:1 |

입력 윤곽은 별도 `--border-field`를 사용하고 초점에서는 3px 외곽선을 제공한다. disabled는 읽을 수 있는 회색 글자와 배경, 실제 `disabled` 속성으로 표시한다. 첨부의 전체 opacity 0.3은 사용하지 않았다. 이유를 읽고 다음 행동을 고를 수 있도록 하는 접근성 조정이다.

## 3. 글자·공간·표면

- 서체: `Pretendard Variable, Pretendard`가 기기에 있으면 사용하고, 없으면 OS 한글/라틴 기본 서체로 폴백한다. 저장소에 Pretendard 파일이 없으므로 외부 폰트 요청을 추가하지 않았다. Toss Product Sans·Tossface·브랜드 전용 자산은 사용하지 않는다.
- 본문 15px/1.6, 설명 13px/1.65, 카드 제목 20px/1.5, 페이지 제목 32px/1.35. 모바일 페이지 제목은 28px. 숫자·시간·비용·처리 건수는 `tabular-nums`로 움직임을 줄인다.
- `--text-scale`과 기존 큰 글자 설정을 유지한다. 200%에서는 추천 카드와 복잡한 조건 입력을 한 열로 바꾸고 고정 폭 대신 줄바꿈을 허용한다.
- 핵심 간격: 4/8/12/16/20/24/32/40/64px. 관련 입력 사이 24px, 카드 안쪽 24px(모바일 16~20px), 페이지 좌우 모바일 20px(아주 좁은 폭 16px).
- 반경: badge 8px, 입력 12px, 버튼 14px, 카드 20px, 모달 24px, chip pill. 카드의 깊이는 약한 그림자와 표면 차이로 구분한다.
- 그림자 역할: `shadow-card`·`shadow-popover`·`shadow-dialog`·`shadow-dock`. 색상 그림자·텍스처·전체 배경 그라디언트를 추가하지 않는다.
- 앱의 800/380px 분기점은 기존 웹 구조와 실제 지원 폭을 위한 제품 선택이며 첨부 브랜드의 공식 breakpoint가 아니다.

## 4. 컴포넌트 계약

### 버튼과 입력

화면 단위 주요 행동은 `primary`, 보조 행동은 `secondary`, 가벼운 행동은 `text-button`을 사용한다. 추천 화면에서는 추천 실행을 주요 행동으로 두고 카드 내부 행동은 약한 초록 배경으로 구분한다. 최소 클릭 영역 44px, 입력 높이 48px를 기본으로 한다. 작은 시각 요소도 클릭 영역을 줄이지 않는다. 폼의 오류는 필드 곁에 남기고 실패 후 입력을 보존한다.

### 여행 문맥과 출발점

여행 기간과 도시는 상단 scope에 유지한다. 숙소 이름과 출발점 상태는 별도 흰 카드에 표시하되, 초록색 장식 선으로 확인 완료처럼 보이지 않게 한다. 숙소 위치를 모르면 “위치 미확인”을 유지한다. 직선거리와 실제 도보시간은 별도 정보다.

### 추천 진행

`#recommendationRunStatus.recommendation-progress[data-state]`가 진행 화면이다.

| 상태 | 보여줄 정보 | 다음 행동 |
| --- | --- | --- |
| validating | 입력을 확인하는 상태 | 중복 클릭 방지 |
| queued | 저장된 작업이 시작을 기다리는 상태 | 화면을 나가도 작업 ID로 복구 |
| running | 서버가 보고한 현재 단계·실제 처리 수 | 기존 결과가 있으면 계속 표시 |
| reconnecting | 상태 연결 확인 중, 같은 작업 유지 | 상태 다시 확인 |
| complete | 완료와 실제 결과 수 | 장소 확인 |
| partial | 일부만 처리한 결과·누락 이유 | 결과 보기 또는 명시적 재시도 |
| empty | 실제 후보 부족과 조건 불충족을 구분 | 조건 수정·다른 날짜·장소 저장 |
| budget | 비용 한도 때문에 새 작업 제한 | 저장된 결과 열람 |
| failed / cancelled | 실패 또는 취소가 기록된 상태 | 입력을 보존한 재시도 |

세 점 loader는 활동 유무만 나타낸다. 거짓 퍼센트·남은 시간·시간에 따라 자동 진전하는 단계·skeleton shimmer는 사용하지 않는다. 단계 마커는 server job stage에 의존한다. `role=status`, `aria-live=polite`, `aria-atomic=true`와 상태 문장을 함께 사용하며 로더 점은 읽기 대상에서 제외한다.

### 결과와 방문 전 확인 후보

실제 장소가 있지만 정보가 부족한 경우 “0건”만 보여주지 않는다. “조건을 확인한 추천”과 “방문 전 확인할 장소”를 수치와 문장으로 구분하고, 조건을 확인한 추천이 없으면 확인 후보 구획을 연다. 낮은 정보 품질을 초록 rank badge로 포장하지 않는다. 확인된 조건 위반이나 제외 장소는 별도 구획에 남긴다. “확인 필요” 카드는 검증된 추천·예약 가능 보장이 아니다.

### 모션·초점

자주 쓰는 탭·필터·키보드 이동에 지연 모션을 추가하지 않는다. 포인터 누름은 기존 0.97 배율과 140ms 반응을 유지한다. loader는 900ms opacity 반복만 사용한다(완료까지 걸리는 시간 표시가 아니다). `prefers-reduced-motion`에서는 정적인 점과 상태 문장만 남긴다. hover는 hover 가능한 포인터에서만 적용한다. 기존 dialog의 Escape·focus trap·복귀 동작을 유지한다. `forced-colors`에서도 선택 윤곽과 단계 마커가 남는다.

## 5. 적용 전후 검토

| Before | After | Why |
| --- | --- | --- |
| 한 CSS에 amber와 forest 팔레트가 여러 번 선언됨 | 단일 semantic 토큰과 light/dark 역할 매핑 | 어느 테마에서도 수정 결과를 예측할 수 있도록 함 |
| 녹색을 띤 페이지·카드·장식 선이 모두 경쟁 | 중립 회색 바탕·흰 카드·초록 주요 행동 | 다음 행동과 여행 정보를 먼저 읽도록 함 |
| 결과가 0건일 때 작업 여부·후보 상태를 파악하기 어려움 | 실제 job 상태·처리 수·확인 후보를 분리 | 기다릴지, 다시 확인할지, 조건을 바꿀지 판단하게 함 |
| 여러 카드의 진한 primary 버튼이 함께 강조 | 화면 주요 행동은 진하게, 카드 행동은 약한 초록 | 카드 내용과 핵심 행동의 위계를 유지 |
| 숙소 이름·세부 라벨에 고정 px가 섞임 | 공통 글자 토큰과 200% 줄바꿈 | 긴 원어명과 큰 글자에서 잘림을 줄임 |
| 임의 색상 그림자와 큰 blur | 표면 역할별 중립 그림자 | 모달·메뉴·카드 깊이를 일관되게 표현 |
| 흐린 placeholder와 opacity disabled | 읽을 수 있는 semantic 보조 글자·disabled 상태 | 실패 원인과 다음 행동을 이해할 수 있게 함 |
| 로딩을 화면의 작은 문장으로만 알림 | 정적인 단계·상태 문장 + 활동 중 세 점 | 실제 작업 진행을 눈과 보조기기로 확인 |

## 6. 검증과 경계

- 토큰 대비: 위 계산으로 검증했다. external font·브랜드 asset·지도 호출을 추가하지 않았다.
- 정적 CSS 문법, public asset 해시, 추천 상태·결과 DOM 시험, 데스크톱/모바일/큰 글자 브라우저 시험은 이번 변경 검증 보고서에 기록한다. 코드가 존재하는 것과 브라우저에서 확인한 것을 구분한다.
- 화면은 근거의 유무를 표시할 뿐 실제 후보·원문 리뷰·도보 경로를 만들지 않는다. 디자인 변경이 리뷰 품질 기능을 켜거나 지출 한도를 변경하지 않는다.
- 금융 서비스·숙박 상품 전용 흐름은 이식하지 않았다. 초록 브랜드와 제품 상태를 위한 토큰 값은 Travel Inbox의 자체 선택이다.
