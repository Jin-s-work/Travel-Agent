## 1. 반드시 완성할 사용자 흐름

로그인 → 마지막 여행 복원 또는 여행 생성 → 기본 추천 확인 → 필요한 조건만 수정 → 장소 저장 → 상세 확인 → 저장한 곳으로 일정 미리보기 → 적용 → 새로고침 → 되돌리기.

메인에서 ‘여행에 물어보기’에 접근하고, 기존 메일 업로드·예약 교정·날짜별 예약 질문도 계속 사용할 수 있어야 해.

기존 여행에서는 추천을 보기 위해 필수 입력을 다시 요구하지 않아야 해. 장소 저장은 한 번의 명확한 행동으로 끝나야 해. 일정 적용처럼 결과를 바꾸는 확인 단계는 줄이지 마.

## 2. 묶음 A — 여행 맥락과 입력을 정리해

이 묶음의 저장/API/화면/실패 흐름을 먼저 연결하고 묶음 B로 넘어가.

### 2.1 여행 맥락의 단일 기준

- 현재 사용자·여행 ID, 여행 version, 방문일, 도시 구간, 인원, 출발점, 선택한 추천 방식을 하나의 검증된 context로 다뤄. 클라이언트 owner_id를 신뢰하지 마.
- 마지막 여행을 복원하되 삭제되었거나 권한이 없으면 안전하게 여행 선택으로 돌아가. 다른 계정의 context를 재사용하지 마.
- 방문일은 여행 기간 내의 도시 현지 오늘을 우선하고, 미래 여행은 시작일, 종료 여행은 마지막 선택일 또는 시작일을 사용해. 자동 선택 이유를 진단할 수 있게 해.
- 방문일에 도시 구간이 하나면 자동 사용해. 겹치면 도시 선택 한 번, 없으면 날짜/도시 중 문제가 있는 항목만 고치게 해. ‘해당 도시 체류 구간 없음’ 오류만 보여주고 막지 마.
- 날짜 경계·겹침 판단은 기존 도메인 계약을 재사용해. UI에서 별도 날짜 로직을 만들어 서버와 다르게 계산하지 마.
- 여행 인원과 숙소를 재사용해. 인원을 모르는 상태와 1명을 같게 취급하지 마. 아동·식단·접근성의 미확인을 임의로 충족 처리하지 마.
- 해당 날짜의 확인된 숙소가 여러 개면 이름으로 고르게 해. 숙소가 없으면 도시·선택 동네 기준으로 탐색할 수 있어야 해.

### 2.2 날짜·조건 입력

- 연도는 네 자리 유효 연도만 허용해. `000000`, `0000`, 잘못된 윤일, 시작일보다 이른 종료일을 서버에서도 거절해. 입력 도중의 부분값과 제출 가능한 날짜는 구분해.
- 오류는 필드 옆에 표시하고 다른 입력을 지우지 마. 모바일 날짜 입력과 키보드 입력을 모두 확인해.
- 기본 화면에는 여행/날짜/도시/인원/출발점 요약과 ‘조건 수정’만 보여줘. 취향·가격·언어 임계값은 필요할 때만 열 수 있게 해.
- 조건 패널에서는 사용자가 고친 값만 초안에 반영하고 ‘적용’ 한 번으로 제출해. 닫기는 기존 결과를 유지하고 미적용 입력을 어떻게 처리하는지 명확히 해.
- 인당/전체, 식사/하루, 통화 기준은 상세 조건 안에서 구분해. 입력 수를 줄이려고 다른 의미의 숫자를 합치지 마.
- 편집·선택은 명확한 버튼·라디오·세그먼트로 제공해. 단순한 선호나 모드 선택을 의미 불명확한 토글로 만들지 마. 실제 ON/OFF 설정만 스위치를 유지할 수 있어.

### 2.3 이동 구조

상위 이동은 ‘찾기 / 저장한 곳 / 일정 / 예약’을 기본안으로 적용해. 기존 홈은 여행 요약으로 유지하고 로고 등 일관된 경로로 접근할 수 있게 해. 실제 화면을 비교했을 때 기존 구조보다 이동이 늘어나면 근거를 기록하고 조정해.

‘여행에 물어보기’는 메인 입력란과 찾기 쉬운 고정 진입 버튼으로 제공해. 다른 화면을 가리는 거대한 플로팅 패널은 피하고 모바일 키보드가 열렸을 때 입력·전송 버튼이 가려지지 않게 해. 기존 질문 URL·메일·설정 경로를 없애지 마.

## 3. 묶음 B — 추천 화면과 상태를 이해하기 쉽게 만들어

### 3.1 두 가지 발견 방식

- ‘현지어 리뷰’와 ‘유명한 곳’을 독립된 구획으로 제공해. 음식점·카페·볼거리는 이 구분과 독립적인 분류 필터야.
- 홈에서도 각 구획의 의미와 자료 유무가 드러나야 해. 유명 후보가 먼저 정해진 수를 차지해 현지어 후보를 감추지 마.
- 일반 지도 자료는 ‘주변 장소 둘러보기’에 둬. 현지어/유명함이 검증된 자료처럼 승격하지 마.
- 최초 진입은 이용 가능한 결과를 우선 안내하되, 사용자가 명시적으로 선택한 현지어 탭을 다른 탭으로 자동 전환하지 마.
- 미지원은 ‘이 도시의 현지어 리뷰를 준비하고 있어요’와 사용 가능한 대안을 보여줘. 조건 불충족·예산 소진·장애를 같은 0건으로 표시하지 마.
- 일부 결과만 있으면 실제 개수를 보여줘. 2곳이면 2곳을 유지하고 기준을 몰래 완화하지 마.

### 3.2 카드와 상세

- 카드에는 이름·원어명, 허용된 사진, 선택 이유 최대 2개, 실제 기준의 거리·가격, 저장 행동을 우선해.
- 모든 카드에 같은 긴 확인 문구를 붙이지 마. 선택을 바꾸는 미확인 1개를 먼저 보여주고 세부 근거는 상세에 정리해. 확인된 위반은 경고를 붙여 추천하는 대신 기존 필수 조건 정책으로 제외해.
- 언어 카드의 관측 범위와 표본 수는 숨기지 마. 원문 리뷰 언어가 현지 주민 비율이나 맛의 보증인 것처럼 표현하지 마.
- 사진은 최대 3장이라는 기존 목표를 유지해. 첫 사진만 우선 로드하고 나머지는 갤러리 사용 시 불러와. 이 단계에서 공급자가 없는 사진을 만들거나 다른 지점 이미지로 채우지 마.
- 사진 로딩 중/사진 없음/실패/만료를 구분해. 사진 없음이 확인되면 빈 대형 영역을 남기지 않고 텍스트 카드로 전환해. 이미지 때문에 이름·저장 버튼의 위치가 크게 뛰지 않게 해.
- 상세에는 방문일·인원, 운영·예약, 가격, 언어 근거 순서로 보여줘. 주소/원어명 복사와 지도 열기는 가까이 배치해.
- 가격·경로가 미확인이면 빈 값을 0이나 무료로 바꾸지 마. 직선거리와 실제 이동시간을 분명히 구분해.
- 비교는 같은 방문일·인원에서 서로 다른 최대 3곳이야. 이미 비교 중인 장소를 다시 넣어 수를 늘리지 마.

### 3.3 200개 후보를 다룰 결과 계약

사용자의 최신 기준은 **추천 요청당 최대 200개 고유 지점 후보**야. 예전 60개 제한을 새 제품 계약으로 굳히지 마. 장소 후보 200곳과 장소별 리뷰 200건을 서로 다른 설정으로 관리해.

- 첫 화면은 6~12곳, 추가 보기는 12곳씩 보여줘. 200개 카드를 한 번에 렌더링하지 마.
- API에는 PRD의 candidate counts, coverage, truncation_reason, run/snapshot/version, cursor를 정의해. 기존 응답과 호환되는 방식으로 확장해.
- cursor는 사용자·여행·run·조건 snapshot과 연결해. 다른 run의 cursor나 삭제된 여행의 cursor를 받아 읽지 마.
- 추가 보기는 저장된 순서의 페이지 조회야. 목록이 늘어날 때 기존 순서·저장 상태·스크롤을 보존하고 중복 장소를 넣지 마.
- 후보 수집 확대는 2단계야. 현재 공급자가 37개/60개만 반환하면 실제 값과 범위를 보존해. 이 단계에서 200개 합성 fixture가 동작했다고 실제 200개 수집을 완료했다고 보고하지 마.
- 일반 목록 조회·탭 변경·사진 넘기기·추가 보기 때문에 외부 추천 수집 job을 생성하지 마.

### 3.4 상태와 요청 경합

`job_state`, `availability_state`, `freshness_state`, `result_count`, `blocking_reason`, `warnings`, `next_actions`를 독립적으로 다뤄. UI를 위해 기존 durable job 상태를 덮어쓰지 마.

- 기능 OFF/도시 미지원 → 준비 상태와 대안.
- 정상 평가 후 조건 불충족 → 실제 부족 개수와 사용자가 선택하는 조건 수정.
- 외부 장애 → 유효한 저장 결과 유지, 재시도 가능 여부.
- 예산 소진 → 저장 결과 조회와 개인 여행 기능 유지.
- 결과 만료 → 표시 가능 범위와 재확인 상태. 이용 권한 철회 자료는 표시하지 마.
- job 성공 후 결과 GET 실패 → 같은 run 읽기 재시도. 새 작업 실행 금지.
- 세션 만료 → 안전한 재로그인 복귀와 개인정보 정리.
- 버전 충돌 → 서버 값과 초안 비교, 초안 보존.

최초 로딩에만 골격을 보여주고, 조건 수정 중에는 기존 목록과 ‘이전 조건의 결과’ 표시를 유지해. 실제 단계·처리 건수만 보여주고 시간에 따라 자동으로 오르는 가짜 퍼센트를 만들지 마.

trip_epoch/request_seq 및 서버 snapshot/version을 확인해. A→B 여행 전환, 필터 연속 변경, 취소 뒤 늦은 응답을 시험해. AbortController만으로 서버 중복 실행을 막았다고 판단하지 마. 서버 Idempotency-Key는 실행자·scope·operation·payload hash를 검증하고 같은 key의 다른 payload는409여야 해.

SSE가 있다면 Last-Event-ID와 기존 job을 복원해. 다시 연결했다고 새 추천을 실행하지 마. 완료 후 페이지를 닫아도 다시 열어 상태와 결과를 볼 수 있어야 해.

## 4. 묶음 C — 저장·일정·피드백을 이어줘

- 저장은 서버 성공 뒤 확정 표시해. 낙관적으로 처리하면 실패 시 되돌리고 사용자의 선택은 복구 가능하게 해.
- 더블클릭·재시도는 서버에서 중복을 막아. 홈·탐색·상세·보관함의 저장 상태가 같아야 해.
- 보관함에서 날짜와 장소 선택을 그대로 일정 미리보기로 전달해. 다시 여행/도시/인원을 입력하게 하지 마.
- 일정 생성·편집은 기존 validator 및 preview/apply/undo를 재사용해. 확정 예약을 자동 이동·삭제하지 마. 잠정안 허용과 확인된 위반은 구분해.
- 일정 적용 직전 소유권·삭제·version·고정 예약·사실 신선도를 확인하고 충돌 시409로 원본을 보존해. undo는 새 revision으로 만들어.
- 일정에서 제거해도 외부 예약 취소가 아님을 필요한 위치에서 알려줘.
- 기존 피드백으로 ‘이번 여행에서 덜 보기/제외’를 제공할 수 있어. 범위는 해당 여행이고 철회 가능해야 해. 클릭 하나로 계정 전체 취향을 영구 변경하지 마.
- 저장된 장소끼리 가까운 순서 보기는 기존 좌표만으로 가능한 경우에 한해 제공해. 새 기능 때문에 핵심 흐름 완성을 미루지 마.

## 5. 접근성·디자인의 완료 기준

색·브랜드·Pretendard를 유지하고 기존 디자인 토큰으로 간격·정렬·문자 크기를 통일해. 별도 디자인 시스템이나 거대한 컴포넌트 라이브러리를 새로 도입하지 마.

- 390px 모바일과 넓은 화면, 200% 글자/줌에서 기능을 시험해.
- 일본어·스페인어·카탈루냐어의 긴 장소명과 주소를 넣어 잘림·겹침을 확인해.
- 키보드로 필터, 갤러리, 저장, 상세, 비교, 모달 닫기까지 이동할 수 있어야 해.
- 모달은 열릴 때 적절한 포커스, 닫힐 때 트리거 복귀, 오류 필드 연결을 제공해.
- 진행 상태는 접근성 알림으로 전달하되 카드 전체를 계속 읽게 하지 마.
- 눌림/저장 피드백은 즉시, 네트워크 성공 표시는 실제 응답 이후에 제공해. reduced-motion을 지원해.

## 6. 계측과 시험

기존 분석 동의·이벤트 계약을 재사용해. 화면 노출, 저장 성공, 일정 apply 성공을 구분하고 event_id로 중복을 막아. 원문·질문·정밀 위치·숙소명·건강/식단·개인 메모를 일반 이벤트에 넣지 마.

PRD U01~U12를 모두 검증해. 200개 결과 페이지 계약은 이 단계에서 합성 자료로도 검증하고, 실제 후보 수집 시험은 2단계로 남겨.

필수 fixture:

1. 사용자 A/B 각각 두 여행, 같은 이름의 여행·지점, 계정 전환.
2. 다도시 경계일, 겹치는 도시, 날짜 구간 없음, 종료 여행, 숙소 없음.
3. 유명 후보3+현지어 후보1, 기능 OFF+UNKNOWN, 정상 조건 탈락2곳.
4. 후보200개, 12개씩 더 보기, 같은 장소 재등장, 다른 run cursor.
5. 느린 응답 3개 역순 도착, 다른 여행 전환, 세션 만료.
6. 완료 job 결과 GET 실패, 새로고침, SSE 이어받기.
7. 저장 더블클릭, 실패 후 재시도, 다른 화면의 저장 상태.
8. 일정 충돌·동시 apply·undo·삭제 후 늦은 응답.
9. 사진 없음/실패/만료/1장/3장과 attribution.

시작점으로 기존 `test_home_ui.cjs`, `test_discovery_flow_ui.cjs`, `test_recommendation_progress_ui.cjs`, `test_discovery_filters_ui.cjs`, `test_itinerary_first_preview_ui.cjs`, `test_recommendation_persistence.py`, `test_discovery_intents.py`를 확인해. 파일 존재와 실행 명령을 먼저 조사하고 영향 범위에 맞게 실행해. 단순 문자열 포함 여부만으로 흐름이 완성됐다고 판단하지 마.

브라우저에서 합성 계정으로 여행 생성→탐색→조건 변경→저장→상세→일정 preview/apply→새로고침→undo를 실행해. 실제 확인한 브라우저·화면 크기·키보드 경로와 미검증 기기를 나눠 기록해. 기존 차단·권한을 우회하지 말고 막힌 경로는 이유와 가능한 검증을 분리해 보고해.

외부 키가 없어도 fake provider로 상태·동시성·화면 시험은 완료해. 리뷰를 실수집하거나 운영 기능을 켜는 것을 이번 단계 완료 조건으로 만들지 마.
