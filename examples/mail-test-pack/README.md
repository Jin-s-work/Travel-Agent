# 직접 해보는 예약 메일 테스트

모든 업체·주소·예약번호·여행자는 합성입니다. 실제 예약이 아니며 메일을 발송하거나 링크를 실행하지 않습니다. 테스트 자료에는 개인정보·비밀키가 없습니다.

## 먼저 확인할 점

현재 배포는 **무료/외부 과금 OFF**입니다. 파일 형식 검사·접수·중복/실패 표시를 시험할 수 있지만, 새 메일의 AI 추출·임베딩 성공은 보장되지 않습니다. `BUDGET_EXCEEDED` 또는 공급자 미설정이면 무료 정책이 작동한 결과입니다. 재시도를 반복해도 켜지지 않습니다. 외부 키를 채팅에 넣거나 자동 결제를 켜지 마세요. 자동 추출 결과를 시험하려면 별도로 승인한 한도/공급자 설정이 필요합니다. 로컬 fake provider는 복구·화면 검증용이며 언어 이해 정확도의 증거가 아닙니다.

## 준비: 테스트 여행 만들기

- `메일 연습 · 도쿄`: 2026-11-06 ~ 2026-11-09, 성인2, 도시 도쿄.
- `메일 연습 · 마드리드`: 2026-11-12 ~ 2026-11-16, 성인2, 도시 Madrid/마드리드.
- DST 사례는 별도 `시간대 연습`: 마드리드 2026-10-25 하루.
- 8건 사례는 별도 빈 도쿄 여행 2026-11-07 하루. 다른 메일을 섞으면 총9건이라는 기대값이 달라집니다.

## 업로드와 확인

1. ZIP을 풀고 해당 여행에서 **메일 → 파일 선택**으로 `.eml` 한 개를 올립니다. ZIP 자체는 메일이 아닙니다.
2. 상태가 완료/일부 완료/실패인지 확인합니다. 실패를 예약0개 성공으로 읽지 마세요.
3. 분석 가능 환경에서는 예약 목록과 `expected-results.json`의 의미를 비교합니다. JSON은 정답 설명이며 자동 추출 결과를 담은 파일이 아닙니다.
4. 예약 상세에서 한 값을 교정하고 새로고침합니다. 교정값·출처가 유지되는지 확인합니다.
5. 같은 파일을 같은 여행에 다시 올리고 중복 표시를 확인합니다. 다른 여행의 같은 파일은 별도 소유 범위입니다.
6. 무료 모드에서도 JSON의 값을 참고해 **예약 직접 추가**로 만들어 날짜 질문·교정·새로고침 흐름을 확인할 수 있습니다.

## 사례별 포인트

|파일|확인할 내용|
|---|---|
|01 왕복 항공|왕복 두 예약, 출발/도착 네 사건과 현지 시간대|
|02 도쿄 숙소|3박, 체크인/아웃 구분, 숙박을 종일 busy로 막지 않음|
|03 식당|아동 나이 미확인, 보증금과 최종 가격 분리|
|04 마드리드 숙소|Madrid가 Barcelona로 변하지 않음|
|05 복수 예약|한 메일의 두 예약을 개별 교정·삭제|
|06 날짜만 있음|정확한 시각·인원·가격은 미확인|
|same-name-a/b|같은 reservation.eml 파일명, 서로 다른 내용 보존|
|07 하루8건|빈 여행에서8건+수동1건=전체9건 조회|
|08 변경 요청|미확정 요청을 확정 예약/사용자 교정으로 덮어쓰지 않음|
|09 HTML|본문 추출, 링크 자동 실행 없음|
|10 DST|중복되는 현지시각은 UTC 확정 금지|

재추출은 원래 메일과 연결한 기능으로 실행하세요. 08 파일을 따로 업로드했다고 자동으로 동일 예약 병합이 완료됐다고 가정하지 않습니다. 삭제 시험은 이 합성 여행에서만 하세요. 실제 외부 예약의 취소와 무관합니다.
